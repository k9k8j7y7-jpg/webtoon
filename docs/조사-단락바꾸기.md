## 요약 8줄

1. **idea_brief.story** 키: `ki`(도입) · `seung`(전개) · `jeon`(전환) · `gyeol`(결말). 톤은 `idea_brief.tone`, 인물은 `idea_brief.characters[]`. 전체 `gate_status.idea_brief`에 저장
2. **planning_draft 자동 저장**: `PUT .../planning-draft` (프론트 800ms 디바운스). `gate_status.planning_draft`에 genre/mood/development/characters 저장, snapshot=true 시 `last_gen_input`도 갱신
3. **[다시 정리]**: `POST .../idea-brief` + `{hint}` → `revise_idea_brief(existing, hint)` 호출. gemini-2.5-flash, temp 0.7, 4096 토큰. 패킷 차감 없음(텍스트 전용). **전체 brief를 재생성**하되 hint에 안 언급된 부분은 유지하라는 프롬프트 규칙
4. **이야기 전개 칩**: `planning_draft.development` (calm/dramatic/twist/hook/growth/mystery/cliffhanger). `prompt_fragments.py`의 `DEVELOPMENT_FRAGMENTS` → `build_story_options_prompt()` → 기획 생성 프롬프트 끝에 "연출 지시:" 블록으로 주입
5. **단락 1개 재생성**: 현재 `revise_idea_brief`는 target_section/direction 파라미터 없음. **새 엔드포인트 불필요** — 기존 함수에 `target_section: str | None`(ki/seung/jeon/gyeol) + `direction: str | None` 추가하고, 프롬프트에 "이 섹션만 재작성, 나머지 그대로 반환" 조건 분기하면 충분. 라우터도 기존 `POST .../idea-brief`에 body 필드 추가로 대응 가능
6. **last_gen_input stale 배너**: `inputSig`가 characters/genre/mood/development만 비교 — **idea_brief.story 수정은 감지 못함**(배너 미표시). 단락 재생성 기능 추가 시 story 필드도 시그니처에 포함하거나, 단락 변경은 기획 재생성 대상이 아니므로 별도 "brief 변경" 배너가 필요할 수 있음
7. **revise 프롬프트 구조**: `IDEA_BRIEF_REVISE_INSTRUCTION`(service.py:449-478)이 기존 brief 전문 + hint를 받아 동일 JSON 스키마로 반환. 부분 재생성은 이 프롬프트를 분기하여 "story.{section}만 direction에 맞게 다시 써라" 지시 추가로 구현 가능
8. **비용**: 텍스트 전용(gemini-2.5-flash)이므로 단락 재생성도 0패킷. 모델·토큰 상수 변경 불필요
