## 요약 10줄

1. **jobs.py** 재사용 가능 — `run_job_in_background` + `pollJob(2초)` + `<JobProgress>` 그대로. 단, 인메모리라 재시작 시 소실, `notify()` 미연결
2. **cuts 테이블** — `spec` JSON 컬럼이 이미 확장 포인트. `spec.video_url` / `spec.video_candidates` 추가가 별도 테이블보다 일관적
3. **ffmpeg·moviepy** 서버에 미설치, requirements.txt에도 없음. 영상 저장 경로는 `episodes/{id}/cuts/{uuid}.mp4` 패턴으로 자연 확장
4. **뷰어·Gate5** 컷 이미지는 `<img>` + `position:relative` 컨테이너 + BubbleOverlay(`absolute inset-0 SVG`). `<video>` 교체 시 BubbleOverlay는 수정 없이 동작(width/height props만 전달)
5. **Pillow 합성**(서버 ZIP 경로)은 정지 이미지 전용 — 영상 프레임 합성은 ffmpeg drawtext 또는 프론트 Canvas→MediaRecorder 필요
6. **패킷 차감** — `charge_packets()` + `GenerationLog(kind="cut")` 성공 시 차감 패턴. 영상은 `kind="video"` ENUM 추가 + 패킷 N개 차감으로 확장
7. **Gemini Veo** — image-to-video 지원, 5초 클립 2~4분 소요, 기본 RPM 1~5(매우 낮음), 장당 $1.75~$2.50(이미지 대비 25~35배). 동시 2개 호출은 쿼터 여유 시 가능
8. **인스타 공유** — `navigator.share({files: [mp4]})` iOS Safari 15+ / Chrome Android 86+ 통과. 인스타가 mp4 수신 → Reels 편집기 오픈. 단, `share()`는 onClick 동기 호출 필수(영상 사전 준비)
9. **비용 장벽이 핵심** — 10컷 에피소드 영상화 $17~$25, 현 이미지($0.67) 대비 25배. 패킷 환산 시 컷당 10~15패킷 필요
10. **권장 순서** — PoC(1컷 image-to-video) → 비용·품질 판단 → 전체 설계. ffmpeg 서버 설치 + Veo 쿼터 신청이 선행 조건

## ① 백그라운드 작업 인프라 (jobs.py)

| 항목 | 현황 |
|---|---|
| 라이프사이클 | `create_job(total)` → `queued` → `processing` → `completed` / `completed_partial` / `failed` |
| 실행 | `run_job_in_background(bg_tasks, job_id, coro)` — `asyncio.new_event_loop`으로 코루틴 래핑, FastAPI BackgroundTasks에 등록 |
| 폴링 | `GET /jobs/{job_id}` 2초 간격, 최대 1800회(~60분). 프론트 `pollJob()` + `<JobProgress>` |
| 알림 | `notify()`는 **미연결** — 댓글·답글·문의 전용. job 완료 시 푸시 알림 보내려면 db+BackgroundTasks 주입 필요 |
| 인메모리 | 재시작 시 job 소실. 영상 2~4분 생성 중 `--reload` 발생하면 복구 불가 |
| **재사용 판정** | ✅ 그대로 사용 가능. notify 연동은 선택(나중에 추가 가능) |

### 영상 저장 방안

**JSON 컬럼(`spec`) 확장 권장** — 별도 `cut_videos` 테이블 불필요

```jsonc
// spec 내 추가 필드
{
  "video_url": "episodes/42/cuts/abc123.mp4",
  "video_status": "pending|generating|done|failed",
  "video_candidates": ["url1.mp4", "url2.mp4"],  // 후보 선택 시
  "video_job_id": "job_xxx"                        // 폴링용
}
```

이유: (1) spec이 이미 모든 컷 메타데이터의 확장 포인트 (2) 영상 후보는 일시적 — DB 인덱싱·JOIN 불필요 (3) 기존 패턴(effect_items, product_items)과 일관

## ③ 서버 환경 — ffmpeg·storage·용량

| 항목 | 현황 |
|---|---|
| ffmpeg | **미설치.** requirements.txt·코드 어디에도 없음. `sudo apt install ffmpeg` 필요 |
| moviepy | 미설치. 필요 시 `pip install moviepy` (ffmpeg 의존) |
| Storage 경로 | `episodes/{ep_id}/cuts/{uuid}.jpg` → 영상은 `episodes/{ep_id}/cuts/{uuid}.mp4` 자연 확장 |
| Storage 구현 | 로컬 FS 기본(`/home/bitnami/project-t/storage/`), S3 옵션 |
| 용량 관리 | 코드에 cleanup/TTL 없음. 5초 mp4 ≈ 2~5MB → 10컷 에피소드 ≈ 20~50MB. 이미지(30~100KB/컷)의 50~100배 |
| **선행 작업** | ffmpeg 설치 + storage 용량 모니터링 추가 권장 |

## ④ 뷰어·Gate5 컴포넌트 — video 교체 지점

### 이미지 렌더 현황 (3곳)

| 컴포넌트 | 파일 | 구조 |
|---|---|---|
| Gate5Review | `gates/Gate5Review.jsx` | `<div relative overflow-hidden>` → `<img ref={imgRef}>` + BubbleOverlay + EffectLayer … |
| ViewerPage (CutViewer) | `pages/ViewerPage.jsx` | `<div relative>` → `<img ref={imgRef}>` + BubbleOverlay |
| CutEditor | `components/CutEditor.jsx` | `<div relative style={dispSize}>` → `<img ref={imgRef}>` + 6레이어 오버레이 |

### BubbleOverlay 호환성

BubbleOverlay는 `<svg absolute inset-0 width={width} height={height}>` — 부모 컨테이너의 `position:relative` + 미디어 렌더 크기(width/height)만 의존. **`<video>` 교체 시 수정 없이 동작.**

### 교체 전략

```jsx
// 기존
<img ref={imgRef} src={imageUrl} className="w-full block" />

// 영상이 있으면
{cut.spec?.video_url
  ? <video ref={imgRef} src={videoUrl} autoPlay loop muted playsInline className="w-full block" />
  : <img ref={imgRef} src={imageUrl} className="w-full block" />
}
```

### Pillow 합성 (서버 ZIP 경로)

`compose_dialogue_on_image()` — PIL Image 입력, RGBA 오버레이, `alpha_composite`. **정지 이미지 전용.**

영상에 말풍선 합성 방안:
- **방안 A (프론트):** Canvas + MediaRecorder — 프레임마다 BubbleOverlay SVG를 canvas에 그려 WebM/MP4 인코딩
- **방안 B (서버):** ffmpeg drawtext/overlay 필터 — mp4 위에 PNG 오버레이 합성 (서버 ffmpeg 필요)
- **권장:** 뷰어는 `<video>` + 실시간 SVG 오버레이(수정 없음). 내보내기만 ffmpeg 합성

## ⑤ 패킷 차감·환불·generation_logs

| 함수 | 역할 |
|---|---|
| `require_packets(user_id, needed, db)` | 사전 잔량 가드 (402) |
| `charge_packets(user_id, amount, reason, ref_log_id, db)` | 원자적 차감 (`SELECT FOR UPDATE`) |

**generation_logs 스키마:** id, cut_id, episode_id, project_id, user_id, `kind` ENUM("cut","character","location","product"), model, model_tier, cost_usd, packets_charged, seed, created_at

**영상 확장:** `kind` ENUM에 `"video"` 추가 (step 마이그레이션). 패킷 차감량은 비용 기준 산정 — Veo $1.75~$2.50/컷이면 이미지($0.067) 대비 ~25배 → **10~15패킷/컷** 또는 별도 "영상 패킷" 단위

| 환경 | `canShare({files: [mp4]})` | 비고 |
|---|---|---|
| iOS Safari 15+ | ✅ | 인스타 → Reels 편집기 |
| Chrome Android 86+ | ✅ | 인스타 → Reels 편집기 |

**주의사항:**
- `share()`는 `onClick` 동기 호출 필수 — 영상은 모달 열릴 때 사전 준비 (현 이미지 사전 렌더와 동일 패턴)

- 인스타 캐러셀은 이미지+영상 혼합 가능 (최대 10개)
