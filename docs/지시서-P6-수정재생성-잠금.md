## 0. 핵심 원칙 (확정 결정 4 재확인)

| 회차 상태 | 아웃라인 편집 | 합치기/분할 | 대본 |
|---|---|---|---|
| 아웃라인 (episode_id null) | 자유 | 자유 | — |
| 대본 완료 | **[수정 후 재생성]만** | **재생성 경유만** | Gate 2 직접 편집 가능 |
| 이미지 생성됨 | 불가 | 불가 | 수정 불가 (경고) |

- 원칙: **구조 변경은 재생성, 디테일은 편집.** 대본 기계적 병합 금지.
- "이미지 생성됨" 판정: 해당 에피소드에 생성된 컷 이미지가 1장이라도
  존재 (판정 쿼리는 1단계에서 확정)

## 1단계 — 조사 (수정 금지)

1. "이미지 생성됨" 판정에 쓸 데이터 확인: 컷 이미지 존재를 에피소드
   단위로 집계하는 가장 싼 쿼리 (기존 테이블 구조 기준)
2. 기존 대본 재생성(단편의 Gate 2 재생성) 경로 — [수정 후 재생성]이
   재사용할 지점
3. 대본 생성 시 사용자가 Gate 2에서 편집한 내역이 있는 경우의 저장
   구조 (재생성 시 "편집 내역 포함 대체" 경고 문구의 근거)
보고 후 멈춤.

## 2단계 — [수정 후 재생성] (1순위)

### 백엔드
1. POST /series/{sid}/outline/{no}/revise — body: {title?, summary?,
   hook?}:
   a. 해당 회차 episode_id 존재 + 이미지 없음 확인 (이미지 있으면
      409 + "이미지가 생성된 회차는 수정할 수 없습니다")
   b. outline 항목 갱신 (title/summary/hook)
   c. 해당 에피소드의 Gate 1 파생 planning도 동기 갱신
   d. Gate 2 대본 재생성 job 시작 (P5 컨텍스트 주입 그대로 —
      갱신된 summary/hook 사용)
   e. status: "script_regenerating" → 완료 시 "script_done"
2. 주의: 직전/다음 회차의 대본은 건드리지 않는다 (연쇄 재생성 금지 —
   사용자가 필요하면 각 회차를 직접 revise. 단, 응답에
   "다음 회차(N+1화)가 이미 생성된 경우 이전 요약 기준이 바뀌었으니
   재생성을 권장" 정보 플래그 포함 → 프론트 안내용)

### 프론트 (시리즈 홈)
3. 대본 완료 회차 카드: 잠긴 ✏ 대신 **[수정 후 재생성]** 버튼
   - 클릭 → 인라인 편집 모드 (P4의 수정 UI 재사용: 제목/요약/훅)
   - 저장 시 확인 다이얼로그: "1화 대본을 새로 생성합니다.
     기존 대본은 대체됩니다 (대본에서 직접 수정한 내용 포함)."
   - 진행 오버레이 (P4 패턴) → 완료 하이라이트
   - 완료 후 다음 회차가 대본 완료 상태면 안내 배너:
     "2화는 이전 1화 내용을 기준으로 생성되었습니다. 2화도
     [수정 후 재생성]으로 갱신하는 것을 권장합니다"
4. 이미지 생성된 회차: [수정 후 재생성]도 숨김/비활성 + 자물쇠
   툴팁 "이미지가 생성된 회차는 수정할 수 없습니다"
보고 후 멈춤.

## 3단계 — 대본 회차 합치기 + 상태 정식화

1. **합치기 확장**: merge API가 episode_id 있는 회차 허용하되
   재생성 경유:
   - 확인 다이얼로그: "3화+4화를 합칩니다. 기존 3화(·4화) 대본은
     새 요약으로 다시 생성됩니다"
   - 병합 요약 생성(기존) → 앞 회차 에피소드 재사용(대본 재생성),
     뒤 회차 에피소드는 삭제 (에피소드 행 + episode_characters.
     캐릭터 본체는 프로젝트 소속이라 무손실) → 리넘버링
   - 어느 한쪽에 이미지 있으면 409
2. **분할**: episode_id 있는 회차는 분할 금지 유지 (앞/뒤 어느
   쪽이 대본을 잇는지 모호 — 사용자는 revise로 해결. 툴팁 안내)
3. **상태 뱃지 정식화** (시리즈 홈 + 회차 카드):
   - 아웃라인(회색) / 대본 완료(파랑) / 이미지 생성됨(초록) /
     생성 중(스피너)
   - 시리즈 카드 "N화 계획 · 대본 N · 이미지 N"에 이미지 집계 연동
     (1단계 판정 쿼리)
4. 잠금 아이콘 툴팁 전면 정비 (모든 잠금에 이유 표시)
보고 후 멈춤.

## 4단계 — 검증

테스트 시리즈(프로젝트 6/시리즈 11 — 1·2화 대본 있음) 재사용:
1. revise: 1화 요약 수정 → 대본 재생성 → 새 대본이 수정 반영 +
   outline/planning 동기 갱신 (API 수치 + 내용 확인)
2. 다음 회차 권장 배너: 1화 revise 후 2화 재생성 권장 안내 표시
3. 이미지 잠금: 테스트 시리즈 회차 1개에 컷 이미지 1장만 생성
   (최소 비용) → revise/merge 409 + 카드 잠금 표시 + 툴팁
4. 대본 회차 합치기: (이미지 없는 회차끼리) merge → 앞 회차 대본
   재생성 + 뒤 에피소드 삭제 + 캐릭터 본체 무손실 + 리넘버링
5. 분할 금지: 대본 회차 split 시도 → 거부 + 안내
6. 상태 뱃지: 아웃라인/대본/이미지/생성중 4상태 표시 확인
7. 시리즈 카드 이미지 숫자 연동
8. 회귀: 아웃라인 회차(episode_id null)의 기존 편집 자유 유지 +
   단편 무변경
보고 후 멈춤.

## 5단계 — 배포 + 실전 + 커밋

- 배포 후 **사용자 실전 = "아빠 엄마에 우리 도도" 1화 revise**:
  첫 만남을 실화로 (부모님 댁에서 처음 만남, 문을 열자 도도가
  처음 보는 아내에게 달려들어 품에 안김, 그 뒤로 계속 생각남) —
  요약 수정은 사용자가 직접 작성
- 이어서 2화 재생성 권장 배너 확인 → 2화도 revise
- 확인 후 커밋:
  - `feat(series): 수정 후 재생성 + 대본 회차 합치기 + 상태·잠금
    정식화 (P6)`
  - `docs: P6 지시서 보관 + PROGRESS 갱신`

## 범위 제한
