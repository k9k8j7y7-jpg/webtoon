## ① 프로젝트·에피소드 생성 흐름

### 현재 입구

| 입구 | 위치 | is_ad | 비고 |
|---|---|---|---|
| 단편 | ProjectPage 3버튼 중 왼쪽 | false | `openModal()` |
| 연작 | ProjectPage 가운데 | false | 별도 시리즈 흐름 |
| 광고 | ProjectPage 오른쪽 | true | `openModal(null, true)` |
| 빠른 한 컷 | `/quick` (랜딩·대시보드·GNB) | false | 별도 흐름, gate 1~4 자동 done |

### 생성 시 받는 필드

`POST /projects/{pid}/episodes` — `EpisodeCreate` schema:
- `episode_no`, `title`, `idea`, `mood`, `is_ad`, `product_name`, `product_features`

### gate_status 초기값

```jsonc
{
  "current_gate": 1,          // quick: 5
  "auto_advance": false,
  "is_ad": <body.is_ad>,      // false | true
  "aspect_ratio": "9:16",     // 하드코드 기본
  "aspect_ratio_locked": false,
  "page_format": "vertical",  // quick: "single_page"
  "page_format_locked": false,
  "gates": {
    "1_planning":   { "status": "draft",  ... },
    "2_script":     { "status": "locked", ... },
    "3_assets":     { "status": "locked", ... },
    "4_storyboard": { "status": "locked", ... },
    "5_review":     { "status": "locked", ... }
  },
  "idea_brief": { "raw": "<idea>", "product": { ... } }  // idea 있을 때만
}
```

### 결정 시점

| 필드 | 시점 | 출처 |
|---|---|---|
| `is_ad` | 에피소드 생성 | 프론트 모달 타입 |
| `aspect_ratio` | 생성 시 `"9:16"` 하드코드 → Gate3에서 변경 → 첫 이미지 생성 시 잠금 | `gate.py` / Gate3 UI / `lock_aspect_ratio()` |
| `page_format` | 생성 시 `"vertical"` 하드코드 → Gate3에서 변경 → 잠금 | 위와 동일 |

**purpose 분기 자리:** `create_initial_gate_status(is_ad, idea, ...)` 에 `purpose` 인자 추가하면 됨. 현재 `is_ad` 불리언을 `purpose: "standalone" | "series" | "ad" | "onecut_ad"` 등으로 확장 가능. `gate_status.purpose` 키 신설.

## ② Gate1 기획 폼 구조 · idea_brief JSON 스키마

### idea_brief 키

```jsonc
{
  "raw": "사용자 원문",
  "summary": "한 줄 소개",
  "characters": [
    { "name": "", "description": "", "gender": "남/여/기타", "age": "" }
  ],
  "story": {
    "ki": "도입 (1~3문장)",
    "seung": "전개",
    "jeon": "전환",
    "gyeol": "결말"
  },
  "tone": "분위기 한 줄",
  "suggested": { "genre": "", "mood": "", "development": "" },
  "product": { "name": "", "features": "" },   // 광고만
  "generated_at": "ISO"
}
```

### 광고 브리프를 같은 자리에 넣을 때

| 광고 브리프 필드 | 기존 키 활용 | 신규 키 |
|---|---|---|
| 목적 (인지도·전환·…) | — | `idea_brief.ad_purpose` |
| 전달 내용 (USP) | `product.features` 확장 가능 | `idea_brief.key_message` |
| 분위기 | `tone` 재사용 | — |
| 타깃 | — | `idea_brief.target_audience` |
| CTA | — | `idea_brief.cta` |
| 제품 | `product` 그대로 | — |

기존 키 중 `tone`과 `product`는 재사용, 나머지 4개는 `idea_brief` 아래 신규 키. `story.ki/seung/jeon/gyeol` 4단은 광고 브리프 모드에서 숨기거나 "상황→문제→해결→CTA" 4단으로 치환 가능(같은 구조, 다른 라벨).

### 프론트 SECTION_CHIPS 라벨

```js
ki:    [{ key: 'hook', label: '초반 후킹' }, ...]
seung: [{ key: 'dramatic', label: '극적으로' }, ...]
jeon:  [{ key: 'twist', label: '반전 있게' }, ...]
gyeol: [{ key: 'happy_ending', label: '해피엔딩' }, ...]
```

광고 모드에서는 칩 세트를 교체: `{ key: 'problem', label: '고민 제시' }` 등.

## ③ 기획·대본 생성 프롬프트

### 기획 프롬프트 분기

`generate_planning()` (story/service.py):
- idea_brief 있으면 4단 스토리+인물+톤 전체를 "아래 내용을 충실히 따를 것" 블록으로 주입
- 하드 제약: "기획서에 없는 새 인물 추가 금지"
- `is_ad=True`면 `IDEA_BRIEF_AD_ADDON` 추가: "제품이 자연스럽게 쓰이는 장면 포함"

### 대본 프롬프트 분기

`generate_script()` (script/service.py) — SYSTEM_INSTRUCTION에 addon 1개 추가:
- `series_context` → `SERIES_ADDON`
- `is_ad` → `AD_ADDON` (완결 필수 + 제품 자연 노출 + 노골 문구 금지)
- 그 외 → `STANDALONE_ADDON` (완결 필수 + 기승전결)

**purpose 분기 자리:** `if is_ad:` 조건을 `if purpose == 'ad':` / `elif purpose == 'onecut_ad':` 등으로 확장. 1컷 광고 addon은 SYSTEM_INSTRUCTION의 "최소 6컷·씬당 2컷" 규칙을 **무시하는 별도 프롬프트**가 필요.

### 1컷 대본을 기존 스크립트 스키마로 표현 가능한지

**가능.** 스키마:
```json
{
  "scenes": [{
    "scene_id": "s01",
    "summary": "...",
    "location_id": "loc_01",
    "cuts": [{
      "cut_number": 1,
      "shot": "full",
      "action": "장면 묘사",
      "dialogue": [
        { "type": "narration", "text": "헤드카피" },
        { "type": "narration", "text": "서브카피" },
        { "type": "speech", "speaker": "char_01", "text": "말풍선 대사" }
      ],
      "characters": [{ "character_id": "char_01", "emotion": "smile" }]
    }]
  }]
}
```

카피 헤드/서브는 `dialogue` 배열의 narration 항목으로 표현. 말풍선은 speech. 샷·앵글은 `shot` 필드. **추가 필드 없이** 기존 스키마로 충분. 다만 `dialogue.bubble_style: "headcopy"` 같은 확장은 렌더링 레이어 추가 필요(⑦ 참조).

## ④ 콘티 생성이 1컷 대본을 받을 때 제약

### 현재 규칙

| 규칙 | 위치 | 강도 |
|---|---|---|
| 최소 6컷 | `SYSTEM_INSTRUCTION` 프롬프트 | AI 프롬프트 (코드 미검증) |
| 씬당 최소 2컷 | `recommend_cut_count()` + `READJUST_INSTRUCTION` | AI 프롬프트 |
| `absolute_min = max(num_scenes * 2, 6)` | `recommend_cut_count()` | 추천값 계산 |

### 1컷 대본 시 영향

- `create_cuts_from_script()`에는 **최소 컷 수 하드 가드 없음** — 1씬 1컷 JSON이 오면 그대로 Cut 1개 생성
- `recommend_cut_count()`는 `absolute_min=2`로 나오지만, 기존 대본이 이미 1컷이면 readjust 할 필요 없음
- `readjust_storyboard()`의 "씬당 2컷" 프롬프트 규칙은 **1컷 트랙에선 호출 자체를 건너뛰면** 무관

**결론:** 1컷 대본은 별도 프롬프트로 생성 + `create_cuts_from_script`에 그대로 전달하면 동작. 기존 규칙이 **코드 레벨 가드가 아닌 AI 프롬프트**이므로 우회 불필요.

## ⑤ StepHeader 단계 목록 — purpose별 변경 가능성

### 현재 구조

```js
const STEPS = [
  { n: 1, key: '1_planning',    name: '기획',       desc: '...' },
  { n: 2, key: '2_script',      name: '대본',       desc: '...' },
  { n: 3, key: '3_assets',      name: '자산 준비',   desc: '...' },
  { n: 4, key: '4_storyboard',  name: '콘티·장소',   desc: '...' },
  { n: 5, key: '5_review',      name: '웹툰 만들기', desc: '...' },
];
```

- **하드코드 5단계**, `export { STEPS }` 외부 참조
- 프로그레스 바: `approvedCount / 5` 하드코드
- 헤더 표시: `STEP {n} / 5`

### "한 컷 트랙" 3단계 표시 (속은 5게이트)

**방법 A — STEPS 자체를 purpose별 분기:**
```js
const STEPS = purpose === 'onecut_ad'
  ? [
      { n: 1, key: '1_planning', name: '브리프',   desc: '...' },  // gate 1
      { n: 3, key: '3_assets',   name: '자산',     desc: '...' },  // gate 3 (gate 2 스킵)
      { n: 5, key: '5_review',   name: '완성',     desc: '...' },  // gate 5
    ]
  : [현재 5개];
```
- `gateStatus` prop에서 `purpose` 읽기
- 프로그레스 바를 `steps.length` 기준으로 변경
- Gate 2·4는 auto_advance로 자동 승인 (백엔드에서)

**방법 B — 현재 5단계 유지하되 라벨만 변경:**
- 덜 혼란스러움, 하지만 "5단계나 있어?" 인상

**추천: 방법 A.** `STEPS`를 prop → `gateStatus.purpose` 기반 분기. 진행 바는 `steps.length` 동적.

## ⑥ 분위기 → 스타일 프리셋·연출 강도·실사 매핑 상수 자리

### 현재 독립 시스템

| 시스템 | 상수 위치 | 제어 | 연결 |
|---|---|---|---|
| **스타일 프리셋** | `backend/app/styles/models.py` STYLE_PRESETS (16종) | Gate3 선택 | prompt_snippet → 컷 프롬프트 |

### 분위기→자동 매핑 상수 자리

`idea_brief.tone` 또는 `idea_brief.suggested.mood` → 스타일/연출 자동 제안. 매핑 상수는 **`backend/app/prompts/mood_mapping.py`** (신규) 또는 `drama.py`에 추가:

```python
MOOD_TO_STYLE = {
    "warm": "emotional_romance",
    "tense": "noir_shadow",
    "cheerful": "korean_webtoon",
    ...
}
MOOD_TO_DRAMA = {
    "warm": "light",
    "tense": "strong",
    "cheerful": "normal",
    ...
}
```

Gate3에서 스타일 미선택 시 자동 제안(덮어쓰기 아님).

## ⑦ 내레이션 박스 → "헤드카피" 레이어 확장 가능성

### 현재 bubble_style 타입

`VALID_STYLES` (composition/bubble_mapping.py): `round`, `narration`, `thought`, `whisper`, `shout`, `angry`, `happy`, `sad`, `surprised`, `shy`, `flustered`, `realize`, `box`, `bar`

### 확장 방법

1. `VALID_STYLES`에 `"headcopy"` 추가
2. `BUBBLE_CONFIGS` (BubbleOverlay.jsx)에 headcopy 정의:
   - 대형 폰트 (fontSize 2.0+, 현재 범위 0.9~1.15)
   - 상/하단 고정 (y=5% 또는 y=85%)
   - 흰 글씨 + 드롭쉐도우 또는 외곽선
   - 배경: 투명 또는 반투명 그라데이션
3. Pillow 렌더 (`composition/service.py`)에 headcopy 분기
4. `RENDERER_VERSION` 올리기
5. CutEditor 툴바에 "헤드카피" 버튼 (내레이션 도구 옆)

**기존 `isNarrationBox` 코드 경로 재사용 가능** — 가변 폰트 크기·위치 지원 이미 구현. fontSize 배율만 키우면 됨. **서브카피**는 별도 dialogue 항목 + fontSize 중간 크기로.

## ⑨ 참고 광고 이미지

### 자산 테이블 위치

| 방안 | 테이블 | 필드 |
|---|---|---|
| A. episodes 확장 | `episodes` | `reference_ad_images JSON` (URL 배열, 최대 2장) |
| B. 별도 테이블 | `episode_references` | `id, episode_id, image_url, analysis_text, created_at` |
| **추천: A** | gate_status.reference_ads 또는 episodes 컬럼 | 2장 한도면 JSON 배열 충분 |

### 비전 분석 텍스트

analyze 엔드포인트 (0패킷, gemini flash 비전):
```
"분위기: warm pastel, 색감: #F5E6D3 베이지 톤, 구도: 인물 좌측 1/3 + 우측 제품,
텍스트 배치: 상단 중앙 헤드카피 + 하단 CTA, 조명: 좌상단 자연광"
```

### build_cut_prompt 주입 자리

`build_cut_prompt()` (prompts/service.py) 조립 순서:
1. 사진 실사 프리앰블
2. 단일 패널 강제
3. 캐릭터 앵커링
4. 캐릭터별 외형+감정
5. 장소/배경
6. 장면 액션
7. 드라마/연출
8. **제품 설명** ← 여기
9. **→ 참고 광고 분석 텍스트 삽입 자리** (9.5번)
10. 스타일 프롬프트
11. 샷 타입 + 스케일 가이드
12. 다인물 구도
13. 강조
14. 프로젝트 규칙
15. 배치 상식
16. 포맷 + "no text"

제품 설명 바로 뒤, 스타일 프롬프트 앞에 넣으면 분위기·구도·조명 지시가 스타일과 자연스럽게 합류.

### 참조 슬롯 우선순위

현재 5장 한도: 캐릭터 시트 → 표정 → 제품 → 장소

참고 광고 추가 시:
1. 캐릭터 시트 (1순위)
2. **제품** (2순위, has_product 컷)
3. **참고 광고** (3순위, 최대 1장 — 2장 중 대표 1장)
4. 표정 시트 (나머지 슬롯)
5. 장소 (마지막)

2인 이상이면 참고 광고 이미지 탈락(표정 우선). 1인 + 제품 + 참고 광고 = 3슬롯, 나머지 2슬롯에 시트+표정.

### 저작권 안내 문구 자리

- **업로드 모달:** 파일 선택 아래 회색 안내 "참고용으로만 사용됩니다. 저작권이 있는 이미지의 무단 복제는 금지됩니다."
- **약관:** 제7조(콘텐츠 권리) 조항에 "업로드된 참고 이미지의 저작권 책임은 이용자에게 있습니다" 1줄 추가

## 핵심 10줄

1. **gate_status.purpose** 키 신설(standalone/series/ad/onecut_ad) → `create_initial_gate_status`에 인자 추가, 프론트 모달 분기
2. **idea_brief 확장** — `ad_purpose`·`key_message`·`target_audience`·`cta` 4키 추가, `story` 4단은 "상황→문제→해결→CTA" 라벨 치환
3. **1컷 대본** — 기존 스크립트 스키마(scenes>cuts>dialogue)로 표현 가능, 최소 6컷·씬당 2컷은 AI 프롬프트일 뿐 코드 가드 없음
4. **콘티 1컷** — `create_cuts_from_script`에 최소 컷 하드 가드 없어 그대로 동작, readjust 호출 건너뛰면 됨
5. **StepHeader** — STEPS를 purpose 기반 분기(3단계 "브리프→자산→완성"), 프로그레스 바 `steps.length` 동적화
6. **분위기→스타일·연출** — 현재 독립 시스템, 매핑 상수 `mood_mapping.py`(신규) 또는 `drama.py` 추가
7. **헤드카피** — `bubble_style: "headcopy"` 추가로 대형 폰트 내레이션 구현 가능, 기존 `isNarrationBox` 경로 재사용
8. **expand 광고 변환** — purpose·is_ad·products 행·브리프 빈 키 승계, 진입점 결과 화면 버튼
9. **참고 광고** — `gate_status.reference_ads` JSON 배열(2장), 비전 분석→build_cut_prompt 제품 뒤 삽입, 참조 슬롯 3순위(시트→제품→참고→표정→장소)
10. **저작권** — 업로드 모달 안내 + 약관 1줄, 참고 이미지는 참조 생성에만 사용(출력에 직접 노출 아님)
