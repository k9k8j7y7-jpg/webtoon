# 지시서 P1 — 단편 아이디어 입력 UI (예시 칩 + 3축 선택)

> **전제:** 결정서-연작설계-v5.md의 확정 결정 6을 구현한다.
> **작업 방식:** 단계 순서대로. 각 단계 종료 시 멈추고 보고 → 확인 후 진행.
> **커밋은 사용자 확인 후.** 파괴적 git 명령 금지.
> **범위:** 단편 생성 플로우만. 연작 관련 코드는 이 지시서 범위 밖.

---

## 0. 목표

새 에피소드(단편) 생성 화면에서 사용자가 아이디어를 쉽게 입력하도록:
① 탭하면 입력칸이 채워지는 예시 칩, ② 장르/분위기/이야기 전개 3축
선택 버튼을 추가하고, 선택값을 기획 생성 프롬프트에 주입한다.
아무것도 선택하지 않으면 현행 동작과 동일해야 한다 (하위 호환).

## 1단계 — 현황 조사 (수정 금지)

1. 새 에피소드 생성 UI의 파일/컴포넌트 위치 (제목·아이디어 입력이 있는 곳)
2. 기획(Gate 1) 생성 API의 요청 스키마 — 아이디어 텍스트가 백엔드 어느
   필드로 가고, 기획 프롬프트가 조립되는 함수 위치
3. 에피소드 생성 시점과 기획 생성 시점의 관계 (에피소드 먼저 만들고
   기획 생성인지, 동시인지)
보고 후 멈춤.

## 2단계 — 데이터/백엔드

- 기획 생성 요청에 선택값 필드 추가:
  `story_options: { genre?, mood?, development? }` (전부 optional)
- 에피소드에도 저장 (재생성 시 재사용): episodes.spec 또는 기존 JSON
  필드에 story_options 보관 — 1단계 조사 결과에 맞는 위치로
- 기획 프롬프트 조립부에 주입. **선택값별 프롬프트 조각은 별도 상수
  파일/dict로 분리** (하드코딩 산재 금지 — 추후 프롬프트 컴파일러의
  부품이 됨):

### 프롬프트 조각 정의 (한국어 기획 프롬프트 기준, 조립 시 해당 언어로)

**장르(genre):** romance/daily/comedy/thriller/fantasy/drama
— 각 1문장: "이 웹툰의 장르는 {장르}다. {장르 관습 1구}" 수준

**분위기(mood):** warm/cheerful/tense/touching/dark
— 각 1문장: 전체 톤과 색감 지시

**이야기 전개(development):** 컷 배분 지시 형태로 작성 (핵심)
- calm(잔잔하게): "큰 사건 없이 감정선 중심. 기승전결의 '전'을 약하게,
  마지막 컷은 여운으로 마무리"
- dramatic(극적으로): "갈등 발생-심화-위기-해소의 뚜렷한 기승전결.
  중반에 명확한 위기 배치"
- twist(반전 있게): "마지막 1~2컷에서 앞의 전제가 뒤집히는 반전.
  복선을 중반에 1개 이상 심을 것"
- hook(초반 후킹): "1~2컷에 가장 강한 사건/충격 배치, 3컷부터 경위 설명"
- growth(성장·역전): "주인공이 낮은/위기 상태에서 시작, 노력·계기를
  거쳐 상승하는 구조. 마지막 컷은 성취 또는 다음 도약"
- mystery(미스터리·떡밥): "첫 컷에 의문 제시, 단서를 조금씩 배치,
  마지막 컷은 전부 해소하지 않고 여운/질문을 남김"
- cliffhanger(클리프행어): "마지막 컷은 해소 없이 새로운 위기/폭탄
  선언으로 종료. 다음 화 궁금증 유발"

미선택 필드는 프롬프트에 아무것도 추가하지 않는다 (현행 동일).
보고 후 멈춤.

## 3단계 — 프론트 UI

### 예시 칩
- 입력칸 아래 칩 3개 표시 (아래 8개 풀에서 랜덤, 화면 진입마다 로테이션)
- 탭 → 입력칸에 문구 채움(기존 입력 있으면 교체 확인 없이 교체하되
  입력칸 포커스 + 전체 선택 상태로 — 바로 수정 시작 가능하게)
- 칩 문구 8개(그대로 사용):
  1. "꽃집을 운영하는 청년이 손님들의 사연을 들으며 자신의 상처도 치유해가는 이야기"
  2. "회사에서 잘린 날, 우연히 복권에 당첨된 40대 가장에게 벌어지는 일"
  3. "전학 첫날, 옆자리 아이가 10년 전 헤어진 소꿉친구라는 걸 알아버렸다"
  4. "죽은 사람의 마지막 문자를 대신 전해주는 아르바이트를 시작했다"
  5. "매일 같은 하루가 반복되는데, 나만 그걸 기억한다"
  6. "천재 요리사였던 할머니의 레시피 노트를 물려받은 손녀의 성장기"
  7. "고백하려던 날, 상대가 먼저 다른 사람과 사귄다는 소식을 들었다"
  8. "지방 소도시에 혼자 내려온 신입 경찰이 마을의 오래된 실종 사건을 파헤친다"

### 칩-버튼 연동 (칩 탭 시 자동 선택, 사용자가 이후 변경 가능)
1→일상힐링·따뜻한 / 2→코미디·유쾌한 / 3→로맨스·따뜻한 /
4→드라마·먹먹한 / 5→판타지·긴장감 / 6→드라마·따뜻한·성장역전 /
7→로맨스·먹먹한 / 8→스릴러·어두운·미스터리떡밥
(전개 미지정 칩은 전개 미선택 상태 유지)

### 3축 버튼
- 섹션 3개: 장르(6) / 분위기(5) / 이야기 전개(7)
- 각 축 단일선택, 재클릭 시 해제. 전부 미선택 허용
- 전개 버튼에는 짧은 설명 표시 (툴팁 또는 버튼 아래 소형 텍스트):
  잔잔하게 "감정선과 여운 중심" / 극적으로 "뚜렷한 기승전결" /
  반전 있게 "마지막에 뒤집히는 결말" / 초반 후킹 "첫 컷부터 강한 사건" /
  성장·역전 "바닥에서 올라가는 이야기" / 미스터리·떡밥 "의문과 단서,
  끝에 여운" / 클리프행어 "다음 화가 궁금해지는 끝맺음"
- 모바일 대응: 버튼 랩 허용, 가로 스크롤 금지

## 4단계 — 검증

- 미선택 생성: 요청 페이로드에 story_options 없음(또는 전부 null),
  기획 프롬프트가 기존과 동일함을 로그로 확인 (하위 호환 판정)
- 3축 전부 선택 생성: 프롬프트에 조각 3개가 정확히 포함되는지 로그 확인
- 칩 탭 → 입력칸 채움 + 연동 버튼 선택 상태 확인 (Playwright)
- 전개 옵션 2종(초반 후킹 vs 잔잔하게)으로 같은 아이디어 기획 생성 →
  결과 기획의 방향이 실제로 달라지는지 1회 육안 비교 (완벽 판정 불요,
  조각이 무시되지 않는지만)
- 재생성 시 저장된 story_options가 재사용되는지

## 5단계 — 배포 + 확인 + 커밋

- 빌드 → scp 배포 → 사용자 테스트 → 확인 후 커밋:
  `feat(input): 단편 아이디어 입력 UI — 예시 칩 + 장르/분위기/전개 선택 (P1)`
- docs 커밋: 결정서-연작설계-v5.md, 지시서-P1-입력UI.md 를 docs/에 보관
