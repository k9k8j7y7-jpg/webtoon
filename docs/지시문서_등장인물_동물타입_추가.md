# 지시 문서: 등장인물 추가설명 필드 추가 (Gate 1)

## 배경

Gate 1(기획) 화면의 등장인물 입력이 현재 이름 / 성별 / 나이만 지원한다.
웹툰 아이디어에 동물이 등장하는 경우(예: "포메라이언 도도가 엄마 아빠와 같이 집앞 공원에서 보내는 즐거운 한때") 캐릭터를 표현할 방법이 없고, 자동 생성도 사람 캐릭터만 생성한다.

별도의 사람/동물 타입 구분 대신 **자유 텍스트 추가설명 필드 하나**를 추가한다.
- 동물: "포메라니안", "코리안숏헤어 고양이"
- 사람: "안경 쓴 회사원", "곱슬머리 초등학생" (외형·성격 힌트로 활용 가능)

## 목표

- 각 등장인물에 **추가설명**(선택 입력) 필드를 추가한다.
- 자동 생성이 아이디어 속 동물 캐릭터를 인식해 등장인물에 포함하고, 추가설명에 품종/종을 채운다.
- Gate 2(대본), Gate 3(자산) 프롬프트에 추가설명이 전달된다.

## 데이터 스키마

캐릭터 객체에 필드 1개 추가 (하위 호환 필수):

```json
{
  "name": "도도",
  "gender": "남",
  "age": 3,
  "description": "포메라니안"   // 신규, 선택 입력, 없으면 null/생략
}
```

**하위 호환 규칙:** `description` 없는 기존 캐릭터는 그대로 동작해야 한다. 마이그레이션 스크립트 금지, 읽기 시점에 빈 값 처리.

**백엔드 확인:** 캐릭터 배열이 자유 dict 스키마로 저장된다면 백엔드 수정 불필요. 필드가 고정 검증되고 있다면 `description`을 optional로 추가. 확인 결과를 보고에 포함할 것.

---

## 단계 1: 프론트엔드 — 캐릭터 입력 UI

대상: Gate 1 기획 화면의 등장인물 컴포넌트 (파일명은 코드베이스에서 확인)

1. 각 캐릭터 행에 추가설명 입력란(text) 추가
   - placeholder: "추가설명 (예: 포메라니안, 안경 쓴 회사원)"
   - 선택 입력. 비워도 저장/생성 진행 가능
2. 레이아웃: [이름][추가설명][성별][나이][삭제] 순서. 추가설명란은 이름란과 비슷한 너비로, 좁은 화면에서는 줄바꿈 허용.
3. 직접 추가로 새 행을 만들 때 description은 빈 문자열로 초기화

**커밋:** `feat: Gate1 등장인물 추가설명 필드 UI`

## 단계 2: 자동 생성 프롬프트 수정

대상: 등장인물 자동 생성 API의 프롬프트

1. 프롬프트에 다음 지시 추가:
   - 아이디어에 동물이 등장하면 반드시 등장인물에 포함할 것
   - 각 캐릭터의 `description`에 짧은 특징을 채울 것 — 동물은 품종/종(아이디어에 명시돼 있으면 그대로, 예: "포메라니안"), 사람은 외형·역할 한 줄(예: "도도의 보호자, 40대 아빠")
   - 동물의 나이는 해당 동물 기준의 자연스러운 나이로
2. 응답 JSON 스키마에 `description` 필드 추가
3. 검증: 스크린샷의 아이디어("포메라이언 도도가 엄마 아빠와...")로 자동 생성 시 도도(description: 포메라니안) + 엄마 + 아빠 3인이 생성되는지 확인

**커밋:** `feat: 등장인물 자동 생성에 description 지원`

## 단계 3: 하위 게이트 전달 확인

1. Gate 2(대본) 생성 프롬프트에 캐릭터 정보가 어떤 형태로 주입되는지 확인하고 description이 포함되도록 수정
   - 예: "도도 (포메라니안, 남, 3살)" 형태의 문자열 직렬화. description이 비어 있으면 기존 형식 그대로.
2. Gate 3(자산/캐릭터 시트) 생성 프롬프트에 동일하게 반영
   - 동물 캐릭터(description으로 동물임이 드러나는 경우)가 사람용 캐릭터 시트 템플릿과 충돌할 수 있음(의상 시트, 표정 시트 구성 등). 충돌 지점이 발견되면 **수정하지 말고 멈추고 보고할 것** — 동물용 시트 템플릿 설계는 별도 세션에서 결정한다.

**커밋:** `feat: Gate2/3 프롬프트에 캐릭터 description 전달`

## 단계 4: 저장/로드 라운드트립 확인

1. description 입력 상태로 기획 저장 → 새로고침 → 값 유지 확인
2. description 없는 기존 에피소드 열기 → 정상 표시 확인 (하위 호환)

**커밋 없음. 확인 결과만 보고.**

---

## 중지 및 보고 지점

- 단계 3에서 동물 캐릭터 시트 템플릿 충돌 발견 시 즉시 중지·보고
- 백엔드 스키마 수정이 필요한 경우, 수정 전에 해당 파일과 변경 범위를 먼저 보고
- 각 단계 완료 시 커밋 해시와 함께 결과 보고

## 하지 말 것

- 사람/동물 타입 토글, 품종 전용 필드 등 구조화 필드 추가 금지 (자유 텍스트 description 하나로 통일)
- 기존 캐릭터 데이터 마이그레이션 스크립트 작성 금지
- 이 문서 범위 밖의 리팩토링 금지
- 동물용 캐릭터 시트 프롬프트 템플릿 신규 설계 금지 (충돌 발견 시 보고만)
