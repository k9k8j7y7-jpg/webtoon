# 지시서 P4 — 연작 입구 + 시리즈 기획 + 2-A 회차 아웃라인

> **전제:** P2(series 테이블·최소 API)·P3 완료. 결정서-연작설계-v5.md
> 확정 결정 1(Gate 2 이층화)·2(데이터 구조)·5(입구 UI) 구현.
> **작업 방식: 각 단계 종료 시 멈추고 보고 → 사용자 확인 후 진행.**
> 커밋은 사용자 확인 후. 파괴적 git 명령 금지.

## 0. 목표와 범위

연작 시리즈를 만들고 회차 계획(아웃라인)을 편집하는 화면까지.
**이 지시서의 전 과정은 텍스트 생성만 있고 이미지 비용 0.**

- 프로젝트 화면: 버튼 2개(+단편/+연작) + 시리즈 카드
- 연작 생성 → 시리즈 기획(바이블) 생성 → 2-A 아웃라인 화면
- 아웃라인 편집: 요약 수정 / 회차 추가 / 병합 / 분할 / 순서 변경
- **범위 밖:** 회차 대본 생성(2-B = P5), 회차 에피소드 행 생성,
  잠금 UI(P6). 아웃라인의 episode_id는 이 단계에서 전부 null 유지.

## 1단계 — 조사 (수정 금지)

1. P2의 series 최소 API(POST /projects/{id}/series, GET /series/{id})
   현재 상태 — 스키마와 실제 동작 재확인
2. ProjectPage의 에피소드 리스트 렌더 구조 (시리즈 카드를 섞어
   넣을 위치)
3. 단편 Gate 1의 기획 생성 프롬프트/응답 구조 (연작 기획이 재사용할
   부분과 달라질 부분 파악)
보고 후 멈춤.

## 2단계 — 백엔드

### 시리즈 생성 + 기획(바이블) 생성
1. POST /projects/{pid}/series — title, idea, story_options(장르/분위기)
   받아 series 행 생성 (bible/outline은 빈 상태)
2. POST /series/{sid}/bible — 바이블 생성 (텍스트 AI 1콜):
   - 입력: idea + 장르/분위기 조각(P1의 prompt_fragments 재사용) +
     등장인물(선택) + **목표 회차 수** (사용자 지정, 기본 8,
     범위 4~24)
   - 출력(JSON 강제): {
       synopsis(전체 줄거리), world(세계관 요약),
       characters[](주요 인물 요약),
       outline[]: [{no, title, summary, hook}] — 회차 수만큼
     }
   - 프롬프트 필수 지시: "각 화는 미니 기승전결 + 엔딩 훅.
     사건 크기와 긴장 리듬으로 분할"
   - 저장: series.bible = {synopsis, world, characters},
     series.outline = [{no, title, summary, hook,
       episode_id: null, status: "outline"}]
3. 바이블/아웃라인 부분 재생성:
   - POST /series/{sid}/bible/regenerate — 전체 재생성 (확인 후)
   - POST /series/{sid}/outline/regenerate — body: {from_no} —
     from_no 이후 회차만 재생성 (앞 회차 요약을 컨텍스트로 주입,
     "방향 바꾸기" 용도. episode_id 있는 회차는 건드리지 않음 —
     지금은 전부 null이라 해당 없음이지만 방어 코드 포함)

### 아웃라인 편집 API
4. PUT /series/{sid}/outline — 배열 통째 교체 (기존 JSON 왕복 패턴).
   서버 검증: no 연속성 재부여(리넘버링 서버 책임), episode_id가
   있는 항목은 삭제/병합 불가 (지금은 전부 null — 방어만)
5. POST /series/{sid}/outline/merge — body: {no_a, no_b} (인접 회차):
   요약 2개를 AI로 1개로 재정리(텍스트 1콜), 훅은 뒤 회차 승계,
   리넘버링
6. POST /series/{sid}/outline/split — body: {no}: 해당 회차 요약을
   AI로 2개 회차로 분할 제안(텍스트 1콜), 리넘버링
7. GET /projects/{pid}/series — 프로젝트의 시리즈 목록
   (리스트 카드용: title, 회차 수, 진행 요약)
8. DELETE /series/{sid} — 회차 에피소드가 하나도 없을 때만 허용
   (보수적 삭제, P3 패턴)
보고 후 멈춤.

## 3단계 — 프론트

### 프로젝트 화면
- 버튼 2개: `+ 단편 에피소드`(기존 모달) / `+ 연작 시리즈`(새 모달)
- 연작 모달: 제목 + 아이디어(+예시 칩 재사용) + 장르/분위기
  (전개 축 없음 — 결정서대로 회차별로 이동) + **목표 회차 수**
  셀렉트(4/8/12/16/24, 기본 8)
- 리스트에 시리즈 카드: `[연작]` 보라 뱃지 + 제목 +
  "N화 계획 · 대본 0 · 이미지 0" (지금은 아웃라인 수만 유효) +
  클릭 → 시리즈 홈(2-A)

### 시리즈 홈 (2-A 아웃라인 화면) — 신규 페이지
```
[시리즈 제목]                     [바이블 보기/접기] [전체 재생성]
시놉시스 (접이식) / 세계관 / 주요 인물 요약

회차 아웃라인                     [+ 회차 추가]
┌ 1화. 제목        상태: 아웃라인
│  요약 (인라인 수정 가능)
│  엔딩 훅: ...
│  [수정] [병합↓] [분할] [삭제] [↑] [↓]
├ 2화. ...
...
[N화부터 다시 생성] (from_no 재생성 진입)
```
- 병합: 인접 다음 회차와. 확인 다이얼로그("1화+2화를 합칩니다.
  요약이 재작성됩니다") → merge API
- 분할: 확인 → split API → 결과 2개 회차로 교체
- 순서 변경: ↑↓ 버튼 (드래그는 범위 밖)
- 각 회차에 [대본 생성] 버튼 자리는 만들되 **비활성 +
  "다음 업데이트에서 제공"** 툴팁 (P5 진입점 예약)
- 모바일: 카드 세로 스택, 버튼 랩

### 라우팅
- /projects/{pid}/series/{sid} — 시리즈 홈
- 에피소드 workflow 라우트는 무변경
보고 후 멈춤 (스크린샷 포함).

## 4단계 — 검증

1. 연작 생성 → 바이블 생성: 12화 지정 시 outline 12개, 각 항목에
   title/summary/hook 존재, episode_id 전부 null (API 응답 검증)
2. 훅 품질 샘플: 생성된 아웃라인 1건의 각 화 hook이 실제로
   다음 화 유도형인지 육안 1회 (완벽 판정 불요)
3. 편집 왕복: 요약 수정 → 저장 → 새로고침 유지
4. 병합: 3화+4화 → 회차 수 -1, 리넘버링, 훅 승계 확인
5. 분할: 1회차 → 2회차, 리넘버링
6. from_no 재생성: 5화부터 → 1~4화 불변, 5화 이후 교체
7. 순서 변경 → 저장 유지
8. 시리즈 삭제: 빈 시리즈 삭제 OK (회차 에피소드 생기는 건 P5라
   거부 케이스는 P5에서 검증)
9. 회귀: 단편 생성/리스트 무변경
Playwright + API 수치. 보고 후 멈춤.

## 5단계 — 배포 + 사용자 테스트 + 커밋

    이 커밋에 포함)

## 범위 제한
- 회차 대본 생성 금지 (P5). [대본 생성] 버튼은 비활성 예약만
- episodes 행 생성 금지 — outline은 순수 JSON 편집
- 잠금/상태 뱃지 로직 금지 (P6). status는 "outline" 고정
- 단편 플로우 코드 변경 최소화 (모달 분기 외 무변경)
