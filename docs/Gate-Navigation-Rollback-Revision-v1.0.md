---

## 배경

두 가지 문제가 확인됨:

**문제 1 (버그):** 게이트 1(기획)·2(대본)가 재진입 시 저장된 데이터를 로드하지 않아, 사용자가 내용을 다시 생성해야 함. (게이트 3·4·5는 `useEffect`로 로드 정상 동작)

**문제 2 (기능 미비):** 완료된 게이트를 클릭해도 이동/열람 불가. 이전 단계 내용을 확인하거나 수정할 방법이 없음.

> 저장 방식은 **자동 저장**으로 한다. 별도 "임시저장" 버튼 없음. 생성 시 DB에 저장되며(게이트 3·4·5가 이미 그러함), 재진입 시 자동 로드. 목적은 "작업이 날아가지 않는 것"이며 자동 저장이 이를 가장 확실히 달성.

---

## A. 문제 1 — 게이트 1·2 데이터 로드 (버그 수정)

게이트 3·4·5와 동일한 방식으로 맞춘다.

### 게이트 1 (기획)
**백엔드:**
- `GET /projects/{id}/episodes/{id}/planning` 엔드포인트 신설.
- 반환: `episode.title`, `logline`, `synopsis`, `script["planning"]` 등 기존 기획 데이터.

**프론트엔드:**
- 마운트 시 `useEffect`로 GET 호출.
- 데이터 있으면 planning state에 세팅 → 기획 결과 화면 바로 표시.
- 데이터 없으면 현행대로 아이디어 입력 폼 표시.

### 게이트 2 (대본)
**백엔드:**
- `GET /projects/{id}/episodes/{id}/script` 엔드포인트 신설.
- 반환: `episode.script["script"]`의 기존 대본(씬·컷·대사).

**프론트엔드:**
- 마운트 시 `useEffect`로 GET 호출.
- 데이터 있으면 script state에 세팅 → 씬/컷 목록 바로 표시.
- 데이터 없으면 현행대로 대본 생성 버튼 표시.

### 검증
- 게이트 1·2에서 생성 후 에피소드를 나갔다가 재진입 → 내용이 그대로 보이는지 확인.

## B. 문제 2 — 이전 게이트 열람 + 되돌아가기 (C안)

### B-1. 완료된 게이트 클릭 → 읽기 전용 열람
- `GateProgress` 컴포넌트에서 **완료(approved) 상태인 게이트**를 클릭 가능하게.
- 클릭 시 해당 게이트 내용을 **읽기 전용**으로 표시. (수정/생성 버튼 비활성 또는 숨김)
- 목적: 예) 대본 작업 중 기획 내용을 다시 확인.
- **기본은 읽기 전용** — 실수로 이전 단계를 수정해 이후 작업이 날아가는 사고 방지.

### B-2. "이 단계로 되돌아가기" 버튼
- 읽기 전용 열람 화면에 **[이 단계로 되돌아가기]** 버튼 배치.
- 클릭 시 → **무효화 경고**(B-3) 표시 → 확인 시 해당 게이트가 `current_gate`로 변경되어 수정 가능 상태로 전환.

### B-3. 무효화 경고 (필수)
되돌아가기 확정 전, **무엇이 무효화되는지 구체적으로** 보여준다.

- Backend-State-Model 3장의 무효화 전파 로직 + API-Spec의 `dry_run`을 활용해, 영향 범위를 **미리 계산**해서 표시.
- 경고 문구 예시 (구체적으로):
  ```
  이 단계로 돌아가 수정하면 다음이 재생성되어야 합니다:
   · 캐릭터 2명 (미나, 여름)
   · 장소 3곳
   · 콘티 15컷
  계속하시겠습니까?
  ```
- 단순 "이후 단계가 무효화됩니다"가 아니라, **실제 영향받는 자산·컷 수를 명시**.
- 확인해야만 진행. 취소 시 읽기 전용 열람으로 복귀.

### B-4. 되돌아가기 실행 (백엔드)
- 되돌아가기 확정 시:
  - `episodes.gate_status.current_gate`를 해당 게이트로 변경.
  - Backend-State-Model 3장의 무효화 전파 실행: 이후 게이트 `gate_status` → `invalidated`, 영향 자산·컷 status → `invalidated`.
  - **지능적 무효화 적용**: diff로 영향 없는 자산은 유지 (Backend-State-Model 3.2).
  - **이미지는 삭제하지 않고 stale 표시** (Backend-State-Model 4, Q26).
- 이미 구현된 무효화 전파 로직(참조: 개발 시 "게이트7 무효화")과 연동.

### B-5. dry_run 엔드포인트
- 되돌아가기 경고용 영향 계산: `POST .../revert?dry_run=true` 또는 유사 엔드포인트로 **실행 없이 영향 목록만** 반환.
- 확정 시 `dry_run` 없이 호출 → 실제 무효화 실행.

## 흐름 요약

```
[✓기획] [✓대본] [✎자산] [🔒콘티] [🔒이미지]
   │
   ├─ 클릭 → 읽기 전용 열람 (확인만)
   │
   └─ [이 단계로 되돌아가기] 클릭
         ↓
      무효화 경고 (dry_run으로 영향 계산)
      "자산·콘티·이미지가 재생성됩니다 — 계속?"
         ↓ 확인
      current_gate 변경 + 무효화 전파 실행
      (지능적 무효화 / 이미지 stale 유지)
         ↓
      해당 게이트 수정 가능 상태
```

## 우선순위

1. **A (데이터 로드 버그)** 먼저 — 리스크 없는 명확한 수정. "데이터 보존" 확보.
2. **B (되돌아가기 + 경고)** — 무효화 로직 연동이라 A 완료 후.

> A를 먼저 완료해 "재진입 시 데이터가 남는다"를 확정한 뒤 B를 얹는다.

---

## 주의사항

- 되돌아가기 시 무효화는 **DB 트리거가 아니라 서비스 계층**에서 처리 (Backend-State-Model 5).
- 이미지 무효화 시 **S3 파일 삭제 금지**, stale 표시만 (Q26).
- 무효화 경고는 반드시 **구체적 영향 목록**을 포함 (단순 알림 금지).
