### /view?n={id} FAIL 원인 분석

`useAutoReadNotification()` (App.jsx:38-49):
- `AppRoutes` 컴포넌트 안에서 호출 → 모든 라우트에서 작동
- **조건:** `if (!nId || !user) return` — user가 null이면 스킵
- **deps:** `useEffect([], [])` — 빈 배열 = 마운트 1회만 실행
- `/view/:shareToken`은 `<RequireAuth>` 밖 (비로그인 공개) → localStorage 토큰이 있어도 `useAuth` 비동기 로딩 중 user=null일 수 있음
- **근본 원인:** `user`가 로딩 완료 전에 useEffect가 실행되어 `!user` 조건에 걸림. deps에 `user`가 없어 재실행도 안 됨

## 요약

1. **WebAPK 자동 재구독 성공** — `push_enabled_here` 플래그 기반 자동 재구독이 01:04:52에 동작, id=6 생성
2. **410 정리 정상** — id=5가 첫 발송 시 410으로 삭제, 이후 발송은 id=2+6 두 건 모두 성공(DELETE 없음)
3. **크롬 탭 구독 생존** — id=2 (10-12 생성)가 아직 유효. 크롬 탭과 WebAPK 양쪽 모두 푸시 수신 가능
4. **알림 3건 미읽음** — 알림센터에서 개별 탭을 안 했거나 read 호출이 안 된 것
5. **폴링 없음** — /notifications 페이지는 주기적 폴링 없이 이벤트 기반 갱신 (라우트 이동, window focus, unread 증가 시)
6. **/view?n={id} read FAIL** — `useAutoReadNotification`의 useEffect가 user 로딩 전에 실행되어 스킵. deps에 user/nId 누락
7. **logger 미출력** — `send_push`의 요약 로그(`sent=N removed=N`)가 uvicorn.log에 안 남음. 로깅 핸들러 설정 점검 필요
8. **대응 필요 2건:** (A) `useAutoReadNotification` deps에 `user`, `params` 추가 (B) 알림 목록 폴링 또는 push 이벤트 기반 갱신 검토
