# Gate5Review 재작성 지시서 v1.0 (3단계)

> **대상:** Claude Code
> **파일:** `frontend/src/components/Gate5Review.jsx` (주 대상)
> **전제:** BubbleOverlay 12종 중 11종 완료 (surprised 조정은 별개 작업, 이번 범위 아님)
> **목표:** git 사고로 유실된 CutEditor 연동을 복원한다. 컷 편집 진입 → 편집 → 저장 → 반영의 왕복을 되살린다.

---

## 0. 이 작업의 성격 — 반드시 이해하고 시작할 것

지금까지의 BubbleOverlay 복구는 "깨진 것을 고치는" 작업이었다.
이번은 다르다. **현재 게이트5 화면은 보기 기능이 정상 동작 중이다.**
썸네일 그리드, 미리보기 모달, 재생성, Export 버튼 모두 살아있다.

따라서 이번 작업의 제1 원칙은:

**"기존에 돌아가는 것을 깨뜨리지 않으면서, 없어진 편집 입구를 다시 단다."**

기존 코드를 대규모로 갈아엎지 마라. 필요한 최소한만 추가·수정한다.
"더 깔끔한 구조로 리팩토링"은 이번 작업이 아니다. 문서 6장의 사고
(리팩토링 중 화면 파라미터까지 변경 → 유실)를 반복하지 마라.

## 1. 절대 규칙

### 하지 말 것
- `BubbleOverlay.jsx`를 수정하지 마라. 어떤 이유로도.
  연동 중 BubbleOverlay에 문제가 보이면 수정하지 말고 보고해라.
- `CutEditor.jsx`를 수정하지 마라. **CutEditor가 명세다.**
  Gate5Review가 CutEditor에 맞춘다. 반대가 아니다.
  CutEditor에 버그가 의심되면 수정하지 말고 보고해라.
- `SfxLayer.jsx`, `exportRenderer.js`, `bubbleLayout.js`,
  `bubbleMapping.js` 수정 금지.
- 백엔드 코드 수정 금지. 저장 API가 없거나 스펙이 다르면
  수정하지 말고 보고해라.
- 새 설정 파일 금지. 새 컴포넌트 파일은 원칙 금지
  (모달 래퍼 수준의 소형 분리가 꼭 필요하면 사전 보고 후 승인받아라).
- `git checkout`, `git reset`, `git stash` 등 파괴적 명령 금지.
- 각 단계 완료 후 사용자 확인 전 커밋 금지.

### 반드시 지킬 것
- 각 단계(3장의 A~D)가 끝나면 **멈추고 화면 확인을 요청**한다.
- 매 단계에서 기존 기능 회귀를 확인한다 (5장 회귀 목록).
- 컷 spec 데이터를 다룰 때 **편집하지 않은 필드를 유실하지 마라.**
  spec에는 dialogue 외에도 characters, location_id, action,
  sfx_items, emphasis 등이 있다. 저장 시 전체 spec을 보존하고
  변경된 부분만 갱신한다.

## 2. A단계 — 조사 (코드 수정 금지)

**아무 코드도 수정하지 말고** 아래를 조사해 보고해라.
이 보고를 사용자가 승인한 뒤에 B단계를 시작한다.

### 2-1. CutEditor.jsx 인터페이스 (가장 중요)
- CutEditor가 받는 props 전체 목록: 이름, 타입, 용도.
  코드에서 그대로 인용해라.
- 저장은 어떤 형태인가? (onSave 콜백? 어떤 인자를 넘기나?)
- 닫기는? (onClose? onCancel?)
- CutEditor가 컷 하나를 받나, 컷 목록과 인덱스를 받나?
- CutEditor 내부에서 API를 직접 호출하는 부분이 있는가,
  아니면 순수하게 콜백으로 결과를 넘기는가?

### 2-2. 현재 Gate5Review.jsx 상태
- 현재 구조 요약: 어떤 상태(state)를 갖고, 어떤 API를 부르고,
  어떤 하위 요소를 렌더하는가.
- CutEditor를 import하거나 참조하는 코드가 한 줄이라도 있는가.
- 미리보기 모달이 어떻게 구현되어 있는가
  (편집 모달을 같은 패턴으로 만들 수 있는지 판단 근거).

### 2-3. 저장 API
- 컷 spec을 갱신하는 백엔드 엔드포인트가 존재하는가?
  frontend의 api 호출부(axios/fetch 래퍼)에서 찾아라.
- 있다면: 메서드, 경로, 요청 본문 형태, 컷 단위인지 에피소드 단위인지.
- 없다면: 그렇다고 보고만 해라. (백엔드 수정은 별도 논의)

### 2-4. SfxLayer.jsx 인터페이스
- props 목록과 용도.
- 현재 Gate5Review 또는 CutEditor 어디에서든 사용되고 있는가.

### 2-5. 서버 번들 참고 (선택)
- 시간이 오래 걸리지 않는 범위에서, 유실 전 번들
  (서버 assets의 8/12 이전 index-*.js 중 flustered 포함본)에서
  Gate5Review가 CutEditor를 어떤 조건으로 열었는지
  (버튼? 컷 클릭? 모달?) 구조만 참고해라.
  수치나 세부 구현을 복사하지 마라. 흐름 참고용이다.

### 보고 형식
- 위 항목별로 코드 인용과 함께.
- 마지막에 "B~D단계 구현 계획"을 5줄 이내로 요약해라.
- 문서 내용과 실제 코드가 충돌하는 지점이 있으면 명시해라.

## 3. 구현 단계 — 반드시 이 순서로, 단계마다 멈춘다

### B단계 — 편집 진입과 닫기 (저장 없음)

목표: 편집의 "문"만 단다. 저장은 아직 하지 않는다.

1. 각 컷 카드에 "편집" 버튼을 추가한다.
   기존 버튼들(재생성, 대사)과 같은 줄, 같은 스타일 계열로.
2. 버튼 클릭 → CutEditor가 열린다.
   - A단계에서 확인한 props 명세대로 정확히 전달한다.
   - 미리보기 모달과 같은 패턴의 모달/전체화면으로.
3. CutEditor의 닫기 콜백 → 모달이 닫히고 게이트5로 돌아온다.
   이 시점에서는 **저장하지 않는다.** 편집해도 버리고 닫는다.
4. 저장 콜백이 호출되면 일단 console.log로 인자만 찍고 닫는다.

**확인 요청 항목:**
- 편집 버튼이 12컷 모두에 보이는가
- 클릭 시 CutEditor가 열리고 해당 컷의 이미지·말풍선이 보이는가
- 말풍선 드래그·크기·종류 변경이 편집 화면 안에서 동작하는가
  (12종 팔레트 — BubbleMiniIcon — 가 보이는가)
- 닫으면 게이트5로 정상 복귀하는가
- 기존 기능 회귀 (5장)

**→ 사용자 확인 후 커밋. 그 다음 C단계.**

### C단계 — 저장 왕복

목표: 편집 결과가 저장되고, 다시 열면 그대로 나온다.

1. CutEditor의 저장 콜백에서 받은 결과를
   A단계에서 확인한 저장 API로 전송한다.
2. 저장 성공 → 게이트5의 컷 데이터를 갱신한다
   (전체 리로드 또는 해당 컷만 갱신 — 기존 데이터 흐름에 맞춰라).
3. 저장 실패 → 사용자에게 알리고 편집 내용을 잃지 않게 한다
   (모달을 닫지 않거나, 재시도 안내).
4. **spec 보존 검증:** 저장 전후의 spec을 console.log로 찍어
   dialogue 외 필드(characters, sfx_items 등)가 유실되지 않는지
   스스로 확인해라.

**확인 요청 항목:**
- 말풍선을 옮기고 저장 → 게이트5 보기 화면에 즉시 반영되는가
- 페이지 전체 새로고침 후에도 유지되는가 (진짜 저장 확인)
- 다시 편집을 열면 옮긴 위치 그대로인가
- 말풍선 종류를 바꿔 저장해도 동일하게 왕복되는가
- 편집하지 않은 다른 컷들이 멀쩡한가
- 기존 기능 회귀 (5장)

**→ 사용자 확인 후 커밋. 그 다음 D단계.**

### D단계 — SfxLayer 통합

목표: 효과음이 보기 화면과 편집 화면에서 표시된다.

1. A단계 조사 결과에 따라 SfxLayer를 배선한다.
   - 이미 CutEditor 내부에서 쓰고 있다면: 보기 모드
     (게이트5 미리보기)에만 추가하면 된다.
   - 어디에도 없다면: 보기 모드부터 추가하고,
     편집 쪽은 CutEditor 수정이 필요하므로 보고만 해라.
2. sfx_items가 있는 컷(준호 에피소드 #4 "반갑!!")에서 확인.

**확인 요청 항목:**
- #4에서 효과음이 보이는가 (위치·회전·색상 반영)
- sfx 없는 컷에서 아무 영향 없는가
- 기존 기능 회귀 (5장)

**→ 사용자 확인 후 커밋. 3단계 완료.**

각 단계 확인 요청 전에 스스로 점검하고 결과를 보고에 포함해라.

## 6. 검증 방법

- Playwright 셀프 루프를 계속 쓴다.

  시나리오를 추가해라 (B단계에서 시도, 어려우면 보고 후 수동).
