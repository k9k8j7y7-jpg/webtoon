## 핵심 8줄

1. **products 테이블 이미 존재** — `episode_id·name·features·photo_url(투명PNG)·sheet_url(일러시트)·status`. characters 확장 불필요
2. **참조 이미지 5장 한도** (`MAX_REF_IMAGES=5`, images/service.py:35) — 캐릭터 시트+표정+장소+제품 시트 경합. 실사 캐릭터 3장이면 제품 슬롯 0
3. **제품 참조 이미 구현됨** — `has_product=True`인 컷에서 `Product.sheet_url` 자동 첨부(images/service.py:329–343) + `product_desc` 프롬프트 주입
4. **라벨 텍스트 재현은 양쪽 다 불가** — GPT·Gemini 모두 세부 글자 뭉개짐 (scratch 실험: "SCALP SUPPORT"까지만 판독). **제품 레이어(product_items) 합성이 정답**(현행)
5. **빠른 한 컷 QuickRequest**: prompt·preset_ref·style·aspect_ratio·shot·dialogue 6필드. 제품 사진 추가 = `product_photo` 필드 1개 + 비전 추출 + 프롬프트 주입
6. **광고형 is_ad**: `gate_status` JSON 플래그 → AD_ADDON 대본·drama_level light·제품 CRUD 활성. 제품 등록 시 is_ad 자동 ON 가능
7. **비전 추출 비용 ≈ $0.0002/회** — gemini-2.5-flash 텍스트, 0패킷. 캐릭터·장소·제품 모두 동일 경로
8. **마젠타 합성(방법 C) 실패** — 모델이 flat #FF00FF를 못 지킴 + 접촉부 인페인팅 없음. 방법 A(참조 생성)가 최선, 제품 레이어로 보완

### 컷 spec JSON (`storyboard/service.py` create_cuts_from_script)
```json
{
  "cut_id": "ep01_c001",
  "scene_id": "s01",
  "cut_number": 1,
  "characters": [{"character_id": "hero", "emotion": "neutral", "pose": "", "outfit": "default"}],
  "location_id": "cafe_interior",
  "shot": "bust",
  "action": "카운터에서 제품을 들고 웃는다",
```

**"등장 제품" 필드:** `has_product` boolean이 이미 존재. 여러 제품 구분이 필요하면 `product_ids: [1, 2]` 배열 추가 가능하나, 현재 에피소드당 제품 1개이므로 불필요.

### 대본 생성 프롬프트 (`script/service.py`)
- `is_ad=True` → `AD_SCRIPT_INSTRUCTION_ADDON` 선택 (제품 자연 노출 + 완결 구조)
- 제품 정보: `gate_status["idea_brief"]["product"]` → planning dict 경유 → 대본 프롬프트 주입
- `_detect_product_in_cut()` — 콘티 생성 시 action/dialogue에 제품명이 나오면 `has_product=True` 자동 판정

## ⑤ 빠른 한 컷 + 제품 사진

### 현재 QuickRequest (`quick/router.py`)
```python
class QuickRequest(BaseModel):
    prompt: str          # 장면 설명 1–200자
    preset_ref: str      # 프리셋 캐릭터 키
    style: str           # korean_webtoon / anime / emotional_romance
    aspect_ratio: str    # 1:1 / 4:5 / 9:16
    shot: str            # auto / close_up / bust / full
    dialogue: str        # 선택, 말풍선 대사
```

### 제품 사진 1장 추가 시 영향
1. **QuickRequest 확장:** `product_photo: UploadFile | None` 필드 추가
2. **전처리:** 업로드 → 비전 추출(이름·형태·색) → `product_desc` 문자열
3. **프롬프트 주입:** `build_cut_prompt(product_desc=…)` + 제품 사진을 `ref_images`에 추가 (슬롯 1개)
4. **슬롯:** 프리셋 시트 1 + 표정 1 + 제품 사진 1 = 3/5 여유
5. **패킷:** 기존 1패킷 유지 (비전 추출은 텍스트 모델, 0패킷)
6. **제품 레이어:** 빠른 컷에서는 제품 레이어 합성 안 함 (복잡도 과다) — 참조 생성(방법 A)으로 충분

### 제품 ↔ is_ad 연결 가능성
| 시나리오 | 현행 | 개선안 |
|---|---|---|
| 광고형 에피소드에서 제품 등록 | ◎ 정상 동작 | 유지 |

### 보충 ② product_items 상세

**정의:** `cuts.spec["product_items"]` — JSON 배열 (effect_items·sfx_items·pngbubble_items와 동일 패턴)

**항목 구조:**
```json
{
  "product_id": 1,
  "x": 0.5,          // 0–1 정규화 중심 좌표
  "y": 0.5,
  "width": 0.3,      // 0–2, 컷 폭 대비 비율
  "rotation": 0,     // 0–360°
  "opacity": 1.0     // 0–1
}
```

**표시 이미지:** `product.photo_url` (실사 투명 PNG) — sheet_url이 아님. sheet_url은 AI 생성 참조용.

**파이프라인:**

| 단계 | 컴포넌트 | 역할 |
|---|---|---|
| 보기 | `ProductLayer.jsx` | `<img>` 절대 위치, center-anchor, pointer-events:none |
| 편집 | `CutEditor.jsx` 내 SVG 히트박스 | 드래그·회전·크기·투명도, productItems state → save 시 spec 저장 |
| 뷰어 | `ViewerPage.jsx`, `Gate5Review.jsx` | ProductLayer 렌더 |
| 내보내기 | `exportRenderer.js` | photo_url → Base64 fetch → SVG `<image>` (CORS taint 방지) |

**레이어 순서 (6단):** 이미지 → **제품** → 효과 → SVG말풍선 → PNG말풍선 → 효과음

**검증:** `_validate_product_items()` (storyboard/router.py) — product_id int, x/y/opacity ∈[0,1], width ∈(0,2], rotation ∈[0,360]

**운영 사용:** ep30 (헤어팩 광고)에서 실제 사용 중. 제품 실사 PNG를 컷 위에 오버레이하여 라벨 텍스트 보존.

### 보충 ③ 대본→콘티→컷 제품 흐름

**1. 아이디어 (Gate1):** `gate_status.idea_brief.product = {name, features}` — 광고 에피소드 생성 시 설정

**2. 대본 (Gate2, script/service.py):**
- `is_ad=True` → `AD_SCRIPT_INSTRUCTION_ADDON` 선택
- 애드온 핵심: "제품/브랜드를 스토리에 자연스럽게 녹여라", "캐릭터가 실제 사용/경험", "마지막 장면에 제품 자연스럽게 등장"
- `idea_brief.product`가 기획 프롬프트에 `"\n제품: {name} — {features}"` 주입 (story/service.py)

**3. 콘티 (Gate4, storyboard/service.py):**
- `create_cuts_from_script(product_names=[...])` — DB에서 에피소드 전체 제품명 조회
- `_detect_product_in_cut(cut_data, product_names)`:
  - action + 전체 dialogue.text 합쳐서 소문자화
  - 매칭 1: 제품명 키워드 (2글자 이상 각 단어)
  - 매칭 2: 제품 활동 키워드 `["제품","상품","패키지","브랜드","사용","바르","뿌리","마시","먹"]`
  - True → `has_product=True` 자동

**4. 이미지 (Gate5, images/service.py + prompts/service.py):**
- `has_product=True` → products DB 조회 → `sheet_url` 참조 첨부 (슬롯 남으면) + `product_desc` 텍스트 주입
- `build_cut_prompt(product_desc=...)` → 프롬프트에 "제품 설명 + 시트 참조 일치 + 크기 제약 + 자연 배치" 블록

**5. 편집 (Gate4/5):** 콘티 편집 모달에서 `has_product` 수동 토글 가능

### 보충 ④ 참조 5장 슬롯 우선순위

**조립 순서** (`images/service.py` generate_cut_image):

```
슬롯 조립 순서:
1. 캐릭터 정면 시트 (또는 실사 사진 최대 3장/인) — 무조건 먼저
2. remaining = 5 - len(시트) - 1(장소 예약)
3. 캐릭터 표정 시트 — remaining 범위 내, 초과 시 drop + warning log
4. 장소 이미지 — long/full 시만 (bust/close_up 텍스트만), 768px 다운스케일
5. 제품 시트 — has_product=True 시, 잔여 슬롯만, 초과 시 silent skip
```

**시나리오별 슬롯 배분:**

| 구성 | 시트 | 표정 | 장소 | 제품 | 합계 | 제품 상태 |
|---|---|---|---|---|---|---|
| 1인 | 1 | 1 | 1 | 1 | 4 | ◎ 참조+텍스트 |
| 2인 | 2 | 1 (2번째 drop) | 1 | 1 | 5 | ◎ 마지막 슬롯 |
| 2인 (표정 2) | 2 | 2 | 1 | 0 | 5 | ✗ 텍스트만 |
| 3인 | 3 | 1 | 1 | 0 | 5 | ✗ 텍스트만 |
| 실사 1인 | 3 | 0 | 1 | 1 | 5 | ◎ |
| 실사 2인 | 4~6 | 0 | 0~1 | 0 | 5 | ✗ |

**핵심:** 제품 시트 이미지가 탈락해도 `product_desc` 텍스트 프롬프트는 항상 주입됨. 2인 에피소드에서 제품 시트 시각 참조 없이 텍스트만으로 생성되는 것이 현재 약점.
