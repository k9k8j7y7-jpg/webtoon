# 지시서 P5 — 회차 대본 생성 (2-B) + 캐릭터 자동 연결

> **전제:** P4 완료. 결정서-연작설계-v5.md 확정 결정 1(2-B)·2(지연 생성)·
> 3(캐릭터 자동 연결) 구현. 아래 설계 결정 3건은 잠정 확정 —
> **사용자가 화면을 본 뒤 조정될 수 있음** (특히 결정 A).
> **작업 방식: 각 단계 종료 시 멈추고 보고 → 확인 후 진행.**
> 커밋은 사용자 확인 후. 파괴적 git 명령 금지.

---

## 0. 설계 결정 (잠정)

- **A. Gate 1 스킵:** 회차 에피소드는 Gate 1을 자동 승인 상태로 생성,
  Gate 2(대본)부터 시작. Gate 1 탭은 읽기 전용(바이블 파생 기획 표시)
- **B. 컨텍스트 선별 주입:** 바이블 전문이 아니라 —
  시놉시스 + 주요 인물 요약 + 세계관 1~2문장 + 해당 회차
  {title, summary, hook} + 직전 회차 {title, summary, hook}
  (1화는 직전 회차 없음 → 해당 블록 생략)
- **C. 시리즈 홈 관제탑:** 생성·진입·복귀 전부 시리즈 홈 기준.
  workflow 화면은 기존 그대로 재사용

## 1단계 — 조사 (수정 금지)

1. 에피소드 생성 API(POST /episodes)의 현재 파라미터와 생성 직후
   상태 (gate_status 구조, Gate 1 승인 처리 방식)
2. Gate 2 대본 생성 API의 입력 (기획 내용을 어디서 읽어오는지) —
   연작 컨텍스트를 끼워 넣을 지점 특정
3. workflow 화면의 "← 에피소드 목록" 복귀 로직 (시리즈 홈 복귀로
   분기할 지점)
4. P3의 episode_characters 연결 API 재확인 (자동 연결에 재사용)
보고 후 멈춤.

## 2단계 — 백엔드

1. **POST /series/{sid}/episodes/{no}/generate** — [대본 생성] 본체:
   a. outline[no]에 episode_id 있으면 409 (이미 생성됨)
   b. episodes 행 생성: series_id, episode_no, 제목=회차 title,
      Gate 1 자동 승인 + 기획 필드는 바이블에서 파생
      (logline=회차 summary 요약, synopsis=회차 summary,
      characters=바이블 인물 중 등장 예상 — 파생 규칙은 단순하게,
      과설계 금지)
   c. **직전 회차 캐릭터 자동 연결**: outline[no-1].episode_id가
      있으면 그 에피소드의 episode_characters를 현재 에피소드로
      복사 연결 (ref_key 충돌 검사 — P3 link 로직 재사용).
      1화 또는 직전 회차 미생성이면 생략
   d. Gate 2 대본 생성 job 시작 — 프롬프트에 결정 B의 컨텍스트
      선별 주입 (기존 대본 프롬프트 + 연작 컨텍스트 블록 추가.
      "이 화는 전체 이야기의 {no}/{total}화. 직전 화에서 {요약}.
      이번 화는 {summary}로 진행, 마지막 컷은 {hook}으로 마무리"
      구조)
   e. outline[no] 갱신: episode_id 기록, status="script_generating"
      → job 완료 시 "script_done"
2. **outline 상태 동기화**: GET /series/{sid} 응답의 outline에
   각 회차 에피소드의 실제 진행(대본 승인 여부, 이미지 유무)을
   집계해 내려주기 (시리즈 카드 "대본 N · 이미지 N" 숫자의 근거)
3. 방어 실효화: PUT outline / merge / split에서 episode_id 있는
   항목 보호 (P4에서 방어 코드만 있던 것이 이제 실제 작동 —
   에러 메시지: "대본이 생성된 회차는 아웃라인에서 수정할 수
   없습니다")
보고 후 멈춤.

## 3단계 — 프론트

1. **시리즈 홈**:
   - [대본 생성] 버튼 활성화 (비활성 예약 해제) → 확인 다이얼로그
     ("N화 대본을 생성합니다. 직전 회차의 캐릭터가 자동으로
     연결됩니다") → generate API → P4 진행 표시 패턴 재사용
     (카드 오버레이 + 잠금)
   - 완료 시 카드에 상태 뱃지 "대본 완료" + [열기] 버튼 →
     workflow로 이동 (Gate 2 탭에서 시작)
   - episode_id 있는 회차: ✏/병합/분할/🗑 비활성 + 안내 툴팁
     (2단계 3번의 프론트 짝)
2. **workflow 화면**:
   - 연작 회차(episodes.series_id 있음)면 복귀 링크 "← 시리즈 홈"
     + 상단에 "N/총화 · 시리즈명" 표시
   - Gate 1 탭: 읽기 전용 표시 (바이블 파생 기획 + "연작 회차는
     시리즈 기획을 따릅니다" 안내. 수정/재생성 버튼 숨김)
   - Gate 2 이후는 기존 그대로 (수정 금지)
3. 시리즈 카드: "대본 N · 이미지 N" 실숫자 연동 (2단계 2번)
보고 후 멈춤 (스크린샷 포함).

## 4단계 — 검증

1. 생성 플로우: 테스트 시리즈(새로 하나 생성)에서 1화 [대본 생성]
   → episodes 행 생성 + Gate 1 자동 승인 + 대본 생성 완료 +
   outline에 episode_id/status 기록 (API 수치)
2. **컨텍스트 주입 확인**: 생성된 프롬프트 로그에서 시놉시스/회차
   summary/hook 블록이 실제 포함됐는지 + 대본 마지막 씬이 hook
   방향인지 육안 1회
3. 2화 생성 → **직전 회차 캐릭터 자동 연결** 확인:
   1화 에피소드의 캐릭터가 2화에 연결돼 있는지 (episode_characters)
4. **이월 검증 — 스킵 배너 실발화**: 2화 Gate 3에서 캐릭터 자동
   생성 실행 → 자동 연결된 캐릭터(대본에 등장)가 스킵되고
   "N명 건너뜀" 배너 표시
5. 중복 생성 방어: 같은 회차 재차 generate → 409
6. 잠금 실효: 대본 생성된 회차에 merge/split/PUT 시도 → 거부
7. 1화 workflow 진입 → "← 시리즈 홈" 복귀 + Gate 1 읽기 전용 확인
8. 회귀: 단편 에피소드 생성·workflow 무변경
9. 시리즈 카드 숫자: "대본 2 · 이미지 0" 반영
검증용 테스트 시리즈는 마지막에 정리하되, 4번(스킵 배너)까지
확인 후. 보고 후 멈춤.

## 5단계 — 배포 + 사용자 테스트 + 커밋

- 배포 후 사용자 실사용: **"아빠 엄마에 우리 도도" 1화 실전 생성**이
  최종 테스트 (사용자 판단으로 진행)
- 특히 결정 A(Gate 1 스킵)의 화면 흐름이 자연스러운지 사용자 확인 —
  어색하면 조정 논의
- 확인 후 커밋:
  - `feat(series): 회차 대본 생성(2-B) + 컨텍스트 주입 + 캐릭터
    자동 연결 (P5)`
  - `docs: P5 지시서 보관 + PROGRESS 갱신`

## 범위 제한

- 상태 뱃지는 최소한만 (본격 상태 UI는 P6)
