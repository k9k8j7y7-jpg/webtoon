## 2. 이벤트 방식 — mouse + touch 분리, 드래그 판정

### 바인딩 패턴 (모든 드래그 대상 공통)
```jsx
// SVG 요소 (말풍선·효과음·효과·제품·PNG말풍선)
onMouseDown={e => handleXxxPointerDown(e, i)}
onTouchStart={e => { e.preventDefault(); handleXxxPointerDown(e, i); }}
```
- **Pointer Events API 미사용** — `onPointerDown` 아님, `mouse` + `touch` 분리 바인딩
- `handleXxxPointerDown` 안에서 `e.touches` 존재 여부로 touch/mouse 분기:
  ```js
  const clientX = e.touches ? e.touches[0].clientX : e.clientX;
  ```
- `onTouchStart`에서 `e.preventDefault()` 호출 → **스크롤 방지** (의도적)

### 전역 이벤트 리스너 (line 876-886)
```js
window.addEventListener('mousemove', handleMouseMove);
window.addEventListener('mouseup', handleMouseUp);
window.addEventListener('touchmove', handleTouchMove, { passive: false });
window.addEventListener('touchend', handleTouchEnd);
```
- `touchmove`는 `{ passive: false }` — `e.preventDefault()` 가능하게 설정됨
- `handleTouchMove`(line 823-833): `e.preventDefault()` 호출 후 6종 드래그/회전 적용

### 드래그 판정 임계값
```js
const DRAG_THRESHOLD = 5;  // line 120
```
- `Math.hypot(dx, dy) < 5px` 미만이면 이동 아닌 선택(클릭)으로 판정
- 5px은 PC에서 적절하나 **모바일 터치에서는 너무 낮음** — 손가락 흔들림으로 의도치 않은 미세 드래그 발생 가능
- 권장: 모바일은 10-15px

### 히트 영역 크기
- **말풍선**: SVG `<g>` 그룹 안 `<rect>` — 실제 말풍선 크기와 동일 (너비 `w*imgW`, 높이 `bubblePixelH`). 좁은 말풍선은 히트 영역이 작음
- **효과음**: `sfxHitBox()` 함수 (line 79-84) — `w = max(40, text.length * fontSize * 0.62) + 24`, `h = fontSize * 1.4`. 짧은 효과음("쾅!")은 ~64×34px → 모바일 터치에 작음
- **리사이즈 핸들**: 말풍선 우측 `<rect>` 4×bubbleH (line 1252) — **4px 너비**는 터치 불가
- **회전 핸들**: 효과·제품·PNG말풍선의 회전 원 `<circle r={7}>` (line 1332 등) — **14px 직경**, 터치에 작음 (최소 44px 권장)
- 선택 상태 테두리: 2px 점선 → 모바일에서 보이지만 조작 핸들이 너무 작음

## 3. 컷 영역·하단 패널 — touch-action, overflow, 높이

### 전체 레이아웃 (line 914-917)
```jsx
<div className="fixed inset-0 z-50 bg-black flex flex-col">
```
- `fixed inset-0` → 뷰포트 전체 차지
- `flex flex-col` → 상단 바 + 이미지 영역 + 하단 패널 수직 배치
- **100vh/dvh 명시 없음** — `inset-0`으로 처리 (iOS Safari에서 `100vh`보다 안전)

### 이미지 영역 (line 1016-1018)
```jsx
<div ref={containerRef}
  className="flex-1 flex items-center justify-center overflow-hidden min-h-0 relative"
  onClick={...}>
```
- `flex-1 min-h-0` — 남은 공간 전부 차지, 최소 높이 0 (축소 가능)
- `overflow-hidden` — 이미지/오버레이 넘침 잘림
- **touch-action 미설정** → 기본값 `auto` → 이미지 위에서 스크롤/핀치 가능
- 하지만 SVG `onTouchStart`에서 `e.preventDefault()` → 실질적으로 이미지 위 터치 스크롤 차단

### 하단 패널 (line 1440-1443)
```jsx
<div className="shrink-0 bg-zinc-900 border-t border-zinc-800 max-h-[40vh] overflow-y-auto"
  onClick={e => e.stopPropagation()}>
```
- `max-h-[40vh]` + `overflow-y-auto` → 40vh 초과 시 내부 스크롤
- `shrink-0` → flex에서 축소 안 됨

### 모바일에서 하단 패널 스크롤 안 되는 원인 후보

1. **전역 `touchmove` preventDefault**: line 823의 `handleTouchMove`가 `e.preventDefault()`를 **무조건** 호출. 드래그 ref가 하나라도 설정되어 있으면 해당 드래그 적용 후 preventDefault, 아무 ref도 없어도 함수 진입 시 무조건 호출 → **패널 안 터치 스크롤도 차단됨**
   ```js
   const handleTouchMove = useCallback((e) => {
     e.preventDefault();  // ← 항상 호출, 패널 스크롤 죽임
     const t = e.touches[0];
     if (dragRef.current) applyDrag(t.clientX, t.clientY);
     // ...
   }, [...]);
   ```
   **이것이 1순위 원인.** `window` 레벨에서 모든 touchmove를 preventDefault하므로 하단 패널의 overflow-y-auto 스크롤이 동작하지 않음.

2. **`e.stopPropagation()`만 있고 touchmove 분리 안 됨**: 패널 `div`에 `onClick={e => e.stopPropagation()}`은 있으나 touch 이벤트는 window 전역 리스너가 먼저 잡음

3. **iOS Safari 주소 바**: `max-h-[40vh]`의 `vh`가 주소 바 포함 높이 → 실제 가시 영역보다 큼 → 패널이 화면 밖으로 밀림. `dvh` 사용하면 해결

4. **슬라이더 (`<input type="range">`)**: 터치 드래그가 전역 touchmove에 잡혀 값 변경과 동시에 이미지 위 드래그가 발동할 수 있음
