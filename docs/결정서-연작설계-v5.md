## 확정 결정 1 — Gate 2 이층화

- **2-A 회차 아웃라인** (시리즈 레벨, 최초 1회 + 수시 편집):
  전체 줄거리를 N화로 분할 → 회차별 {제목, 한 줄 요약, 엔딩 훅}.
  사용자: 추가/병합/분할/순서변경/요약수정. 상세 대본 없음.
- **2-B 회차 대본** (회차 레벨, 회차마다 반복):
  아웃라인에서 회차 선택 → 그 회차만 씬/컷 대본 생성.
  컨텍스트 주입: 시리즈 바이블 + 해당 회차 요약·훅 + 직전 회차 요약.
  이야기 전개 선택 버튼은 여기(회차별로 다르게).
- 2-A는 별도 게이트가 아니라 **시리즈의 홈 화면**. "다음 회차 만들기"의
  복귀 지점.

## 확정 결정 2 — 데이터 구조

```
projects (그대로)
 ├─ series (신규): id, project_id, title,
 │     bible JSON(시놉시스·세계관·캐릭터요약),
 │     outline JSON(회차 배열 [{no,title,summary,hook,episode_id|null,status}])
 └─ episodes (+2 컬럼): series_id nullable FK, episode_no nullable
characters (소속 변경): episode_id → project_id, + user_id nullable(라이브러리)
episode_characters (신규): episode_id, character_id
```

- series_id NULL = 단편. **기존 에피소드 마이그레이션 불필요.**
- outline의 episode_id는 처음 null — 2-B 진입 시점에 episodes 행 생성
  (지연 생성의 데이터 표현).
- 회차 에피소드는 Gate 2-B 이후 **기존 Gate 3~5를 그대로** 탄다.

## 확정 결정 3 — 캐릭터 자산화 (2계층)

- **프로젝트 레벨(기본):** 생성 즉시 프로젝트 소속(자동 자산화, 저장 버튼
  없음). Gate 3에서 [프로젝트 캐릭터 불러오기] = 연결(생성 비용 0, 같은
  참조 이미지 = 같은 얼굴). 시트에서 삭제/숨김으로 정리.
- **사용자 레벨(승격):** 시트의 "내 라이브러리 등록"(별표) → 모든
  프로젝트 피커에 [내 캐릭터] 섹션으로 표시. 시그니처 캐릭터 대응.
- 다른 프로젝트 캐릭터 직접 사용은 불가(프로젝트 = 세계관 벽).
  라이브러리 승격이 그 통로. "복제 후 개명"은 1차 범위 밖(추후 복제 버튼).
- 공유 캐릭터 재생성 시 경고: "N개 에피소드 사용 중, 새 이미지는 이후
  생성부터 적용". 기존 컷 이미지 불변.
- 연작: N화 에피소드 생성 시 직전 회차 연결 캐릭터 자동 연결.
- 마이그레이션: 기존 캐릭터에 소속 에피소드의 project_id 부여 +
  episode_characters 1행씩. 이미지/이름 무변경. 동명 중복은 병합하지
  않고 사용자가 시트에서 정리.

## 확정 결정 4 — 3단계 상태와 잠금·합치기

| 상태 | 편집 | 합치기/분할 |
|---|---|---|
| 아웃라인 (episode_id null) | 자유 (JSON 편집, 비용 0) | 자유 |
| 대본 완료 | 국소 수정(대사 등)은 대본 편집 | **아웃라인 병합 → 대본 재생성** (기존 대본 대체 확인 다이얼로그, 비용 = 대본 생성 1회) |
| 이미지 완료 | 대본 수정 불가 | 불가 (버튼 비활성 + 안내) |

- 원칙: **구조 변경은 재생성, 디테일은 편집.** 대본 기계적 이어붙이기 금지
  (컷 배분·훅 위치가 깨짐).
- 병합 시 뒤 회차 번호 리넘버링. 엔딩 훅은 뒤 회차 것 승계.

## 확정 결정 5 — 입구/리스트 UI

- 프로젝트 화면 버튼 2개: `+ 단편 에피소드` / `+ 연작 시리즈`
- 리스트 혼재: 단편 카드(게이트 기준 표시 유지) / 시리즈 카드 1장
  (`[연작]` 뱃지 + `3/12화 완성 · 4화 진행 중` 회차 기준 표시)
- 시리즈 카드 클릭 → 2-A 아웃라인 화면(시리즈 홈)

## 확정 결정 6 — 단편 입력 UI (P1 범위)

- 예시 칩 8개(탭하면 입력칸 채움, 로테이션), "주인공+상황+감정 한 줄" 구조
- 3축 단일선택: 장르 6 / 분위기 5 / 이야기 전개 7
  (잔잔하게·극적으로·반전 있게·초반 후킹·성장 역전·미스터리 떡밥·클리프행어)
- 전부 선택 안 함 허용(미선택 시 AI 추론 = 현행 동작)
- 칩-버튼 연동(예시 탭 시 어울리는 축 자동 선택)
- 각 전개 옵션은 기획 프롬프트에 **컷 배분 지시 문장 조각**으로 주입
  (예: 초반 후킹 = "1~2컷에 최강 사건, 3컷부터 경위")
- 연작 입력에는 전개 축 없음(회차별 2-B로 이동). 장르/분위기는 동일

## 구현 순서 (확정)

| 단계 | 내용 | 성격 |
|---|---|---|
| P1 | 단편 입력 UI (칩+3축+프롬프트 주입) | 독립, 즉시 가치 |
| P2 | DB 공사 (series, 캐릭터 이전, 마이그레이션) | 화면 무변화. DB 백업 필수, "기존 에피소드 무변경" 수치 판정 |
| P3 | 캐릭터 라이브러리 (Gate 3 피커 2단, 승격) | 단편에서도 가치 |
| P4 | 연작 입구 + Gate 1 + 2-A 아웃라인 | 비용 0 영역, UX 실사용 후 다듬기 |
| P5 | 2-B 대본 + 컨텍스트 주입 + 캐릭터 자동 연결 | 연작 1화 최초 완주 |
| P6 | 상태 표시·잠금·합치기 마무리 | |
