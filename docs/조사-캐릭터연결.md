# 조사 — 캐릭터 연결 버그 2건 (2026-10-01)

## 발견 경위
"형식 테스트"(ep38)에서 컷 #3·#5의 `character_id: kim_jeong_shin`이 연결된 캐릭터
`ref_key: mother`와 매칭되지 않아 시트 참조 미첨부 확인.

---

## 버그 1 — 기획(Gate1)에서 동물 캐릭터 누락

### 현상
ep38 `idea_brief.characters`에 도도(갈색 포메라니언)·김정신 **둘 다** 있으나,
`planning.characters`에는 김정신만 생성됨 → 대본도 `kim_jeong_shin`만 참조.

### 비교: ep36 "장소 테스트2"
ep36 `idea_brief.characters`에도 도도·카페 주인·하준 3명 → `planning.characters`에
도도(`dodo`)·카페 주인(`cafeOwner`)·하준(`hajun`) **3명 모두 생성됨**.

### 원인 분석
- **코드 필터링은 없다.** `generate_planning()` (`story/service.py:97-188`)은 idea_brief
  전체를 프롬프트에 주입하고, 동물을 제외하는 조건문이 없음.
- 프롬프트 지시: "기획서의 인물·사건·결말을 그대로 따를 것. 기획서에 없는 새 인물을
  추가하지 말 것(단역 제외)." (`story/service.py:145`)
- idea_brief 생성 프롬프트에도 "동물이 등장하면 반드시 characters에 포함"
  (`story/service.py:40, 222`) 명시.
- **결론: AI의 비결정적 행동.** ep36에서는 도도가 주인공이라 AI가 포함했고,
  ep38에서는 도도가 보조라 AI가 임의로 탈락시킨 것. 코드 버그가 아니라 프롬프트
  준수 실패(LLM 환각).

### 추가 문제: ref_key 불일치
ep38에서 AI가 김정신의 ref_key를 `kim_jeong_shin`으로 생성.
그 후 사용자가 "캐릭터 불러오기"로 다른 에피소드의 `mother` 캐릭터를 연결 →
대본의 `kim_jeong_shin` ≠ 캐릭터 DB의 `mother` → 시트 참조 미첨부.

## 버그 2 — 캐릭터 불러오기 시 ref_key 매핑 부재

### 코드 위치
`characters/router.py:423-468` — `POST /characters/link`

### 동작
1. 원본 캐릭터의 `ref_key`를 **그대로 유지**한 채 에피소드에 연결
2. ref_key 중복만 검사(409), 대본의 character_id와 매핑하는 단계 없음
3. 결과: 대본이 `kim_jeong_shin`을 참조하는데 연결된 캐릭터는 `mother`
   → Gate5 ⚠ 경고만 표시, 이미지 생성 시 시트 미첨부

### 연작은 어떻게 맞추는가
- 바이블이 ref_key를 확정 (`series/router.py:929-946`, `_derive_planning_from_bible()`)
- 바이블 characters가 planning.characters로 **그대로 복제** (ref_key 불변)
- 대본 생성 시 "ref_key를 그대로 사용. 새 키를 만들지 말 것" 지시
  (`script/prompt_fragments.py:103`)
- 캐릭터 시트 생성도 같은 ref_key 사용 → **자연스럽게 일치**
- 단편에서는 이 흐름이 깨짐: planning AI가 ref_key를 새로 생성하고,
  다른 에피소드 캐릭터를 불러오면 원본 ref_key와 충돌

## 버그 3 — 콘티 생성(Gate4) 캐릭터 가드 없음

### 코드 위치
- 장소 가드: `storyboard/router.py:84-105` — 대본의 `location_id` 중 DB 미등록 있으면
  **400 에러** + 누락 목록 표시
- 캐릭터 가드: **없음.** 대본의 `character_id`와 에피소드 캐릭터를 대조하는 코드
  자체가 Gate4에 존재하지 않음
- Gate5 프론트(`Gate5Review.jsx:524-527`)에서 `isUnknownChar()` → **⚠ 표시만**

### 비대칭 이유 (추정)
장소는 Gate4("콘티&장소")에서 함께 관리하므로 누락 시 즉시 차단이 자연스럽지만,
캐릭터는 Gate3에서 관리하므로 Gate4 시점에 유연성을 둔 설계. 다만 결과적으로
캐릭터 누락이 이미지 품질 저하(시트 미참조)로 이어지므로 경고 이상이 필요함.

## 해결안

### a) 기획에서 idea_brief.characters를 planning 기본으로 승계 (동물 포함)

**목적:** AI가 동물을 누락하는 문제 근본 해결

**방법:** `generate_planning()` 프롬프트 보강 — idea_brief.characters 각각에 대해
"이 인물은 반드시 planning.characters에 포함할 것 (동물 포함)" 명시.
또는 AI 응답 후처리로 idea_brief.characters 중 planning에 빠진 인물을 자동 추가
(ref_key는 이름 기반 자동 생성).

**수정 파일:**
- `backend/app/story/service.py` — `generate_planning()` 프롬프트 또는 후처리
- 추정 30줄 이내

### b) 불러오기 시 "대본의 어느 인물로?" 매핑 드롭다운 + ref_key 덮어쓰기

**목적:** 기존 캐릭터를 다른 에피소드에 불러올 때 대본 ref_key와 매핑

**방법:**
1. 프론트: 불러오기 클릭 시 대본의 character_id 목록 표시 →
   "이 캐릭터를 대본의 어느 인물로 사용할까요?" 드롭다운
2. 백엔드: link API에 `override_ref_key` 파라미터 추가 →
   에피소드 범위에서 해당 캐릭터의 ref_key를 덮어쓰기
   (원본 캐릭터 레코드 불변, EpisodeCharacter에 override 컬럼 또는
    에피소드 전용 캐릭터 복제)

**수정 파일:**
- `backend/app/characters/router.py` — link 엔드포인트에 매핑 로직
- `backend/app/characters/models.py` — EpisodeCharacter에 `ref_key_override` 컬럼 또는
  캐릭터 복제 로직
- `backend/app/images/service.py` — `_get_character_references()`에서 override 조회
- `frontend/src/components/gates/Gate3Assets.jsx` — 피커 모달에 매핑 UI
- 마이그레이션 stepN.sql 필요 (EpisodeCharacter 컬럼 추가 시)
- 추정 150줄+

### c) 콘티 생성 가드 400

**목적:** 대본 character_id 중 에피소드 미연결 캐릭터가 있으면 콘티 생성 차단

**방법:** `create_storyboard()` (`storyboard/router.py`)에서 장소 가드와 동일 패턴으로
대본의 character_id 집합 vs DB episode_characters ref_key 집합 비교, 차집합 → 400.

**수정 파일:**
- `backend/app/storyboard/router.py` — `create_storyboard()` 내 장소 가드 아래에
  캐릭터 가드 추가
- 추정 15줄

**주의:** 단독 적용 시 기존 에피소드에서 캐릭터 불일치가 있으면 콘티 재생성 불가.
해결안 a) 또는 b)와 함께 적용해야 안전.
