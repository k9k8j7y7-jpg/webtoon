# 조사: 구독·알림·댓글·웹푸시

> 2026-10-09 조사 완료 — 코드 수정 없음. 지시서 `docs/지시서-구독알림.md` 0단계 결과

## 0. 결론 먼저 (지시서 보정 필요 3건)

1. **공개(showcase)는 지금 관리자 전용.** `POST /admin/episodes/{id}/showcase`(require_admin)뿐이고 작가 본인이 공개하는 API·UI가 없다. → "작가가 공개하면 구독자 알림"을 하려면 **작가용 공개 토글이 1단계에 추가로 필요**(아래 §2-3 제안). 안 만들면 알림 트리거가 "관리자가 노출할 때"가 됨
2. **`/@닉네임` 경로는 React Router 7에서 부분 동적 세그먼트(`/@:nick`) 미지원.** → `/u/:nickname` 권장(또는 `/:handle`에서 `@` 접두 검사 — 다른 라우트와 충돌 위험). 서비스 경로는 `/WEBTOON/u/닉네임`
3. **sw.js는 루트(`/sw.js`) 불필요.** 앱 전체가 `/WEBTOON/` 아래라 `/WEBTOON/sw.js` 기본 scope `/WEBTOON/`로 충분. Apache 수정 없음

## 1. users — 프로필

| 항목 | 현황 |
|---|---|
| 컬럼 | `id, provider, provider_uid, email, display_name(100), created_at, is_admin, updated_at` |
| 닉네임 | 없음 (`display_name`은 OAuth 실명/닉네임) |
| 소개·아바타 | 없음 |
| OAuth 이름 | 구글 `name`, 카카오 `profile.nickname`, 네이버 `name or nickname` → `display_name`. **로그인마다 덮어씀**(`auth/router.py:64`) |
| OAuth 사진 | 받지 않음(구글 `picture`, 카카오 `profile_image_url`, 네이버 `profile_image` 존재하나 미수집) |
| `/me` | `users/router.py` — id·display_name·email·provider·is_admin |

- 제안: `nickname`을 **별도 컬럼**(공개용, 사용자 지정). `display_name`은 실명일 수 있어 공개 노출 금지. 닉네임 미설정 작가는 공개 화면에 "작가" 등 익명 폴백
- 닉네임 초기값 제안: 비워 두고 첫 로그인 배너로 설정 유도(실명 자동 공개 위험 회피)
- 중복 체크: `UNIQUE(nickname)` + PUT 시 사전 조회 → 400. 대소문자·공백 정규화(trim, 2~20자, 한글·영문·숫자·_)
- 아바타: `storage.upload_image()` + `image_util.validate_and_process()` 재사용(캐릭터·문의 첨부와 동일). 경로 `avatars/{user_id}/{uuid}.jpg`, 정사각 256~512px 리사이즈. OAuth 사진 가져오기는 2차

## 2. 공개 구조 (showcase)

- **에피소드 단위**: `episodes.showcase(bool)`, `showcase_category(short/series/ad)`, `share_token(UUID)`, `view_count`, `like_count` (step20·21)
- 소유: `Episode.project_id → projects.user_id`. 작가 단위 목록 쿼리 가능:
  `Episode JOIN Project WHERE Project.user_id=:uid AND Episode.showcase=1 AND Episode.deleted_at IS NULL AND Project.deleted_at IS NULL`
  (인덱스: episodes.project_id 있음. 규모상 문제 없음)
- 공개 시각 컬럼 없음 → 새 화 피드 정렬용 `episodes.published_at DATETIME NULL` 추가 제안(step30)
- 갤러리 `GET /showcase/episodes`: share_token·title·genre·thumbnail·view·like만. **작가 정보 없음**
- 뷰어 `GET /showcase/view/{token}`: title·episode_no·page_format·cuts·products. **작가 정보 없음**. `ViewerPage`는 Layout 밖(헤더·🔔 없음)
- 응답에 `author: {nickname, avatar_url}` 추가 필요(user_id 노출 대신 nickname 사용 권장)

### 2-3. 작가 공개 토글 (지시서 보정 제안)
- `POST /episodes/{id}/publish` `{published: bool}` — 소유자만, 게이트5 이미지 1장 이상일 때만. share_token 자동 생성, 카테고리는 is_ad/series_id로 자동(관리자 로직 재사용)
- 관리자 노출 토글은 그대로 두되 "랜딩 추천(featured)"과 "공개(published)"를 분리할지 결정 필요:
  - **안 A(권장)**: `showcase` = 작가 공개(작가 페이지·구독 알림·공유 뷰어) / 신규 `featured` = 관리자가 랜딩 갤러리에 노출. 갤러리 쿼리는 `featured=1`로 변경
  - 안 B: showcase 하나로 유지 → 작가가 공개하면 바로 랜딩 갤러리에 뜸(검수 없음 위험)
- 알림 트리거: showcase false→true **최초 전환 시 1회**(`published_at IS NULL`일 때만 → 껐다 켜기 반복 알림 방지)

## 3. 좋아요·조회수 (댓글 설계 참고)

- `showcase_likes(episode_id, fingerprint(64), created_at, UNIQUE(episode_id, fingerprint), FK episodes)` — **비회원 fingerprint(IP+UA 해시)** 기반, user_id 없음
- `episodes.like_count / view_count` 비정규화 카운터 + 원자 UPDATE
- 조회수 중복 방지는 인메모리 dict(24h, 재시작 시 초기화)
- 지시서 "좋아요는 회원" 원칙과 다름 → 이번 범위에서 바꾸지 않음(회귀 위험). 2차에서 user_id 컬럼 추가 검토
- 댓글은 이 패턴 차용: `episodes.comment_count` 비정규화 + comments 테이블, FK episodes, utf8mb4

## 4. 문의 🔔 unread-count → 알림센터 통합

- 현재: `GET /inquiries/unread-count` = `answered_at IS NOT NULL AND (user_read_at IS NULL OR user_read_at < answered_at)` 건수. `Layout.jsx:37`에서 폴링, 헤더 배지(`Layout.jsx:124`)
- 답변 지점: `inquiries/router.py:236~238` (사용자 메시지 API에서 is_admin일 때 answered_at 갱신) + `:347` 상태 변경
- 통합 방법:
  1. `notify(db, user_id, type='inquiry_answer', title, body, link='/inquiries/{id}')`를 `:238` 직후 호출(같은 트랜잭션)
  2. 헤더 🔔은 `GET /notifications/unread-count` 하나만 폴링. 문의 배지 제거
  3. 문의 상세 열람 시(`:198` user_read_at 갱신) 해당 link의 inquiry_answer 알림도 읽음 처리 — 두 읽음 상태 동기화
  4. `/inquiries/unread-count`는 문의 목록 화면 내 표시용으로 유지(삭제 안 함)
- 과거 답변분은 마이그레이션으로 알림 백필하지 않음(운영 DML 회피)

## 5. 비동기 (알림 생성·푸시 발송)

- `jobs.py`: 사용자가 진행률을 폴링하는 **인메모리 Job** 용도(create_job → run_job_in_background, 새 이벤트 루프). 알림에는 과함
- 제안:
  - **알림 행 생성**: 동기 `notify()` / 팬아웃은 `notify_many()` — `INSERT ... SELECT follower_id FROM subscriptions WHERE author_id=:a` 단일 bulk insert. 구독자 수천 명까지 수십 ms → 요청 안에서 처리해도 됨
  - **웹푸시 발송**(3단계): FastAPI `BackgroundTasks.add_task(send_push_batch, notification_ids)` — 요청 세션은 닫히므로 함수 안에서 `SessionLocal()` 새로 열기. pywebpush는 동기 HTTP → 스레드풀에서 실행되어 이벤트 루프 안 막음. 410/404 endpoint 삭제
  - jobs.py는 재사용 불필요(진행률 UI 없음). 재시작 시 미발송 푸시 유실은 허용(알림 행은 DB에 남음)
- 배포 주의: `--reload` 중 생성 작업 규칙은 동일 적용

## 6. PWA 조건

| 항목 | 현황 |
|---|---|
| HTTPS | OK (ssagda.com) |
| manifest | 없음 |
| service worker | 없음 |
| 아이콘 | `public/favicon.svg`·`icons.svg`만. **192/512 PNG(+maskable) 필요**, apple-touch-icon 180 |
| Vite PWA 플러그인 | 미설치. vite ^8.2 — vite-plugin-pwa 호환 확인 필요 |
| 정적 서빙 | Apache `/WEBTOON/` → uvicorn, `main.py:84` SPA fallback이 `frontend/dist/{path}` 파일이 있으면 그대로 서빙 → `public/sw.js`·`manifest.webmanifest`는 빌드 시 dist로 복사되어 `/WEBTOON/sw.js`로 응답됨 |
| scope | `/WEBTOON/sw.js` 등록 → 기본 scope `/WEBTOON/`. 앱 전체 커버. `Service-Worker-Allowed` 헤더 불필요 |
| MIME | Starlette FileResponse가 .js → `text/javascript`, `.webmanifest`는 mimetypes 미등록일 수 있음 → `manifest.json` 이름 사용 권장 |
| 캐시 | sw.js는 `Cache-Control: no-cache` 권장(현재 FileResponse 기본 헤더만) — 3단계에서 fallback에 sw.js 예외 한 줄 |

- 권장: **수동 sw.js + manifest.json**(푸시 수신·notificationclick만, fetch 캐시 없음). 플러그인은 precache가 배포 갱신과 꼬일 위험 + 의존성 추가 대비 이득 적음
- iOS: 16.4+에서 **홈 화면 추가(standalone)일 때만** 웹푸시. `display: standalone`, `start_url: /WEBTOON/`, `scope: /WEBTOON/`
- pywebpush 미설치(cryptography는 있음). VAPID 키는 서버 `.env`에 줄 추가(덮어쓰기 금지 규칙)

### step30 — 프로필·구독·알림 (+공개)
```sql
ALTER TABLE users
  ADD COLUMN nickname VARCHAR(20) NULL,
  ADD COLUMN bio VARCHAR(100) NULL,
  ADD COLUMN avatar_path VARCHAR(500) NULL,
  ADD UNIQUE KEY uk_users_nickname (nickname);   -- NULL 다수 허용

  id BIGINT AUTO_INCREMENT PRIMARY KEY,

  UNIQUE KEY uk_sub (follower_id, author_id),
  KEY idx_sub_author (author_id),

CREATE TABLE notifications (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,

  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_noti_user_read (user_id, is_read, created_at),
  CONSTRAINT fk_noti_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### step31 — 댓글·신고·차단
```sql

  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  episode_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  parent_id BIGINT NULL,            -- 1단계 깊이: 답글의 parent는 항상 최상위 댓글(앱 검증)
```
