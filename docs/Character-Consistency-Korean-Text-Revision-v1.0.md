> **범위:** 게이트 5 컷 이미지 생성의 캐릭터 일관성 강화 + 그림 속 한글 텍스트 처리.
> **중요도:** ★최상위. 캐릭터 일관성은 이 제품의 핵심 해자. 이것이 깨지면 웹툰이 성립하지 않는다.

## 배경 및 근본 원인

**증상:** 같은 캐릭터(예: jun_kim)가 컷마다 다른 사람(나이·얼굴·머리색)으로 생성됨.

**진단된 근본 원인:** 캐릭터 시트 이미지를 Gemini에 **주입은 하지만**, "이 이미지가 이 캐릭터다"라는 **앵커링(연결 지시)이 없음.** Gemini가 레퍼런스 이미지를 "그냥 참고"로만 보고, 텍스트 설명("30대 남성")으로 매번 새로 상상해 그림.

**추가 문제:**
- 이미지-캐릭터 매핑 없음 (레퍼런스를 그냥 나열)
- 프롬프트 순서가 스타일 우선 → Gemini가 스타일 맞추다 얼굴 변경
- 그림 속 한글 텍스트 깨짐 (예: "투자"→"붕자", "지금"→"지굼")

# A. 캐릭터 일관성 강화 (메인) ★

Nano Banana 2는 멀티 레퍼런스로 캐릭터 일관성을 유지하는 능력이 있으나(캐릭터 4명+오브젝트 14개), **명시적 앵커링 지시가 있어야** 제대로 작동한다.

## A-1. 이미지-캐릭터 매핑 명시

레퍼런스 이미지를 넣을 때, 각 이미지가 어떤 캐릭터인지 라벨링한다.

- 현재: 레퍼런스 이미지를 그냥 나열 → Gemini가 뭐가 뭔지 모름.
- 변경: 각 이미지 앞/뒤에 "이 이미지는 [캐릭터명]" 명시.
  ```
  [Image 1] → "Image 1 is the reference for the character 'jun_kim'."
  [Image 2] → "Image 2 is the reference for the character 'jeongsin_kim'."
  ```

## A-2. 강한 앵커링 지시 (영어)

레퍼런스 이미지의 얼굴·외모를 **정확히 유지**하라는 강한 지시를 추가. **제어 지시는 영어로** (이미지 모델이 영어 지시에 더 안정적).

- 예시 (강한 앵커링):
  ```
  CRITICAL: The characters in this image MUST exactly match the provided
  reference images. Replicate their facial features, hairstyle, hair color,
  age, and body type precisely. Only change their expression and pose to fit
  the scene. NEVER alter the character's facial identity or appearance.
  Image 1 = jun_kim, Image 2 = jeongsin_kim.
  ```
- 얼굴 정체성은 절대 바꾸지 말고, **표정·포즈만** 상황에 맞게 변경하도록 명시.

## A-3. 프롬프트 순서 재조정 — 캐릭터 우선

- 현재 순서: 스타일 → 샷타입 → 장소 → 캐릭터 → 액션 → 강조
- 문제: 스타일이 맨 앞이라 Gemini가 스타일에 맞추다 얼굴을 바꿈.
- 변경: **캐릭터 앵커링(A-2)을 최우선**으로. 얼굴을 먼저 고정하고 스타일은 그 위에 입히는 순서.
  ```
  권장 순서:
  1. 캐릭터 앵커링 지시 (이 얼굴을 유지하라) ← 최우선
  2. 캐릭터별 표정·포즈 (emotion/pose)
  3. 장소·상황 (location/action)
  4. 스타일 (화풍은 얼굴 정체성을 덮지 않는 선에서 적용)
  5. 샷타입·강조
  ```
- **스타일이 캐릭터 얼굴을 덮어쓰지 않도록** 스타일 지시를 "화풍/채색에만 적용, 인물 정체성은 레퍼런스 유지"로 제한.

## A-4. 다인 컷 처리

- 여러 캐릭터가 등장하는 컷은 각 인물의 레퍼런스를 모두 주입하고, 이미지-캐릭터 매핑(A-1)으로 구분.
  ```
  "Image 1 = jun_kim, Image 2 = jeongsin_kim.
   Draw both characters maintaining their exact appearances from the references."
  ```
- Nano Banana 2의 다중 캐릭터 일관성 능력(4명까지) 활용.

## A-5. 레퍼런스 선택

- 기본: 각 캐릭터의 `type='front'`(정면) 시트를 레퍼런스로 주입(현행 유지).
- 가능하면 표정 시트도 함께 주입해 표정 변화 시 정체성 유지 강화(선택).

## A-6. 남는 실패는 재생성으로

- 강한 앵커링으로 대부분의 컷이 일관되게 나오게 하되(1차 방어), 이미지 생성의 확률적 특성상 소수는 여전히 흔들릴 수 있음.
- 흔들린 컷은 **부분 재생성**(`POST /cuts/{cut_id}/regenerate`, 기존 기능)으로 다시 뽑음(2차 방어).
- "주입 강화로 실패율을 낮추고, 남는 소수는 재생성" 구조.

# B. 그림 속 한글 텍스트 처리 (절충)

> 말풍선/대사(코드로 얹는 텍스트)는 Gate4-5 지시서(말풍선 조판)에서 처리. 여기서는 **그림 속에 그려지는 한글**(신문·화면·간판 등)을 다룬다.

## B-1. 절충 원칙

| 텍스트 종류 | 처리 |
|---|---|
| **긴 문장** (신문 기사 제목, 화면 문구 등) | 그림 속에 **그리지 않음**. "경제면 신문", "주식 앱 화면"처럼 텍스트 없이 묘사. 정보가 꼭 필요하면 나레이션/말풍선으로 뺌 |
| **짧은 핵심 단어** ("폭락", "매수", "급등" 등) | 그림 속에 두되(연출 임팩트), 정확한 문구 + 한글 명시. 깨지면 재생성 |
| **읽혀야 하는 정보성 텍스트** | 그림 속에 억지로 넣지 말고 나레이션/말풍선으로 유도 |

## B-2. 프롬프트 처리

- **긴 텍스트 억제:** 컷 프롬프트에서 긴 한글 문구를 그림에 넣으라는 지시를 제거. 대신 사물로만 묘사.
  ```
  나쁜 예: "신문에 '노후 대비 투자 위기법'이라고 쓰여 있다"
  좋은 예: "김준이 경제면 신문을 읽고 있다" (구체 문구는 그리지 않음)
  ```
- **짧은 단어는 정확히 명시:** 꼭 필요한 짧은 단어는 정확한 글자 + 한글임을 명시.
  ```
  "화면에 붉은 글씨로 '폭락' (Korean word for crash)이 크게 표시된다"
  ```

## B-3. 정보성 텍스트를 말풍선/나레이션으로 유도

- 콘티(게이트4) 생성 시, 그림 속 텍스트로 표현하려던 정보(광고 문구, 기사 내용 등)를 가능하면 **나레이션이나 대사로 전환**하도록 유도.
- 이러면 코드로 얹는 텍스트가 되어 깨지지 않음(말풍선 조판 활용).

## B-4. 남는 깨짐은 재생성

- 그림 속 짧은 단어가 깨지면 부분 재생성으로 보완(A-6과 동일 방식).

---

## 우선순위

1. **A (캐릭터 일관성)** — 최우선. 제품의 심장. A-1(매핑)+A-2(앵커링)+A-3(순서)이 핵심.
2. **B (한글 텍스트)** — A와 함께 또는 직후.

> A를 먼저 적용하고 소수 컷(2~3컷)으로 캐릭터가 일관되게 나오는지 확인한 뒤 B 적용 권장.

---

## 검증

1. **소수 컷(2~3컷)** 생성 → 같은 캐릭터가 컷 간 동일 인물로 보이는지 확인 (얼굴·나이·머리색).
2. **다인 컷** 생성 → 여러 캐릭터가 각자 정체성 유지하는지.
3. **긴 대본(40컷)** 생성 → 전체적으로 캐릭터 일관성이 유지되는지, 흔들린 컷 비율이 크게 줄었는지.
4. 그림 속 긴 한글 텍스트가 사라지고, 짧은 단어만 남는지.
5. 남는 흔들림/깨짐은 부분 재생성으로 보완되는지.
