# 지시서 — 구독·알림·댓글 (작가 프로필 → 구독 → 🔔 → 댓글 → 웹푸시 PWA)

> 원칙: 단계마다 멈추고 보고. 커밋은 도도 확인 후. 마이그레이션은
> 리허설 → 백업 → 도도 "실행해" → 적용 → 그 다음 배포. 배포 전 생성
> 작업 없는 것 확인. 패킷 소모 없음(전부 텍스트·UI).
> 근거: docs/조사-구독알림.md (0단계 결과로 세부 보정)
> [근거] 도도 아이디어(당근 참고) — 마음에 든 작가를 구독하면 새 웹툰이
> 올라올 때 폰으로 알림, 작가와 구독자가 댓글·답글로 소통.
> [근거] 도도 결정 — 알림은 앱 대신 **웹푸시 + PWA**(스토어 심사 없음,
> 코드 재사용). 이메일·알림톡은 나중. 열람은 공개 유지, 구독·댓글·
> 좋아요는 회원(Claude 제안, 도도 동의).
> [근거] Claude 제안 — 구독 단위는 **작가**(시리즈별은 2차), 답글은 1단계
> 깊이, 신고·차단은 처음부터.

## 목표 (도도가 화면에서 보게 되는 것)
- **작가 프로필**: 설정에서 닉네임(필수·중복 불가)·한 줄 소개·프로필
  이미지. `/@닉네임` 페이지 = 소개 + 공개 작품 목록 + 구독자 수(1명
  이상일 때만) + [구독] 버튼. 갤러리·뷰어의 작가 이름이 이 페이지로 링크
- **구독**: 뷰어 상단·작가 페이지에 [구독]/[구독 중]. 비회원이 누르면
  로그인 유도(login_redirect로 복귀). 헤더 드로어에 "내 구독" — 구독
  작가 목록 + 새 화 피드(최신순)
- **🔔 알림센터**: 헤더 🔔 클릭 → 목록(새 화·댓글·답글·문의 답변),
  안 읽은 건 빨간 점 + 숫자. 항목 클릭 → 해당 페이지 + 읽음. 문의
  🔔(unread-count)는 이 알림센터로 흡수
- **새 화 알림**: 작가가 에피소드를 공개하면(showcase on) 구독자 전원에게
  "OO 작가의 새 웹툰 '제목'" 알림 자동 생성. 작가가 따로 할 일 없음
- **댓글**: 뷰어 하단 댓글 영역 — 댓글 + 답글(1단계), 작성자 닉네임·
  시각, 작가 댓글엔 "작가" 배지. 본인 삭제, 작가는 내 작품 댓글 삭제·
  사용자 차단, 누구나 신고. 신고는 /admin 탭에서 처리
- **웹푸시**: 알림센터 상단 "폰으로 알림 받기" 토글 → 브라우저 허용 →
  이후 새 화·답글이 폰 알림창에. 아이폰은 "공유 → 홈 화면에 추가" 안내
  카드. 설정에서 알림 종류별 on/off

## 0단계 — 조사 (코드 수정 없음) → docs/조사-구독알림.md
- users 테이블: 닉네임·소개·프로필 이미지 컬럼 유무, OAuth 3사 프로필
  이름 활용 가능 여부, 닉네임 중복 체크 자리
- 공개 구조: showcase 플래그가 에피소드 단위인지, 작가 단위 목록
  쿼리(user_id → 공개 에피소드) 가능한지, 뷰어 /view 경로·갤러리 카드에
  작가 정보 노출 여부
- 좋아요·조회수 테이블 구조(댓글 테이블 설계 참고)
- 문의 🔔 unread-count 구현(알림센터로 통합 방법)
- 서버: 비동기 작업(알림 생성·푸시 발송)을 어디서 돌릴지 — 기존
  jobs.py run_job_in_background 재사용 가능한지
- PWA 조건: https OK, manifest.json·service worker·아이콘 유무, Vite PWA
  플러그인 쓸지, Apache가 /sw.js를 루트에서 서빙 가능한지(scope)
- 테이블 초안: subscriptions(follower_id, author_id, created_at, UNIQUE),
  notifications(user_id, type, title, body, link, is_read, created_at,
  idx user_id+is_read), comments(episode_id, user_id, parent_id NULL,
  body, status, created_at), comment_reports(comment_id, reporter_id,
  reason), user_blocks(author_id, blocked_user_id), push_subscriptions
  (user_id, endpoint, p256dh, auth, user_agent, created_at). 전부
  step30·31·32로 단계별 분리
- 규모·단계 나누기 제안. 요약 10줄만 채팅에

## 1단계 — 작가 프로필 + 구독 + 알림센터
- step30: users에 nickname(UNIQUE)·bio·avatar_path, subscriptions,
  notifications. 리허설 → 백업 → "실행해" → 적용 → 배포
- 백엔드: PUT /me/profile(닉네임 중복 400), GET /authors/{nickname}
  (프로필 + 공개 작품), POST/DELETE /authors/{id}/subscribe, GET
  /me/subscriptions(작가 목록 + 새 화 피드), GET /notifications(목록·
  unread count), POST /notifications/{id}/read, POST /notifications/
  read-all. 알림 생성 함수 notify(user_id, type, title, body, link) —
  문의 답변도 이 함수로 교체. **showcase on 시** 구독자 전원 notify
  (background)
- 프론트: 설정 페이지(닉네임·소개·아바타, 첫 로그인 시 닉네임 미설정이면
  안내 배너), /@닉네임 페이지, 뷰어·갤러리 작가 링크 + [구독] 버튼,
  "내 구독" 페이지, 헤더 🔔 → 알림센터 드롭다운(모바일은 전체 화면),
  드로어에 내 구독·알림. 다크·375px
- 배포 → 도도 확인(계정 A가 작가, 계정 B(테스트 계정)로 구독 → A가
  에피소드 공개 → B 🔔에 새 화 알림 → 클릭 → 뷰어) → 커밋

## 2단계 — 댓글·답글·신고·차단
- step31: comments, comment_reports, user_blocks
- 백엔드: GET/POST /episodes/{id}/comments(parent_id로 답글), DELETE
  (본인·작가·관리자), POST /comments/{id}/report, POST /authors/block,
  차단된 사용자는 그 작가 작품에 댓글 불가(403 "작성할 수 없어요").
  댓글·답글 시 작가/원댓글 작성자에게 notify. 관리자 GET /admin/reports
  + 처리(삭제·무시)
- 프론트: 뷰어 하단 댓글 영역(목록·입력·답글 펼치기·신고·삭제), 작가
  배지, 비회원은 "댓글을 쓰려면 로그인", /admin 신고 탭
- 배포 → 도도 확인(B가 댓글 → A 🔔 → A 답글 → B 🔔, 신고 → 관리자 탭,
  차단 → B 댓글 불가) → 커밋

## 3단계 — 웹푸시 + PWA
- step32: push_subscriptions
- PWA: manifest.json(이름·아이콘 192/512·theme·display standalone),
  service worker(푸시 수신·클릭 시 link 열기, 캐시는 최소), Vite PWA
  플러그인 또는 수동. Apache에서 /sw.js 루트 서빙 확인
- 백엔드: VAPID 키 생성(.env, 채팅 금지), POST /push/subscribe·
  DELETE, notify()에서 푸시 발송(pywebpush, background, 실패 endpoint
  정리). 알림 종류별 설정(users.notify_prefs JSON)
- 프론트: 알림센터 "폰으로 알림 받기" 토글 → Notification.request
  Permission → 구독 전송. iOS Safari 비-standalone이면 "홈 화면에 추가"
  안내 카드(공유 아이콘 → 홈 화면에 추가 → 다시 열기). 설정에 알림
  종류 on/off
- 배포 → 도도 확인(**도도 폰 실기기** — 안드로이드 크롬: 바로 허용 →
  A 공개 → 폰 알림창 / 아이폰: 홈 화면 추가 후 동일) → 커밋
