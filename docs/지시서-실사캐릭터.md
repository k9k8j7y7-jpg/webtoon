# 지시서 — F 실사 캐릭터 (사진 속 인물이 웹툰 세계에 등장)

> 원칙: 단계마다 멈추고 보고. 커밋은 도도 검증 후. 마이그레이션은
> 리허설 → 백업 → 도도 "실행해". 이미지 생성 검증은 **새 단편 1개, 컷 3장**.
> 근거: docs/조사-실사캐릭터.md (2026-10-02), 실험 scratch/photo/
> gpt_realphoto_test.py (2장, $0.057·34초/컷, 얼굴 유지·도도 시트 반영 확인)
> [근거] 도도 결정 — 실사 캐릭터가 하나라도 연결된 에피소드는 **전 컷을
> GPT(gpt-image-2.5-sunburst images.edit)로 생성**(컷별 모델 분기 없음).
> **스타일 선택과 무관**하게 사용 가능. 단편·연작·광고 3타입 공통.
> 시트 생성 없음(패킷 미차감). 편집은 옷·머리·소품만, 얼굴·체형·나이 잠금.

## 목표 (도도가 화면에서 보게 되는 것)
- 캐릭터 만들기 모달(게이트3·라이브러리 공통)에 **[실사 캐릭터]** 토글.
  켜면 시트 생성 대신 **사진 업로드**(1~3장, 정면 필수·전신 권장)와
  **동의 체크**("본인이거나 초상권 사용에 동의한 사람의 사진입니다")가
  나타남. 동의 없이는 저장 불가
- 캐릭터 카드: 시트 자리에 업로드 사진 썸네일 + **"실사"** 배지.
  [재생성(2패킷)] 대신 **[사진 교체]**. 편집은 설명(옷·머리·소품)만
- [캐릭터 불러오기] 피커: 실사 캐릭터는 **어느 스타일 탭에서든 항상 표시**
  ("실사" 배지)
- 게이트5: 실사 캐릭터 포함 에피소드는 생성 버튼 옆에 "실사 캐릭터 포함 —
  컷당 약 30~40초" 안내. 생성 결과: 사람은 사진 그대로, 배경·웹툰
  캐릭터는 선택한 스타일
- 기존 에피소드·웹툰 캐릭터는 변화 없음(Gemini 경로 그대로)

## 0단계 — DB
- step28.sql: `characters.is_photo_real TINYINT(1) DEFAULT 0`,
  `characters.consent_given TINYINT(1) DEFAULT 0`. reference_photos JSON은
  기존 컬럼 재사용(조사 1번)
- 리허설(로컬) → 서버 백업 → 도도 "실행해" → 적용 → 보고

## 1단계 — 백엔드
- Character 생성/수정 API: `is_photo_real`·`consent_given` 수신(FormData
  multipart 원칙). is_photo_real=1이면 **사진 1장 이상 필수, consent_given
  필수(없으면 400 "초상권 동의가 필요합니다")**, 시트 생성 호출 스킵·패킷
  미차감. style은 null 허용(스타일 무관). 사진 저장은 기존
  validate_and_process() 재사용(조사 7번)
- 시트 재생성 API: is_photo_real이면 400("실사 캐릭터는 사진 교체로")
- **[사진 교체]** API: reference_photos 교체(기존 파일 정리)
- /characters/link 피커 목록: 스타일 필터에서 is_photo_real은 **항상 포함**.
  스타일 불일치 400 검사에서 실사 캐릭터 제외
- images/service.py: `_episode_has_photo_real_char()` → True면 해당
  에피소드 **모든 컷** OpenAIImageAdapter(조사 3번). 참조 이미지 순서 =
  실사 사진(정면 먼저, 최대 3) + 웹툰 캐릭터 시트 + 장소 이미지(첨부 시).
  비율 5종 → GPT size 매핑(1:1→1024², 9:16·3:4→1024×1536, 16:9·4:3→
  1536×1024) 후 **중앙 크롭으로 정확한 비율** 맞춤. page_format 정합성
  검증은 현행 그대로
- prompts/service.py `build_cut_prompt(has_photo_real_char=True)`:
  ① "Person(s) in reference photo(s): keep exact face, body shape, age,
  hairstyle — photorealistic as in the photo. Only outfit may follow the
  description." ② 스타일 snippet은 **배경·웹툰 캐릭터에만** 적용한다고
  명시 ③ 웹툰 캐릭터: "match the sheet's proportions and eye size exactly,
  no chibi exaggeration"(실험에서 도도가 SD화된 문제) ④ 옷 일관성: 캐릭터
  설명의 옷 문구를 매 컷 프롬프트에 포함
- 마켓(G) 대비: is_photo_real 캐릭터는 공개/마켓 노출 **불가** 가드 한 줄
  (지금은 플래그만)
- 배포·reload·health → 보고. 여기까지는 패킷 0

## 2단계 — 프론트
- 캐릭터 모달(게이트3 + 라이브러리): [실사 캐릭터] 토글 → 사진 업로드
  (1~3장, 첫 장 "정면" 라벨, 미리보기·삭제), 동의 체크박스 + 약관 링크.
  토글 켜면 스타일 선택 숨김, 시트 생성 문구 숨김. 다크 대응
- 카드: 사진 썸네일 + "실사" 배지, [재생성] 숨김 → [사진 교체], 편집 모달은
  설명·옷·머리·소품만(얼굴 관련 필드 잠금 안내)
- 피커: 실사 캐릭터 항상 표시 + 배지
- 게이트5: 실사 포함 시 안내 문구(생성 전 + 진행 중 "약 30~40초")
- 배포 → 도도 확인(모달·카드·피커 화면만, 패킷 0) → **커밋**

## 3단계 — 검증 (패킷 3 + API 약 $0.1)
- 새 단편 **"실사 테스트"**(테스트 프로젝트): 도도 사진(정면 상반신 +
  전신 1장), 웹툰 캐릭터 도도(캐릭터 테스트 것) 연결, korean_webtoon,
  세로 웹툰 9:16. 콘티 → 컷 3장만 생성:
  - 바스트샷(사람+도도) / 풀샷(사람 전신+도도) / 도도 단독 컷
  - 확인: 얼굴 동일, 전신 체형 유지, 도도 시트 비율 유지, 도도 단독 컷도
    GPT 경로로 생성됐는지(로그), 비율 9:16 정확
- 스타일 호환 실험(에피소드 아님, scratch 스크립트): 같은 참조·같은 장면을
  **SD/개그체·수채화풍** 2장 → 실사 사람과 어색하면 해당 스타일에 "실사
  캐릭터는 어색할 수 있어요" 안내 문구(프리셋에 플래그)
- 연작·광고: 코드 경로가 타입 무관인지 확인만(생성 안 함)
- 도도 확인 → 커밋
