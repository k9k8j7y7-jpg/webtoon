# 조사: 게이트1 카드 저장 (F5 유실 문제)

> 2026-10-06 조사 완료 — 코드 수정 없음

## 1. 현재 입력이 사는 곳

| 입력 | 저장 위치 | 서버 저장 시점 |
|---|---|---|
| idea_brief (요약·인물·전개·톤) | DB `gate_status.idea_brief` | **onBlur 자동저장** (500ms debounce) + [저장] 버튼 |
| 등장인물 카드 (이름·설명·성별·나이) | **React state만** (`characters`) | [기획 생성] POST body에만 포함 → F5 유실 |
| 장르·분위기·전개 칩 | **React state만** (`genre/mood/development`) | [기획 생성] POST body에만 포함 → F5 유실. 생성 후에는 `script.story_options`에서 복원 가능 |
| 기획 결과 (제목·로그라인·시놉시스) | DB `episodes` 테이블 | [기획 생성] 시 즉시 저장, 편집은 [저장] 버튼 |

**핵심 문제:** 등장인물 카드 + 3축 선택이 React state 전용 → F5·뒤로가기에 전부 날아감.
idea_brief에서 승계된 카드도 매번 `useEffect`로 재생성하지만, 사용자가 수정한 값은 복원 불가.

## 2. stale 배너 메커니즘

`Gate1Planning.jsx` 348-354행:
- `inputSig` = `JSON.stringify(characters + genre + mood + development)` (useMemo)
- `lastGenSig` = 기획 생성 시점에 `inputSig` 스냅샷 (setState)
- `inputsChanged` = `lastGenSig !== null && lastGenSig !== inputSig`

**한계:** `lastGenSig`가 React state → 새로고침 시 `null`로 초기화 → **배너 표시 불가**.
기획 생성 후 카드를 수정하고 F5 → 배너 안 뜨고, 수정된 카드도 유실.

## 3. 저장 방식 후보 비교

### (a) debounce 자동 저장 — gate_status.planning_draft

변경 시 500ms debounce로 `gate_status.planning_draft` JSON에 자동 저장.

```jsonc
// gate_status.planning_draft 예시
{
  "characters": [{"name":"도도","description":"...","gender":"여","age":"20대"}],
  "genre": "일상",
  "mood": "따뜻한",
  "development": "반전",
  "saved_at": "2026-10-06T12:00:00Z"
}
```

| 항목 | 내용 |
|---|---|
| **장점** | 마이그레이션 불필요(gate_status JSON 내부 키 추가). 사용자 행동 변경 없음. idea_brief onBlur 저장과 패턴 동일. F5 후 즉시 복원. stale 비교 기준도 함께 저장 가능(`last_gen_snapshot`) |
| **단점** | 편집할 때마다 PUT 호출(debounce로 완화). gate_status JSON 크기 약간 증가 |
| **변경 파일** | 프론트: `Gate1Planning.jsx` (debounce 훅 + 초기 로드 복원). 백엔드: `story/router.py` (PUT `/planning-draft` 엔드포인트 1개, 또는 기존 idea-brief PUT 확장). `gate.py`는 변경 불필요(JSON 자유 키) |
| **규모** | **소** — 프론트 ~40행, 백엔드 ~20행, 마이그레이션 0 |

### (b) [임시 저장] 버튼

사용자가 명시적으로 클릭해야 저장.

| 항목 | 내용 |
|---|---|
| **장점** | API 호출 최소. 저장 의도 명확 |
| **단점** | 사용자가 안 누르면 유실 그대로 — 문제 해결 안 됨. 버튼 위치·라벨 고민. 누르라는 가이드 필요 |
| **변경 파일** | 프론트: `Gate1Planning.jsx` (버튼 + 저장 로직). 백엔드: 동일 |
| **규모** | **소** — (a)와 비슷하지만 UX 열등 |

### 권장: **(a) debounce 자동 저장**

idea_brief가 이미 onBlur 자동 저장하므로 패턴 일관성 확보. 사용자 행동 변경 0.

## 4. stale 비교 기준 저장

자동 저장 시 `gate_status`에 두 키를 함께 두면 새로고침 후 배너 유지 가능:

```jsonc
{
  "planning_draft": { /* 현재 카드 값 */ },
  "last_gen_input": { /* 마지막 [기획 생성] 시점의 카드 값 스냅샷 */ }
}
```

- 페이지 로드 시 `planning_draft`와 `last_gen_input`을 비교 → 다르면 stale 배너 표시
- [기획 생성] 성공 시 `last_gen_input` = 현재 `planning_draft` (서버에서 갱신)
- **마이그레이션 불필요** — gate_status JSON 내부 키

## 5. 게이트2·3·4 유실 패턴 점검

| 게이트 | 유실 위험 | 이유 |
|---|---|---|
