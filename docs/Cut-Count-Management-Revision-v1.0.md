# Project T — 컷 수 관리 수정 지시서 (게이트 2 + 게이트 4)

> **버전:** v1.0
> **작성일:** 2026-07-31
> **대상:** Claude Code
> **참조 문서:** docs/ 의 API-Spec-v1.0, Cut-Spec-Schema-v1.0, Data-Model-v1.0, Backend-State-Model-v1.0
> **범위:** 컷 수(cut count)가 게이트 2·4에 걸쳐 어떻게 결정·조정되는지. 두 게이트의 역할을 분리한다.

---

## 배경 및 핵심 원칙

**발견된 버그:** 대본 생성(게이트 2)의 컷 수 상한이 8~15컷으로 고정되어, 긴 시놉시스의 후반부가 잘림. (예: 에피소드10에서 시놉시스엔 결말(빚·파멸·폐인)이 있으나 대본은 씬 4에서 끊김.)

**근본 원인:** 컷 수를 고정 상한으로 막아, 이야기 완결성보다 컷 수 제한이 우선됨.

**핵심 원칙:** **컷 수는 이야기 분량이 정한다.** 고정 상한으로 막지 않는다.

이 원칙이 두 게이트에 다르게 적용된다:

| 게이트 | 역할 | 컷 수 관련 |
|---|---|---|
| **게이트 2 (대본)** | 이야기 완결 | 시놉시스를 **빠짐없이** 대본화. 컷 수는 이야기에 필요한 만큼(상한에 안 잘림) |
| **게이트 4 (콘티)** | 컷 수 조정 | 사용자가 컷 수를 조정. 단 하한 아래로는 못 줄임(이야기 뭉개짐 방지) |

> 게이트 2 = "이야기를 다 담는다", 게이트 4 = "몇 컷으로 그릴지 정한다". 역할이 분리된다.

---

# A. 게이트 2 — 대본 컷 수 자동 조절

## A-1. 고정 상한 제거

- 현재 시스템 프롬프트의 **"1화 분량(8~15컷)", "총 컷 수는 8~15개"** 제한을 제거.
- 대신 다음 지시로 교체:
  ```
  "시놉시스의 모든 주요 장면을 빠짐없이 대본화하라.
   컷 수는 이야기를 완결하는 데 필요한 만큼으로 한다.
   시놉시스의 결말까지 반드시 포함하라."
  ```

## A-2. 느슨한 극단 방지 가드레일

- 완전 무제한이 아니라, **극단만 막는 넓은 범위**를 둔다. 예: **최소 6컷 ~ 최대 40컷.**
- 이 범위는 "이야기가 잘리는 것"과 "무한정 길어지는 것" 양극단만 방지. 대부분의 이야기는 이 안에서 자연스럽게 결정됨.
- **상한(40)이 이야기 완결성보다 우선하지 않도록 주의.** 이야기가 잘리느니 컷이 많은 편이 낫다. 40컷으로도 부족한 극단적 시놉시스는 사용자에게 "시놉시스가 너무 깁니다" 안내(드문 케이스).

## A-3. 자동 조절 (구간 분기 아님)

- "짧은 시놉시스 = N컷, 긴 시놉시스 = M컷" 같은 **구간 분기를 두지 않는다.**
- AI가 시놉시스의 주요 장면 수·흐름에 맞춰 자연스럽게 컷 수를 정하게 한다. (짧은 이야기는 억지로 늘리지 않고, 긴 이야기는 잘리지 않게)

## A-4. 검증

- 긴 시놉시스(예: 에피소드10)로 대본 생성 시, **시놉시스 결말까지 대본에 포함되는지** 확인.
- 짧은 시놉시스로 생성 시, 억지로 늘어나지 않는지 확인.

# B. 게이트 4 — 컷 수 조정 (하한 제약 + 최소 편집)

> 현재 상태: 컷 목록 표시는 되나 **읽기 전용**. 컷 수정 API(`PUT /cuts/{id}`, `PUT /cuts/{id}/dialogue`)는 백엔드에 존재하나 편집 UI 없음.

## B-1. 컷 수 조정 — 권장 범위 + 하한 강제

**권장 컷 수 제시:**
- 게이트 4 진입 시(콘티 생성), AI가 대본을 분석해 **권장 컷 수(범위)**를 제시. 예: "이 대본은 18~24컷이 적당합니다."
- 기본값으로 그 범위 내 컷 수로 자동 분할(현행 자동 분할 유지).

**컷 수 재조정:**
- 사용자가 목표 컷 수를 입력하면(예: "20컷으로") AI가 그 수에 맞춰 재분할.
- **하한 강제:** 대본 분량상 최소 컷 수 아래로는 막는다.
  - 하한 아래 요청 시(예: 대본이 20컷 분량인데 4컷 요청):
    ```
    "이 대본은 최소 N컷이 필요합니다.
     컷을 더 줄이려면 대본(이야기)을 줄여주세요."
    ```
  - "대본을 줄이라"는 안내와 함께 게이트 2로 유도(안내만, 자동 이동은 선택).
- **이유:** 긴 대본을 억지로 적은 컷에 담으면 말풍선 폭탄·내용 뭉개짐. A(게이트2)와 정합 — 짧게 하려면 컷이 아니라 대본부터 짧아야 함.

## B-2. 컷별 수정 — 기존 API에 UI 연결 (최소 편집)

- 백엔드에 이미 있는 엔드포인트에 **편집 UI만** 붙인다:
  - `PUT /cuts/{cut_id}` — 샷 타입, 액션, 대사 수정
  - `PUT /cuts/{cut_id}/dialogue` — 대사만 수정
- 컷 카드에 [편집] 버튼 → 샷 타입(long/full/bust/close_up) 선택, 대사 텍스트 편집 UI.

## B-3. MVP 범위 (최소 편집)

- **포함:** 컷 수 재조정(B-1) + 컷별 수정(B-2, 기존 API 연결)
- **제외 (V1):** 컷 추가/삭제/병합, 드래그 순서 변경.
  - 이유: 컷 수 재분할로 대부분 대체 가능. 개별 편집은 손이 많이 가므로 MVP엔 과함.

## 흐름 요약

```
게이트 2 (대본)
  시놉시스 → "빠짐없이 대본화" (상한에 안 잘림, 6~40 가드레일)
  → 이야기 완결된 대본
       ↓
게이트 4 (콘티)
  대본 분석 → 권장 컷 수 제시 "18~24컷 적당"
  → 자동 분할
  → 사용자 조정:
      · 범위 내(예: 20컷) → 재분할
      · 하한 아래(예: 4컷) → 막고 "대본을 줄이세요" 안내
  → 컷별 수정 (샷·대사, 기존 API 연결)
       ↓
게이트 5 (이미지 생성)
```

2. **B (게이트 4 컷 조정)** — A로 대본이 완결된 뒤 컷 조정이 의미 있음.
