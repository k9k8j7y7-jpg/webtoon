## 묶음 1 — 작은 수정 4건 (한 번에 배포)

### 1. 푸시 탭 → 자동 읽음
- [근거] 겪은 문제 — 폰 알림을 탭해서 댓글까지 봤는데 알림센터엔
  빨간 점이 그대로 남음
- send_push payload에 `notification_id` 포함 → sw.js notificationclick
  에서 link에 `?n={id}` 붙여서 열기(**link에 `#comment-{id}` 해시가
  있으면 해시 앞에** 쿼리 삽입). sw는 토큰이 없으니 읽음 호출은 프론트
  가 담당: 앱 로드 시 `n` 쿼리가 있으면 POST /notifications/{n}/read
  호출 후 쿼리만 제거(해시는 유지해서 댓글 강조 그대로)
- 이미 열려 있는 탭이 있으면 그 탭을 focus + navigate(지금 동작 유지)

### 2. 알림 목록 자동 갱신
- [근거] 겪은 문제 — 🔔 숫자는 2로 올라갔는데 /notifications 목록엔
  새 알림이 없어서 당겨서 새로고침해야 보였음
- useHeaderCounts의 unread가 **증가**하면 알림 목록(모바일
  /notifications 페이지·PC 드롭다운 열려 있을 때) 다시 가져오기.
  추가로 visibilitychange(visible)·focus 때도 1회 재조회. 폴링 간격은
  늘리지 말 것

### 3. 토큰 만료 튕김 때는 구독 유지 (조사 → 필요 시 수정)
- [근거] 도도 결정 — "로그아웃 버튼 = 이 폰 알림 끊김"은 유지. 단
  **토큰 만료로 자동 튕기는 경우**는 사용자가 나간 게 아니므로 구독을
  지우면 안 됨
- api/client.js 401 리다이렉트 경로·AuthContext 토큰 정리 경로에서
  unsubscribeOnLogout이 호출되는지 확인. 호출되면 **명시적 로그아웃
  버튼에서만** 호출되게 분리. 결과를 한 줄로 보고(호출 안 되면 "이미
  맞음")

### 4-A. 설정 페이지에도 "폰으로 알림 받기" 토글
- [근거] 도도 — 🔔 안에만 있어서 사용자가 어디로 들어가야 하는지 모름
- SettingsPage "알림 설정" 섹션 **맨 위**에 PushToggleCard 그대로
  재사용(같은 컴포넌트·같은 상태·같은 권한 안내). 그 아래 기존 종류별
  on/off. 알림센터 카드의 "종류 고르기" 링크는 /settings#notify 유지

→ 배포 → 도도 확인(체크리스트 1~4) → 다음 묶음

## 묶음 2 — 알림 켜기 유도 + 안드로이드 홈 화면 추가

### 4-C. 1회 "폰으로 알림 받을까요?" 배너
- [근거] 도도 결정(안 A + C) — 알림을 켤 **이유가 생긴 순간**에 한 번만
- 트리거: ① [구독] 성공 직후(작가 페이지·뷰어) ② 댓글·답글 등록 직후
- 조건(전부 만족할 때만): 로그인 상태 / 푸시 지원 브라우저 /
  Notification.permission이 denied 아님 / 현재 이 기기에 활성 구독
  없음 / localStorage `push_nudge_done` 없음
- UI: 해당 화면 하단에 작은 카드(토스트 X — 3초 만에 사라지면 안 됨)
  "새 화·답글 알림을 폰으로 받아볼까요?" [켜기] [나중에]
  - [켜기] → 토글과 **같은 함수**(권한 요청 → 구독 등록) 제자리에서
    실행 → 성공 시 카드가 "알림을 켰어요 ✓"로 바뀌고 2초 후 사라짐.
    iOS 비-standalone이면 [켜기] 대신 "홈 화면에 추가" 안내로 전환
  - [나중에] 또는 X → `push_nudge_done=1` 저장 → **이 기기에서 다시
    안 띄움**(기간 만료 없음 — 단순하게)
  - [켜기] 성공 시에도 `push_nudge_done=1`
- 다크·375px

### 5. 안드로이드 "홈 화면에 추가" 안내 카드
- [근거] 도도 결정 — 크롬 탭에서 받은 푸시는 머리에 "Chrome
  ssagda.com"이 뜸. 홈 화면에 추가(WebAPK)하면 **EziToon 이름·아이콘**
  으로 뜨고 폰 설정에 EziToon 앱 알림 항목이 생김
- main.jsx에서 `beforeinstallprompt` 이벤트를 preventDefault 후 보관
  (전역 또는 context). 보관된 이벤트가 있고 standalone이 아닐 때만
  카드 표시
- 위치: 알림센터 토글 카드 **아래**(토글 ON 상태일 때만 — 알림을 켠
  사람에게만 의미 있음) + 설정 알림 섹션 동일. iOS 카드와 같은 톤
- 문구: "앱처럼 쓰기 — 홈 화면에 추가하면 알림이 EziToon 이름으로
  떠요" [홈 화면에 추가] [닫기]
  - [홈 화면에 추가] → 보관한 이벤트 `.prompt()` → 결과 accepted면
    카드 제거, dismissed면 그대로
  - [닫기] → localStorage `install_nudge_done=1` → 다시 안 띄움
  - 이미 standalone(display-mode)이면 카드 자체 없음
- 설치 가능 조건 확인: 크롬 DevTools → Application → Manifest에
  오류·경고 0(name·short_name·start_url `/WEBTOON/`·display standalone·
  icons 192/512 **purpose any + maskable** 둘 다), sw 등록 OK. 경고
  있으면 manifest 보정. 아이콘 maskable은 Sparkles 로고 주변 여백
  20% 추가한 버전으로(도도 확인)
- 설치 후 동작: 같은 origin·같은 sw·같은 구독이라 재등록 불필요.
  단 설치된 앱에서 로그인 상태는 크롬 탭과 **공유되지 않을 수 있음**
  (WebAPK는 쿠키·localStorage 공유되나 기기마다 다름) → 도도 폰에서
  확인 항목에 포함
