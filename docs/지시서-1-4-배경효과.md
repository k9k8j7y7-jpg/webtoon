# 지시서 — 1-4 배경효과 PNG 오버레이 구현

> Claude Code에게: 이 문서는 1-4 기능의 전체 구현 지시서다.
> **오늘은 1단계만 구현한다. 2~4단계는 전체 그림 파악용으로만 읽고,
> 각 단계는 이전 단계가 커밋되고 도도의 "다음 단계 진행해" 승인이
> 있어야 시작한다.** 절대 앞서 나가지 말 것.

## 공통 규칙 (모든 단계에 적용)
- 각 단계 완료 시 멈추고 보고: 변경 파일 목록 + 핵심 로직 요약
- 커밋은 도도 확인 후에만. 미커밋 방치 금지, 파괴적 git 금지
- DB 마이그레이션 없음 (컷 spec은 JSON — effect_items는 배열 추가일 뿐)
- 기존 기능(말풍선·효과음·내보내기) 회귀 금지. sfx_items 패턴을 최대한 재사용
- 판단이 필요한 지점이 나오면 임의로 정하지 말고 멈추고 질문

## 배경·확정 설계
- 목적: 컷 위에 만화 효과 PNG(집중선·속도선·깜짝 등)를 수동으로 얹는 기능
- 컷 이미지는 9:16 세로 고정 (gemini aspect_ratio 기본값)
- `effect_items` 배열을 컷 spec에 추가. 항목 구조:
  `{effect_id, x, y, width, rotation, opacity, flip_h}`
  - x, y: 효과 중심 위치, 컷 기준 0~1 정규화
  - width: 효과 너비, 컷 너비 기준 0~1 (높이는 PNG 원본 비율로 자동)
  - rotation: 도 단위 (0~360)
  - opacity: 0~1
  - flip_h: boolean (좌우 반전)
- 레이어 순서 (아래→위): 컷 이미지 → 효과(effect) → 말풍선 → 효과음(sfx)
- PNG 위치: `frontend/public/effects/` (10개, 아래 카탈로그 참조)
- 자동 추천·관리자 업로드는 이번 범위 아님 (후순위)

## 1단계 — 백엔드 + 카탈로그 (오늘 작업)

0. 사전 확인: `frontend/public/effects/` 에 위 10개 PNG가 있는지 확인.
   없거나 파일명이 다르면 실제 목록만 보고하고 멈춰.
1. 컷 spec에 `effect_items` 배열 지원
   - 백엔드는 저장/전달 시 배열을 보존
   - 검증 추가: effect_id가 카탈로그 10종 중 하나인지, x/y/width/opacity
     0~1 범위, rotation 0~360, flip_h boolean. 위반 시 400 + 명확한 메시지
   - `effect_items` 없는 기존 컷은 빈 배열로 취급 — 하위 호환 필수
2. `frontend/src/.../effectCatalog.js` 생성
   - 각 항목: `{id, name(한글 표시명), src, category: 'full' | 'partial'}`
   - src는 `/effects/<id>.png`
3. UI는 만들지 말 것 (2단계 범위)

보고 후 대기. 커밋 메시지(승인 후): 
`feat: 컷 spec에 effect_items 지원 + 효과 카탈로그 10종`

## 2단계 — EffectLayer + CutEditor 배치 UI (승인 후 진행)

1. `EffectLayer.jsx` 생성 — SfxLayer 패턴 그대로
   - SVG `<image>`로 효과 PNG 렌더, 정규화 좌표 → 컷 좌표 변환
   - rotation은 효과 중심 기준, flip_h는 scale(-1,1), opacity 적용
   - 레이어 순서 준수: 이미지 → **효과** → 말풍선 → 효과음
2. CutEditor에 효과 편집 기능
   - 효과 추가 UI: 카탈로그에서 선택(한글 표시명 + 썸네일), full/partial 구분 표시
   - full 선택 시 기본값: x=0.5, y=0.5, width=1.0 (컷 전체)
   - partial 선택 시 기본값: x=0.5, y=0.5, width=0.3
   - 기존 드래그 이동 패턴 재사용 + 크기·회전·불투명도·반전 조절 UI
     (효과음 편집 UI와 동일한 조작감 유지)
   - 효과 삭제 가능
3. 저장 시 effect_items가 spec에 반영되고 재로드 후에도 유지되는지 확인

보고 후 대기. 도도가 브라우저에서 배치 테스트 → 통과 후 커밋.

## 3단계 — 내보내기 반영 (승인 후 진행)

1. exportRenderer.js의 3개 경로(ZIP / 세로 이어붙이기 / 인스타) + A4에서
   효과 레이어 렌더
   - 말풍선·효과음과 동일하게 renderToStaticMarkup 경로에 포함
   - PNG는 Base64 인라인으로 임베드 (CORS taint 방지 — 기존 svg-text
     렌더 방식과 동일한 이유)
   - 레이어 순서 화면과 동일: 이미지 → 효과 → 말풍선 → 효과음
2. 확인 기준(수치): 화면 편집기와 내보내기 결과의 효과 위치·크기가
   눈대중이 아니라 좌표 기준으로 일치할 것

보고 후 대기. 도도가 내보내기 3경로 실물 확인 → 통과 후 커밋.

## 4단계 — 배포 (승인 후 진행)

1. 빌드 → 배포 (기존 배포 절차 그대로)
2. 배포 후 확인 항목을 도도에게 안내:
   - ep26 아무 컷에서 효과 추가/이동/삭제
   - 새로고침 후 유지 확인
   - 내보내기 1개 경로 스팟 체크
3. 주의: ep26 게이트3 [자산 수정하기]는 누르지 않는다 (게이트4·5 invalidated)

배포 완료 보고로 1-4 종료. 이후 3화 잔여 컷에서 실사용 테스트는 도도가 진행.
