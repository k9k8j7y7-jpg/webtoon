## 5. 수동 환불 절차

A2 관리자 환불 엔드포인트가 구현되기 전까지의 수동 환불 절차.

### 5-1. 전제

- 환불 정책: 구매 7일 이내, 미사용분 전액 환불. 사용분은 **개당 300원** 공제.
- 패킷 상품: 15개(4,900원) / 30개(9,500원) / 100개(29,900원) / 300개(74,900원)

### 5-2. 환불 금액 계산 예시

| 상품 | 구매가 | 사용 패킷 | 공제 | 환불액 |
|---|---|---|---|---|
| 30개 팩 (9,500원) | 9,500 | 0개 | 0 | **9,500원** (전액) |
| 30개 팩 (9,500원) | 9,500 | 5개 | 1,500원 | **8,000원** |
| 100개 팩 (29,900원) | 29,900 | 20개 | 6,000원 | **23,900원** |
| 30개 팩 (9,500원) | 9,500 | 30개(전부) | 9,000원 | **500원** |

> 공제액 = 사용 패킷 × 300원. 환불액 = 구매가 − 공제액. 환불액 ≤ 0이면 환불 불가.

### 5-3. 절차

#### ① 사용량 확인 (DB 조회만)

```sql
-- 해당 주문의 패킷 사용량 확인
-- 주문 정보
SELECT id, user_id, product_code, amount, status, created_at
FROM orders WHERE id = <주문ID>;

-- 사용자 현재 잔량
SELECT balance FROM packet_balances WHERE user_id = <user_id>;

-- 구매 후 사용한 패킷 (generation 사유)
SELECT SUM(ABS(delta)) AS used
FROM packet_transactions
WHERE user_id = <user_id> AND reason = 'generation'
  AND created_at >= '<주문일>';
```

#### ② 토스페이먼츠 취소 (토스 콘솔)

1. [토스페이먼츠 관리자](https://app.tosspayments.com) 로그인
2. 결제 내역 → 해당 `paymentKey` 검색 (orders 테이블 `payment_key` 컬럼)
3. **부분 취소** 또는 **전체 취소** — 환불 금액 입력
4. 취소 사유 메모: "고객 요청 환불 — 사용 N개 × 300원 공제"

#### ③ 패킷 회수 (DB 변경 — 도도 "실행해" 필요)

```sql
-- 패킷 차감 트랜잭션 기록
INSERT INTO packet_transactions (user_id, delta, reason, description)
VALUES (<user_id>, -<회수할 패킷 수>, 'refund', '환불: 주문 #<주문ID> — 사용 N개 공제');

-- 잔량 갱신
UPDATE packet_balances SET balance = balance - <회수할 패킷 수>
WHERE user_id = <user_id>;

-- 주문 상태 변경
UPDATE orders SET status = 'cancelled' WHERE id = <주문ID>;
```

> **회수할 패킷 수** = 구매 패킷 − 사용 패킷 (사용분은 이미 차감됨)

#### ④ 사용자 알림

```sql
INSERT INTO notifications (user_id, type, title, body, link)
VALUES (<user_id>, 'system', '환불이 처리됐어요',
  '주문 #<주문ID> 환불 <환불액>원이 처리됐어요. 카드사에 따라 2~5영업일 소요될 수 있어요.',
  '/packets');
```

#### ⑤ 확인

```sql
-- 잔량 검증
SELECT balance FROM packet_balances WHERE user_id = <user_id>;
SELECT SUM(delta) AS calc FROM packet_transactions WHERE user_id = <user_id>;
-- 두 값이 일치해야 함
```

### 5-4. 주의사항

- 토스 취소 먼저 → DB 변경은 취소 성공 확인 후
- 패킷 잔량이 부족하면(이미 다 쓴 경우) balance가 음수가 되지 않도록 `MAX(0, balance - 회수)` 적용
- 환불 완료 후 야간 점검 봇의 `packet_ledger` 체크가 불일치를 감지하지 않는지 확인
