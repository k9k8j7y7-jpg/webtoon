## ④ 프롬프트 구성 — 실사 캐릭터 전용 지시

### 현재 `build_cut_prompt()`

파일: `backend/app/prompts/service.py`

1. 단일 일러스트 강제 (83~88행)
2. 캐릭터 앵커링 (89~106행) — "Replicate their facial features, hairstyle, hair color, age, and body type precisely"
3. 캐릭터별 appearance_en 주입 (108~131행)

5. 스타일 (168~169행) — "Apply this art style to coloring and rendering only, preserve character facial identity"
6. 샷 타입·강조 (171~188행)
7. 프로젝트 규칙 (190~197행)
8. 웹툰 기본 지시 (199~214행)

**실사 캐릭터 시 변경 포인트:**

현재 앵커링 지시(92~105행)는 이미 "facial features, hairstyle, hair color, age, and body type"을 복제하라고 지시하므로 GPT에 그대로 전달해도 방향은 맞음.

그러나 실사 캐릭터 전용으로 강화가 필요한 문구:
- 기존: `"Only change their expression and pose to fit the scene"` (105행)
- 실사 강화: `"Only change their clothes to [outfit described], expression, and pose. NEVER change their face, body shape, skin tone, or age. This is a REAL person."`

**스타일 지시 갈등:** 4번 스타일 항목(168~169행)에서 웹툰 스타일 적용을 지시하는데, 실사 캐릭터는 "완전한 일러스트화" vs "실사 얼굴 유지"가 충돌할 수 있음. `gpt_realphoto_test.py` 30~37행의 스타일 프롬프트 참조:
```python
STYLE_PROMPT = (
    "Korean webtoon style, clean line art, cel shading, "
    "natural skin tones, soft shadows, vertical scroll optimized"
)
```
실사 얼굴 보존과 웹툰 스타일을 양립시키는 표현 실험 필요.

**`build_cut_prompt()` 수정 방식:** `has_photo_real_char: bool = False` 파라미터 추가 → True일 때 앵커링 문구 강화.

**변경 규모: 소(S)** — 파라미터 추가 + 조건부 문구 2~3줄.

## ⑤ 캐릭터 편집 및 재생성 예외

### 현재 재생성 플로우

파일: `backend/app/characters/router.py`

- `PUT /characters/{id}` (187~231행): 외형 필드 수정 → `build_character_description()` + `build_appearance_en()` 자동 재조립 → **이미지 재생성은 하지 않음** (별도)
- `POST /characters/{id}/regenerate` (238~282행): 패킷 2 차감 → 기존 이미지 삭제 → `generate_character_sheets()` 재실행

`generate_character_sheets()` (`service.py` 99~302행):
- `adapter.generate_character_sheet()` 호출 → Gemini API로 front + expressions 2장 생성
- `use_photo_reference=True`일 때: `reference_photos` URL을 로드해 Gemini에 스타일 참조로 전달 (203~227행)

### `is_photo_real=True` 캐릭터 예외 처리 필요 항목

1. **시트 생성 스킵:** `is_photo_real=True`이면 Gemini 시트 생성 건너뜀. 대신 `reference_photos` URL 첫 번째 장을 `character_images.type='front'`으로 복사(저장) — 레퍼런스 로드 로직이 동일하게 동작하도록.

2. **패킷 과금:** 시트 생성 없으면 2패킷 차감 없음. 대신 컷 생성 시 GPT는 Gemini와 비용 유사($0.057 vs $0.067)이므로 컷 1패킷 유지 가능 (실험 결과: `gpt_realphoto_test.py` 167~169행 계산식 참조, 장당 ~$0.057).

3. **재생성 버튼 라벨:** Gate3 UI에서 `is_photo_real=True` 캐릭터는 "시트 재생성" 버튼을 비활성화하거나 "사진 교체" 버튼으로 대체.

4. **appearance_en 처리:** 실사 캐릭터는 `build_appearance_en()` 대신 사진 추출(`extract_appearance_from_photos()`)로 생성된 값을 그대로 사용 — 이미 `is_animal` 분기(`service.py` 326행)와 동일 패턴.

5. **라이브러리 연결 시 스타일 필터:** `link_character()` (router.py 446행)에서 `is_photo_real=True` 캐릭터는 스타일 불일치 차단 로직 예외 처리 필요 (시트 기반 스타일 적용 불가).

**변경 규모:**
- `backend/app/characters/service.py`: 중(M) — is_photo_real 분기 + 시트 스킵 로직
- `backend/app/characters/router.py`: 소(S) — regenerate 엔드포인트 조건 처리
