# 단계 헤더(스테퍼) 조사 (2026-10-14)

## ① 스테퍼 컴포넌트

**파일:** `frontend/src/components/GateProgress.jsx`

**상태 판정 (`gateStatus` 키):**
- `gateStatus.current_gate` — 정수 1~5, 현재 활성 게이트
- `gateStatus.gates["1_planning" | "2_script" | "3_assets" | "4_storyboard" | "5_review"].status`:
  - `"approved"` → 초록 원 + Check 아이콘
  - `"draft"` → 파랑 원 + Pencil 아이콘
  - `"invalidated"` → 주황 원 + AlertTriangle 아이콘
  - `"locked"` (기본/폴백) → 회색 원 + Lock 아이콘, `disabled` + `cursor-not-allowed`
- 현재 보고 있는 게이트는 `neon-ring ring-offset-1` 하이라이트

**라우트:** URL 변경 없음 — **state 기반**. `WorkflowPage.jsx`에서 `setViewingGate(gateNumber)` 상태 전환. `displayGate = viewingGate || currentGate`로 표시할 게이트 컴포넌트 결정. `status === 'locked'`이면 클릭 무시.

## ② 이전 단계 되돌리기 → 뒤 단계 무효화

**무효화됨.** 과정:

1. `isViewingPrevious`(viewingGate < currentGate)일 때 노란 배너 + 빨간 "수정하기" 버튼 표시 (`WorkflowPage.jsx:156`)
2. 클릭 → dry_run으로 영향 범위 표시 → 확인 → `POST /episodes/{id}/revert` (`workflow/router.py:206`, body `{target_gate: N}`)
3. 백엔드 무효화:
   - target 게이트 → `"draft"`, `current_gate = target`
   - target+1 ~ 5의 approved/draft 게이트 → `"invalidated"`
   - target ≤ 2: 캐릭터·장소 → invalidated
   - target ≤ 3: 컷 → invalidated
4. **이미지는 삭제 안 됨** — `invalidated` 상태 표시만 ("재생성 필요")
5. 연작 파생 에피소드는 게이트1 revert 차단 (`gateStatus?.series_id` 가드)

## ③ PC에서 스테퍼 폭 불일치 원인

**스테퍼:** `w-full` + `flex-nowrap` — 부모 `max-w-7xl`(1280px) 전체 폭 차지
**게이트 콘텐츠:** 각 게이트 내부 카드는 `max-w-2xl`(672px), `glass-card` 등 — 스테퍼보다 좁음

| 영역 | max-width |
|---|---|
| Layout `<main>` | `max-w-7xl` (1280px) |
| 스테퍼 GateProgress | `w-full` (= 1280px) |
| 게이트 콘텐츠 | `max-w-2xl` (672px) ~ 내부별 상이 |

→ 스테퍼가 콘텐츠보다 훨씬 넓어 시각적으로 안 맞음. 스테퍼에 `max-width` 제약이 없는 게 원인.

PC에서 각 step은 `sm:flex-1`로 5등분 → 1280px/5 = 256px/step. 모바일은 `shrink-0` 고정 너비 + `overflow-x-auto` 가로 스크롤.
