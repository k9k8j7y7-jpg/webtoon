# 지시서 — 관리자 통계 페이지 (돈·사람·품질·상태)

> 목적: 출시 후 도도가 매일 아침 한 화면에서 **"얼마 벌고 얼마 나가는지 / 누가 쓰는지 / 잘 되는지 / 지금 멀쩡한지"** 를 본다. 특히 **패킷당 실제 API 원가**가 핵심 숫자. 상태 탭의 점검 함수는 다음 지시서(야간 점검 봇)가 그대로 재사용하므로 **화면과 분리된 함수**로 만든다.
> 순서: **1단계 조사 → 보고 → 도도 "실행해"(step40) → 2단계 구현 → 검증 → 커밋**. 운영 DB 변경은 리허설·~/backups/·"실행해" 규칙.

## 0. 원칙
- 관리자(기존 admin 권한)만. 비관리자 403. 토큰·키 노출 금지.
- **생성 로직·프롬프트·패킷 차감 규칙 불변.** 외부 API 호출부에는 "기록 한 줄"만 추가하고 호출 내용은 건드리지 않는다. 기록 실패가 생성 실패로 번지면 안 된다(try/except, 로그만).
- 숫자에는 출처를 붙인다: **실측**(api_calls 기록) / **추정**(기록 없던 과거 = generation_logs × 단가표). 화면에 "추정" 배지.
- 화면 단어: 프로젝트/에피소드 금지(관리자 화면도 "작품"으로). 패킷·트랙 이름은 사용자 화면과 같은 라벨(한 컷 광고·인스타툰·연재툰·상세페이지·이야기).

## 1. 1단계 — 조사 (보고 후 대기)

① **외부 API 호출부 전수**: OpenAI 이미지(gpt-image, quality 파라미터 값), Gemini 텍스트(대본·기획안·브리프·카피), Gemini 비전(check_copy_text·check_anatomy·제품 분석), omni 영상, 기타(TTS·번역 등 있으면). 파일:함수 목록 + 각 호출의 응답에서 **사용량 필드**(이미지 수·토큰 in/out·영상 초)를 꺼낼 수 있는지.
② **기존 로그 테이블**: generation_logs(컬럼·packets_charged·model 기록 여부), packet_transactions(reason ENUM 값 전부), orders(status 값·amount·paid_at), refunds 흔적(수동이면 없음), jobs/motion 상태 테이블, inquiries(답변 여부 컬럼), notices, users(created_at·last_login 여부), characters/character_images 수.
③ **지금 당장 뽑을 수 있는 숫자**(SELECT만, 전체 기간): 가입자 수, 결제 건수·합계, 판매 패킷 합, 사용 패킷 합(reason별), 잔량 합(모든 사용자 balance 합), 트랙별 생성 건수(purpose별 generation_logs), 실패 건수, 모션 건수. 표로.
④ **서버 상태 접근**: 디스크 사용량(df /home/bitnami), uvicorn 프로세스·최근 에러 로그 위치, 백업 폴더 ~/backups/ 최신 파일 시각. 서버 명령은 읽기만.
⑤ **step40 리허설 SQL 작성**(아래 2-1 스키마) → project_t_test 적용·down/up 재실행 → 보고. 운영 적용은 "실행해" 후.

## 2. 2단계 — 구현

### 2-1. DB (step40)
- `api_calls`: id, created_at, provider(openai/gemini/omni/other), model, kind(image/text/vision/video/other), purpose(onecut_ad/instatoon_ad/brand_series/detail_page/story/character/motion/check/analysis), user_id, episode_id(nullable), cut_id(nullable), units_json(이미지 수·토큰 in/out·초 등 원본), cost_usd DECIMAL(10,6), cost_krw INT, duration_ms, status(ok/error), error_code(nullable). 인덱스 created_at, purpose, user_id.
- `api_prices`: id, provider, model, kind, unit(image/1k_tokens_in/1k_tokens_out/second), usd_per_unit DECIMAL(12,8), note, updated_at. 초기값은 **현재 OpenAI·Gemini 공식 가격표를 Claude Code가 조사해서 넣고 출처 URL을 note에**(docs/원가-트랙별.md 수치와 대조해 차이 보고).
- `exchange_rates`: date, usd_krw DECIMAL(10,2), source. 하루 1행.
- `admin_checks`(상태 탭·봇 공용): id, run_at, key, status(ok/warn/fail), value, detail, source(page/bot).

### 2-2. 원가 기록 (백엔드)
- 공용 `app/costs/recorder.py`: `record_api_call(provider, model, kind, purpose, units, user_id, episode_id, cut_id, duration_ms, status, error_code)` → 단가표로 cost_usd 계산 → 그날 환율로 cost_krw → INSERT. 단가 없으면 cost NULL + status 그대로(화면에 "단가 미등록" 경고).
- 1단계 ①의 모든 호출부에 **성공·실패 양쪽** 기록. 이미지 호출은 quality·size도 units_json에.
- 환율: 매일 1회(스케줄러 또는 첫 요청 시 lazy) 무료 환율 API(예: frankfurter.app 또는 open.er-api.com, 키 불필요)에서 USD→KRW 받아 exchange_rates에 저장. 실패하면 마지막 행 사용, 행이 없으면 1,400 + 화면에 "환율 기본값 사용" 경고. 외부 호출은 타임아웃 3초.
- 과거 추정: `estimate_legacy_cost(purpose, model)` = generation_logs 1건당 단가표 기준 추정치(이미지 1장 + 검사 1회 등 docs/원가-트랙별.md 계산식). api_calls 기록 시작일 이전 구간에만 사용, 결과에 estimated=true.

### 2-3. 통계 API (`app/admin/stats_router.py`, admin 의존성)
공통 쿼리: `range=today|7d|30d|all|custom&from=&to=`. 응답에 `period`, `generated_at`, 각 숫자에 `source: measured|estimated|mixed`.
- `GET /admin/stats/money`: 매출(paid 합·건수·팩별), 환불(있으면), 판매 패킷·사용 패킷(reason별)·잔량 합·**패킷 부채**(잔량 합 × 기간 평균 판매 단가), API 원가 합(provider별·kind별), **패킷당 원가 = 원가 합 / 사용 패킷**, **트랙별 패킷당 원가**(purpose별 원가 / purpose별 차감 패킷), 마진율 = 1 − 패킷당 원가 / 기간 평균 판매 단가(판매 없으면 인기 팩 단가), 일별 시계열(매출·원가·사용 패킷).
- `GET /admin/stats/people`: 가입(일별), 활성(기간 내 생성 1회 이상), 결제 전환율(가입자 중 결제 1회 이상), 환영 패킷만 쓰고 결제 없음 비율, 첫 생성까지 걸린 시간 중앙값, 상위 사용자 10(사용 패킷·결제액·마지막 활동, 테스트 계정 표시).
- `GET /admin/stats/quality`: 트랙별 생성 성공/실패 건수·실패율, 재생성률(같은 cut version>1 비율), 카피 신고 건수·환불 패킷, 상세페이지 경고 배지 비율(빨강/주황/회색), 모션 성공률·평균 소요, 평균 생성 시간(api_calls duration), 검사(check_*) 재시도 비율.
- `GET /admin/stats/status`: `app/admin/checks.py`의 `run_all_checks(source="page")` 결과. 체크 목록(각각 독립 함수, 하나 실패해도 나머지 실행):
  - `disk`: 사용률(warn 80 / fail 90)
  - `backup`: ~/backups/ 최신 파일 24h 이내(warn 48h / fail 없음)
  - `failed_jobs`: 최근 24h 실패 생성·모션 건수(warn ≥3 / fail ≥10)
  - `packet_ledger`: 사용자별 balance vs packet_transactions 합 불일치 수(fail ≥1, 목록)
  - `api_errors`: 최근 24h api_calls status=error 건수·402/429/404 분리(fail: 402 또는 404 모델 폐기 패턴)
  - `inquiries`: 미답변 문의 수·최장 대기 시간(warn 24h / fail 72h)
  - `exchange_rate`: 오늘 환율 갱신 여부
  - `prices_missing`: 단가 미등록 model 목록
  - `apache_config`: Options -Indexes 3곳·루트 301 유지(curl로 ssagda.com/ 응답 코드·/WEBTOON/storage/ 디렉터리 목록 403 확인)
  - `model_smoke`(수동 버튼 전용, 자동 실행 금지): Gemini 텍스트 1회·비전 1회(작은 이미지)·GPT 이미지 1장 **low 품질 최소 크기**·omni는 호출하지 않고 api_calls 마지막 성공 시각만. 결과 api_calls에 purpose=check로 기록. 버튼 문구 "외부 모델 점검 · 약 N원".
  결과는 admin_checks에 저장(마지막 실행 비교용). 다음 지시서의 봇은 같은 함수를 cron으로 호출.
- `GET/PUT /admin/stats/prices`: 단가표 조회·수정(관리자). 수정 이력은 updated_at + 변경 전 값 note.

### 2-4. 프론트 (`/admin/stats`, AdminPage 탭 "통계" 추가)
- 상단: 기간 칩(오늘·7일·30일·전체·직접) + "마지막 갱신 HH:MM" + [새로고침].
- 탭 **돈**: 숫자 카드 6(매출 / 사용 패킷 / API 원가 / **패킷당 원가** / 마진율 / 패킷 부채) → 트랙별 표(건수·사용 패킷·원가·패킷당 원가·마진율) → 일별 막대(매출·원가 겹쳐서, 라이브러리 없이 CSS 막대) → provider별 원가 표 → 단가표 접기(수정 가능) + 환율 표시.
- 탭 **사람**: 숫자 카드(가입·활성·결제 전환·환영만 이탈) → 일별 가입 막대 → 상위 사용자 표.
- 탭 **품질**: 트랙별 성공/실패/재생성 표 → 경고 배지 비율 → 모션 → 카피 신고.
- 탭 **상태**: 체크 카드 목록(초록/노랑/빨강, 값·설명·마지막 실행) + [지금 점검](model_smoke 제외) + [외부 모델 점검 · 약 N원](인라인 확인 버튼 변환형) + 최근 7일 체크 이력 접기.
- "추정" 배지·"단가 미등록"·"환율 기본값" 경고 표시. 375에서도 카드 1열로 읽히게. 다크 톤 기존 관리자 화면과 동일.

## 3. 검증 (값·캡처)
① step40 운영 적용 후 테이블 4개 SHOW CREATE 요약. ② 테스트 계정 onecut ep159 컷 1장 재생성(1패킷) → api_calls에 이미지 1행 + 검사(비전) 행 생성, cost_krw 값·환율 행 확인 → 돈 탭 "패킷당 원가"가 그 값 반영(기간 오늘). ③ 과거 구간(30일) 돈 탭 "추정" 배지 + 숫자가 docs/원가-트랙별.md 추정과 ±20% 안인지. ④ 상태 탭 [지금 점검] 결과 카드 전부 ok/warn 사유 포함 캡처, admin_checks 행 생성. ⑤ [외부 모델 점검] 1회 실행(약 N원 표기 값 보고) → 3개 ok. ⑥ 단가표 값 하나 수정 → 저장 → 새로고침 유지 → 원복. ⑦ 비관리자 토큰으로 /admin/stats/money → 403. ⑧ 4탭 × 1280·375 캡처 8장, 콘솔 0. ⑨ 사용자 화면 회귀: onecut 1패킷(②와 겸함)·요금 페이지·내 작품 캡처 — 변화 없음.
