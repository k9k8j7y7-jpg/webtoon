## 1. Tailwind 설정 — 커스텀 색·폰트·다크모드

**설정 파일:** 별도 `tailwind.config.js` 없음 — Tailwind v4 + `@tailwindcss/vite` 플러그인(`vite.config.js`). 색·폰트는 `frontend/src/index.css`의 `@theme` 블록에서 CSS 변수로 정의.

**커스텀 색상 (index.css @theme):**
| 변수 | 값 | 용도 |
|---|---|---|
| `--color-primary` | `#FF5722` | 기본 액센트 |
| `--color-primary-dark` | `#E64A19` | 진한 액센트 |
| `--color-surface` | `#ffffff` | 라이트 배경 |
| `--color-surface-dark` | `#121212` | 다크 배경 |
| `--color-ink-black` | `#121212` | 본문 글자색 |
| `--color-comic-orange` | `#FF5722` | 1차 브랜드 |
| `--color-comic-blue` | `#2563EB` | 2차 브랜드 |
| `--color-border` | `#dfe4dc` | 라이트 테두리 |

**커스텀 폰트:** Pretendard(CDN), Playfair Display(Google), NanumBrush·NanumBisang·NanumNunchi·Chab·Jeongseon·Recipekorea·BMJUA (로컬 woff2)

**다크모드 설정:**
- `darkMode: 'class'` **미설정** — Tailwind v4 기본값(= `@media prefers-color-scheme`)으로만 동작
- `index.css`에 `@media (prefers-color-scheme: dark) { body { ... } }` 1건만 존재 (배경색·격자선 반전)
- **class 기반 토글 불가** — `<html class="dark">` 붙여도 Tailwind `dark:` 유틸이 작동하지 않음

**기존 `dark:` 클래스 사용 현황:**
- **잘 된 곳 (~60%):** Layout.jsx, ProjectPage.jsx, ExportProgressModal.jsx, DashboardPage.jsx, GateProgress.jsx — `dark:bg-zinc-900`, `dark:border-zinc-800`, `dark:text-zinc-300` 등 체계적
- **없는 곳 (~40%):** LandingPage.jsx(0건), ViewerPage.jsx(0건), Gate1~5 일부, LoginPage.jsx — 하드코딩 `#0A0F1D` + `border-white/10`

## 5. 다크 배경에서 깨질 수 있는 요소

### 🔴 CRITICAL — 구조적 문제

| 요소 | 파일 | 문제 |
|---|---|---|
| **SVG 말풍선 fill** | `BubbleOverlay.jsx` line 18-100+ | `round/thought/whisper/shout` 등 fill이 `rgba(255,255,255,0.95)` 하드코딩. 다크 배경 위 컷 이미지에 겹쳐지므로 **컷 자체가 어두운 장면일 때** 흰 말풍선과 어두운 글자의 대비가 떨어질 수 있음. 다만 말풍선은 이미지 위 오버레이이므로 앱 배경 다크와 직접 관계는 낮음 |
| **나레이션 말풍선** | `BubbleOverlay.jsx` narration | `fill: rgba(0,0,0,0.65)`, `textColor: #ffffff` — 다크 배경 앱에서 컷 밖으로 나레이션이 겹치면 검은색+흰글자가 배경과 합쳐져 경계 소실 |
| **SFX '흰색' 프리셋** | `CutEditor.jsx` line 55-61 | `{ color: '#ffffff', label: '흰색' }` — 라이트 배경 컷에서 이미 보이지 않는 문제 존재, 다크 배경에서는 편집 패널의 프리뷰가 안 보일 수 있음 |

### 🟠 HIGH — 페이지 단위 하드코딩

| 페이지 | 문제 |
|---|---|
| **LandingPage.jsx** | 전체 `#0A0F1D` 하드코딩 — "항상 다크" 설계. 라이트 모드 전환 시 완전히 깨짐. 반대로 앱 다크 모드에선 이미 다크이므로 문제 없음 |
| **ViewerPage.jsx** | 동일 `#0A0F1D` 하드코딩 (line 102, 121, 124). `border-white/10` 등 다크 전용 |
| **LoginPage.jsx** | 하드코딩 다크 배경 가능성 높음 (미확인) |

### 🟡 MEDIUM — 부분적 주의

| 요소 | 파일 | 세부 |
|---|---|---|
| **컷 이미지 컨테이너** | CutEditor, Gate5Review | 이미지 자체는 어두운 배경 위에서도 괜찮으나, 이미지 주변 패딩/보더가 `bg-white` 계열이면 "흰 프레임" 눈에 띔 |
| **내보내기 렌더러** | `exportRenderer.js` | 캔버스 기반 — 앱 다크와 무관(독립 캔버스), 문제 없음 |
| **PNG 말풍선** | `PngBubbleLayer.jsx` | PNG 이미지 자체가 흰 배경이면 다크에서 눈에 띔. 현재 카탈로그 5종이 투명 배경인지 확인 필요 |
| **Gate1~5 일부** | `gates/*.jsx` | 일부 `bg-[#0A0F1D]/50`, `border-white/10` 혼재 — 라이트 모드에서 깨짐 |
| **효과 PNG 오버레이** | `EffectLayer.jsx` | 카탈로그 10종이 투명 배경이면 OK, 흰 배경이면 다크에서 사각 흰 박스로 보임 |

### 핵심 판단

1. **앱을 "다크 전용"으로 갈 경우:** LandingPage·ViewerPage는 이미 다크이므로 문제 없고, ProjectPage·Layout 등 `bg-white` 쓰는 곳만 다크로 전환하면 됨. 말풍선 fill은 컷 이미지 위 오버레이이므로 앱 배경과 직접 충돌 낮음
2. **라이트/다크 토글을 넣을 경우:** `darkMode: 'class'` 설정 필수 + LandingPage·ViewerPage의 하드코딩 `#0A0F1D`를 CSS 변수화 필요 + 말풍선 fill도 테마 대응 필요
3. **모바일 우선이라면:** 현재 하드코딩 다크 페이지(Landing·Viewer)는 모바일에서 이미 다크이므로, ProjectPage·Gate·편집기 계열만 다크 대응하면 "모바일 다크" 1차 완성 가능
