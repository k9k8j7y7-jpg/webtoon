### 반드시 지킬 것

## 3. 모양 명세 — 12종

각 모양은 **하나의 `<path>`로 본체와 꼬리를 합쳐서** 그린다. 1단계에서 round에 적용한 단일 path 구조를 그대로 확장한다. 본체와 꼬리를 별도 도형으로 그리면 이음새에 선이 생긴다.

### 3-1. `round` (기본)

가로로 넓은 타원. 1단계에서 이미 구현됨.

**변경할 것: 꼬리를 4절의 타입 A(낫형)로 교체.**

현재 꼬리는 이등변삼각형이라 참고 이미지와 다르다. 상세 명세는 **4절 꼬리 명세** 참조.

---

### 3-2. `narration` (나레이션)

둥근 모서리 사각형. 모서리 반경은 폭의 8% 정도(참고 이미지 기준으로 조정).
꼬리는 **타입 C**(4절 참조). 12종 중 유일하게 좌우 대칭인 꼬리다.

⚠️ **주의:** 백엔드 정의상 `narration`은 `isCaption`이며, 폭이 `bubbleW` 고정이다. 1단계에서 이미 그렇게 동작한다. 이 동작을 유지하라.

---

### 3-3. `thought` (생각)

구름 본체 + 원형 점 꼬리.

**본체:** 위쪽에 큰 원 3개, 좌우에 중간 원 2개, 아래에 완만한 곡선. 참고 이미지는 위쪽 굴곡이 크고 아래쪽은 상대적으로 완만하다.

**구현 방법:** 여러 개의 원을 겹치는 방식이 아니라, 하나의 path에서 `A`(호) 또는 `C`(3차 베지어) 명령을 이어붙여 구름 윤곽을 그린다. 원을 여러 개 그리면 겹친 부분의 stroke가 보인다.

**꼬리:** **타입 D**(원 2개). 4절 참조.

---

### 3-4. `whisper` (속삭임)

얇은 선의 타원 + 원형 점 꼬리.

**본체:** `round`와 같은 타원이지만 stroke가 얇고 점선(dash). 백엔드 정의에 `#999 dash`로 되어 있으니 `strokeDasharray`를 적용한다.

**꼬리:** **타입 D**(원 2개). `thought`보다 원이 작다. 4절 참조.

---

### 3-5. `shout` (외침)

촘촘한 지그재그 스파이크.

**본체:** 12~14개의 뾰족한 돌기. 참고 이미지는 돌기가 촘촘하고 규칙적이며 각도가 날카롭다.

**구현:**
```js
// 각도를 등분하고 바깥/안쪽 반지름을 번갈아 사용
const spikes = 13;
for (let i = 0; i < spikes * 2; i++) {
  const angle = (Math.PI * i) / spikes;
  const r = (i % 2 === 0) ? outerR : innerR;
  // rx, ry에 각각 비율 적용해 타원형 스파이크로
}
```
- `innerR / outerR` 비율은 0.78 정도. 참고 이미지와 비교해 조정.
- 돌기 끝은 뾰족하게(직선 연결), 안쪽 골도 뾰족하게.

**꼬리:** **타입 B**(직선 침형). 12종 중 가장 길다. 4절 참조.

⚠️ 꼬리는 돌기 끝이 아니라 **돌기 사이 골에서** 뻗어나온다. 참고 이미지에서 확인할 것.

### 3-6. `angry` (화남)

⚠️ **참고 이미지가 `외침.jpg`와 완전히 동일하다.** 색상(분홍 vs 흰색)으로 구분되므로 실사용엔 문제없지만, 모양에도 미세한 차이를 준다.

**`shout`와의 차이:**
- 돌기 개수를 더 늘린다 (15~16개)
- `innerR / outerR` 비율을 더 낮춘다 (0.70 정도) → 돌기가 더 깊고 날카로움
- 돌기 각도를 약간 불규칙하게 (각 돌기의 반지름에 ±5% 랜덤이 아닌 **결정적** 변주. 예: `i % 3`에 따라 미세 조정). 랜덤을 쓰면 리렌더마다 모양이 바뀌므로 금지.

**꼬리:** **타입 B**. `shout`와 동일하되 길이만 약간 짧다. 4절 참조.

### 3-7. `happy` (기쁨)

뭉게구름.

**본체:** 원 6~7개가 겹친 형태. 위쪽 3개가 크고, 좌우 2개가 중간, 아래쪽 2개가 작다. 참고 이미지는 전체적으로 둥글고 폭신한 인상.

**구현:** `thought`와 마찬가지로 하나의 path에서 호를 이어붙인다.

**꼬리:** **타입 B**(직선 침형). 짧고 뾰족. 4절 참조.

---

### 3-8. `sad` (슬픔)

뭉게구름. `happy`와 형태가 유사하다.

**`happy`와의 차이:**
- 굴곡 개수를 하나 줄인다 (5~6개)
- 아래쪽 굴곡을 더 완만하게 → 처진 인상
- 전체 세로 비율을 약간 높인다 (같은 폭에서 조금 더 세로로 긴 형태)

색상(연파랑)으로 이미 구분되므로 과하게 다르게 만들 필요는 없다.

**꼬리:** **타입 B**(직선 침형). 4절 참조.

---

### 3-9. `surprised` (놀람)

큰 스파이크.

**`shout`와의 차이가 명확해야 한다.** 참고 이미지를 보면:
- 돌기 개수가 훨씬 적다 (7~9개)
- 돌기 하나하나가 크고, 끝이 뾰족하되 **골 부분이 둥글게 파인다**
- `shout`가 톱니라면 `surprised`는 별/폭발에 가깝다

**구현:** 돌기 끝은 직선으로 뾰족하게, 돌기 사이 골은 `Q`(2차 베지어)로 둥글게 파이도록 한다.

**꼬리:** **타입 A**(낫형). 12종 중 휨이 가장 크다. 참고 이미지의 꼬리는 초승달처럼 깊게 휘어 있다. 4절 참조.

---

### 3-10. `shy` (부끄)

기울어진 사각형.

**본체:** 참고 이미지는 위쪽 변이 오른쪽으로 올라간 사다리꼴이다. 좌하단이 살짝 좁아진다. 모서리는 둥글다(반경 폭의 6% 정도).

**구현:** 네 꼭짓점을 잡고 각 모서리를 `Q`로 둥글게 잇는다.
```
좌상단: (x + w*0.03, y + h*0.12)
우상단: (x + w*0.97, y)
우하단: (x + w*0.95, y + h)
좌하단: (x, y + h*0.90)
```
비율은 참고 이미지와 비교해 조정한다.

**꼬리:** **타입 B**(직선 침형). 4절 참조.

---

### 3-11. `flustered` (당황)

둥근 사각형. 모서리 반경이 크다 (참고 이미지는 거의 알약에 가까울 정도로 둥글다. 폭의 12% 정도).

**`narration`과의 차이:** `narration`보다 모서리가 훨씬 둥글고, 유채색이며, 꼬리가 아래 **오른쪽**에 붙는다.

**꼬리:** **타입 A**(낫형). 12종 중 가장 작다. 4절 참조.

---

### 3-12. `realize` (깨달음)

위쪽만 구름, 아래는 완만한 형태.

**본체:** 참고 이미지는 위쪽에 굴곡 3~4개가 있고, 아래쪽은 둥근 사각형에 가깝게 평평하다. `happy`/`sad`가 사방이 구름인 것과 대비된다.

**구현:**
- 위쪽 변: 호 3~4개를 이어 구름 굴곡
- 좌우 변: 완만한 곡선
- 아래쪽 변: 거의 직선에 가까운 완만한 곡선, 양끝만 둥글게

**꼬리:** **타입 B**(직선 침형). 12종 중 치우침이 가장 작아 거의 수직에 가깝다. 4절 참조.

## 4. 꼬리 명세

참고 이미지의 꼬리는 하나의 형태가 아니다. **네 가지 타입**으로 갈린다. 스타일마다 어느 타입인지, 파라미터가 얼마인지 아래 표에 정의한다.

### 4-0. 좌표계 — 반드시 먼저 읽을 것

⚠️ **참고 이미지의 꼬리는 전부 `tail_direction = "down"` 상태다.** 하지만 사용자는 편집 모드에서 방향을 `up`/`down`/`left`/`right`로 바꾸고 `flipTail`도 켤 수 있다.

따라서 꼬리 모양을 **절대 좌표(왼쪽 아래 등)로 하드코딩하지 마라.** 진행 방향 기준의 **로컬 좌표계**로 정의하고, 방향에 따라 회전시킨다.

```
로컬 좌표계 정의:
  기준각 θ₀ = 진행 방향
    down  →  90°
    up    → -90°
    left  → 180°
    right →   0°

  치우침(skew) = 기준각에서 시계 반대 방향으로 더할 각도
  flipTail = true 이면 치우침 부호를 뒤집는다
```

즉 "왼쪽 아래로 치우침"은 `down` 기준에서 **치우침 +20°** 로 표현한다. 방향이 `right`로 바뀌면 같은 +20°가 자동으로 "오른쪽 위 치우침"이 된다.

밑변 두 점은 본체 윤곽선 위에서 구한다. 타원 계열이면:
```
x = cx + rx * cos(θ)
y = cy + ry * sin(θ)
```
사각형·구름·스파이크 계열은 해당 도형의 윤곽선 위에서 같은 각도의 교점을 구한다.

**밑변 두 점은 본체 안쪽으로 3~5px 당긴다.** 1단계에서 확인된 대로, 그래야 본체와 꼬리가 하나의 path로 합쳐질 때 이음새가 보이지 않는다.

---

### 4-1. 타입 A — 낫형 (갈고리)

**적용:** `round`, `surprised`, `flustered`

참고 이미지 `기본.jpg`가 대표적이다. 특징:
- **바깥쪽 변은 직선**으로 길게 뻗는다
- **안쪽 변은 안으로 휘어 들어온다** → 끝이 갈고리처럼 꺾여 보인다
- 밑변이 넓고 끝으로 갈수록 급격히 좁아진다
- 끝점이 밑변 중점의 수직 방향이 아니라 치우쳐 있다

```
path: M(밑변점1) L(끝점) Q(제어점) (밑변점2) Z
```

- `밑변점1 → 끝점`: 직선 (바깥쪽 변)
- `끝점 → 밑변점2`: 2차 베지어 (안쪽 변)
- 제어점은 `끝점`과 `밑변점2`를 잇는 직선의 중점에서, **본체 중심 쪽으로** 당긴 위치

```js
const mid = midpoint(tip, base2);
const ctrl = lerp(mid, center, curveAmount);
```

**파라미터**

| 스타일 | 밑변 폭 | 길이 | 치우침 | 휨(curveAmount) |
|---|---|---|---|---|
| `round` | ±0.22 rad | 본체 높이 × 0.35 | +22° | 0.40 |
| `surprised` | ±0.20 rad | 본체 높이 × 0.42 | −28° | 0.62 |
| `flustered` | ±0.16 rad | 본체 높이 × 0.20 | −18° | 0.35 |

- **밑변 폭**: 기준각에서 좌우로 벌리는 각도. `±0.22 rad`이면 `θ₀+skew` 기준 −0.22 ~ +0.22
- **치우침**: 양수 = 시계 반대 방향
- **휨**: 0이면 직선 삼각형, 클수록 갈고리가 깊어짐

⚠️ `surprised`는 참고 이미지에서 꼬리가 초승달처럼 깊게 휘어 있다. 휨을 가장 크게 준다.

---

### 4-2. 타입 B — 직선 침형

**적용:** `happy`, `sad`, `realize`, `shy`, `shout`, `angry`

참고 이미지 `기쁨.jpg`, `외침.jpg`가 대표적이다. 특징:
- 좁고 뾰족한 침 모양
- 양쪽 변이 거의 직선 (타입 A처럼 갈고리로 꺾이지 않는다)
- 밑변이 좁다
- 길이는 스타일마다 크게 다르다

```
path: M(밑변점1) L(끝점) L(밑변점2) Z
```

단순 삼각형이되, 밑변이 좁고 길이가 길어 침처럼 보인다.

**파라미터**

| 스타일 | 밑변 폭 | 길이 | 치우침 |
|---|---|---|---|
| `happy` | ±0.10 rad | 본체 높이 × 0.22 | +16° |
| `sad` | ±0.10 rad | 본체 높이 × 0.22 | −16° |
| `realize` | ±0.09 rad | 본체 높이 × 0.18 | +6° |
| `shy` | ±0.11 rad | 본체 높이 × 0.24 | +14° |
| `shout` | ±0.08 rad | 본체 높이 × 0.48 | +26° |
| `angry` | ±0.08 rad | 본체 높이 × 0.40 | +26° |

⚠️ **`shout` / `angry` 주의:** 꼬리가 스파이크 돌기 끝이 아니라 **돌기 사이 골에서** 뻗어나온다. 밑변 두 점을 잡을 때 스파이크의 안쪽 반지름(`innerR`) 기준 윤곽선을 써라. 바깥 반지름 기준으로 잡으면 꼬리가 돌기에 얹힌 것처럼 보인다.

⚠️ **`realize` 주의:** 참고 이미지에서 거의 수직에 가깝다. 치우침을 가장 작게 준다.

### 4-3. 타입 C — 대칭 삼각형

**적용:** `narration`

참고 이미지 `나레이션.jpg`. 12종 중 유일하게 **좌우 대칭**인 꼬리다. 자막이라 치우침이 없어야 자연스럽다.

```
path: M(밑변점1) L(끝점) L(밑변점2) Z
```

| 파라미터 | 값 |
|---|---|
| 밑변 폭 | 본체 폭 × 0.09 (각도가 아니라 **절대 폭**) |
| 길이 | 본체 높이 × 0.16 |
| 치우침 | 0° (고정) |

`narration`은 사각형이므로 밑변을 각도가 아니라 아래 변 위의 좌표로 직접 잡는다. 아래 변 중앙에서 좌우로 `본체 폭 × 0.045`씩.

⚠️ `flipTail`을 적용하지 마라. 대칭이라 의미가 없다.

### 4-4. 타입 D — 원 2개

**적용:** `thought`, `whisper`

참고 이미지 `생각.jpg`, `속삭임.jpg`. 삼각형 꼬리가 아니라 **원 2개**가 본체에서 멀어지며 작아진다.

본체 path와 **합치지 말고 별도 도형으로** 그린다. 본체와 떨어져 있는 것이 정상이다.

```
큰 원  중심: 본체 윤곽선 위의 점에서 진행 방향으로 gap₁ 만큼 떨어진 위치
작은 원 중심: 큰 원 중심에서 진행 방향으로 gap₂ 만큼 더 떨어진 위치
```

| `thought` | 본체 높이 × 0.09 | 큰 원 × 0.58 | 본체 높이 × 0.07 | 본체 높이 × 0.10 | +24° |

- 두 원 모두 본체와 동일한 `fill` / `stroke` / `strokeWidth`
- `whisper`는 본체가 점선(dash)이지만 **꼬리 원은 실선**이다. 참고 이미지 확인.

### 4-5. 공통 헬퍼 구조

타입별로 함수를 나눈다. 하나의 거대한 분기문으로 만들지 마라.

```js
// 방향 → 기준각 변환 (공통)
function tailBaseAngle(tailDirection) { ... }

// 본체 윤곽선 위의 점 (도형 종류별)
function pointOnOutline(shapeKind, cx, cy, rx, ry, theta) { ... }

// 타입별 path 생성
function buildTailA(geo, params) { ... }   // 낫형
function buildTailB(geo, params) { ... }   // 직선 침형
function buildTailC(geo, params) { ... }   // 대칭 삼각형
function buildTailD(geo, params) { ... }   // 원 2개 → JSX element 배열 반환
```

`BUBBLE_CONFIGS`에 스타일별로 꼬리 설정을 넣는다.

```js
round: {
  // ...색상...
  tail: {
    type: 'A',
    baseSpread: 0.22,
    length: 0.35,
    skewDeg: 22,
    curveAmount: 0.40,
  },
},
narration: {
  tail: { type: 'C', baseWidthRatio: 0.09, length: 0.16, skewDeg: 0, noFlip: true },
},
thought: {
  tail: { type: 'D', r1: 0.09, r2Ratio: 0.58, gap1: 0.07, gap2: 0.10, skewDeg: 24 },
},
```

### 4-6. 파라미터는 출발점이다

위 수치는 참고 이미지를 눈으로 재서 뽑은 값이다. **화면에서 참고 이미지와 나란히 놓고 비교해 조정하라.** 특히 다음을 확인한다.

- 꼬리가 본체와 하나의 윤곽선으로 이어지는가 (타입 A·B·C)
- 꼬리가 본체와 적당히 떨어져 있는가 (타입 D)
- 꼬리 끝이 충분히 뾰족한가
- 말풍선이 작을 때 꼬리가 과하게 크지 않은가
- 방향을 `up`/`left`/`right`로 바꿔도 형태가 유지되는가
- `flipTail`을 켜면 치우침이 반대로 뒤집히는가

## 5. 텍스트 여백 — 종류별 안쪽 영역

모양이 복잡할수록 글자가 테두리에 걸린다. 종류별로 안쪽 텍스트 영역 비율을 정의한다.

`BUBBLE_CONFIGS`에 각 스타일별로 `insetX`, `insetY`를 추가한다. 텍스트 블록은 이 비율만큼 안쪽으로 들어간 영역 안에만 배치된다.

| 스타일 | insetX | insetY | 이유 |
|---|---|---|---|
| `narration` | 0.06 | 0.08 | 사각형, 여백 적어도 됨 |
| `flustered` | 0.08 | 0.10 | 둥근 사각형 |
| `shy` | 0.10 | 0.12 | 사다리꼴 |
| `round` | 0.12 | 0.14 | 타원 |
| `whisper` | 0.12 | 0.14 | 타원 |
| `realize` | 0.14 | 0.16 | 위쪽만 굴곡 |
| `thought` | 0.16 | 0.18 | 구름 굴곡 |
| `happy` | 0.16 | 0.18 | 구름 굴곡 |
| `sad` | 0.16 | 0.18 | 구름 굴곡 |
| `surprised` | 0.18 | 0.20 | 스파이크 깊음 |
| `shout` | 0.20 | 0.22 | 스파이크 촘촘하고 깊음 |
| `angry` | 0.20 | 0.22 | 스파이크 가장 깊음 |

**적용 방식:**
```
텍스트 영역 폭 = needW * (1 - insetX * 2)
텍스트 영역 높이 = needH * (1 - insetY * 2)
```
이 값은 1단계의 `PADDING_X`, `PADDING_Y`와 **별개로 추가 적용**된다. PADDING은 그대로 두고 inset을 더한다.

역으로, 텍스트가 주어졌을 때 필요한 말풍선 크기를 구할 때도 inset을 역산해야 한다:
```
needW = (텍스트 블록 폭 + PADDING_X * 2) / (1 - insetX * 2)
needH = (텍스트 블록 높이 + PADDING_Y * 2) / (1 - insetY * 2)
```

⚠️ 1단계에서 타원 스타일에 적용한 `ovalScale`(2줄 이하 1.42 / 3줄 이상 1.55)은 **이 inset 방식으로 대체한다.** 두 방식을 동시에 적용하면 말풍선이 과도하게 커진다. `ovalScale` 로직은 제거하고 inset으로 통일하라.

단, 제거 후 3줄 텍스트가 다시 넘치면 해당 스타일의 `insetY`를 올려서 맞춘다.

## 6. 텍스트 세로 중앙 정렬 검증

현재 일부 말풍선에서 텍스트가 위쪽에 몰리고 아래에 빈 공간이 생긴다.

**원인 추정:** `needH`를 확대한 뒤(ovalScale) 텍스트 블록의 세로 중심을 **확대 전 높이** 기준으로 잡고 있을 가능성.

**수정:** 텍스트 블록의 세로 중심이 항상 말풍선 본체의 세로 중심과 일치하도록 한다.
```
텍스트 블록 중심 Y = by + needH / 2
텍스트 블록 시작 Y = 텍스트 블록 중심 Y - (줄수 * 줄높이) / 2
```

가로도 동일하게 `bx + needW / 2` 기준으로 중앙 정렬한다.

**꼬리는 이 계산에서 제외한다.** 꼬리가 아래로 뻗는다고 해서 텍스트가 위로 밀리면 안 된다.

## 7. 텍스트 위치 사용자 조절 — 데이터 구조와 렌더링만

편집 모드에서 사용자가 말풍선 안 텍스트 위치를 직접 조절할 수 있게 한다.

⚠️ **이번 단계에서는 렌더링 지원과 데이터 구조까지만 만든다. 조절 UI는 만들지 마라.** 편집 모드 진입이 `Gate5Review.jsx`(3단계)에 달려 있어 지금은 테스트가 불가능하다. UI는 4단계에서 붙인다.

### 데이터 구조

`cuts.spec`의 `dialogue[].bubble_layout`에 두 필드를 추가한다.

```jsonc
"bubble_layout": {
  "x": 0.3,
  "y": 0.1,
  "width": 0.45,
  "tail_direction": "down",
  "tail_flip": false,
  "font_scale": 1.0,
  "text_offset_x": 0,    // 신규. -0.5 ~ 0.5. 말풍선 폭 대비 비율
  "text_offset_y": 0     // 신규. -0.5 ~ 0.5. 말풍선 높이 대비 비율
}
```

- 기본값은 둘 다 `0` (= 정중앙)
- 값이 없으면 `0`으로 간주 (기존 데이터 호환)
- 백엔드 스키마 변경은 하지 마라. `bubble_layout`은 JSON 필드이므로 추가 필드가 그대로 저장된다.

### 렌더링 적용

5절의 중앙 정렬 계산에 오프셋을 더한다.

```
텍스트 블록 중심 X = bx + needW / 2 + (text_offset_x * needW)
텍스트 블록 중심 Y = by + needH / 2 + (text_offset_y * needH)
```

`SingleBubble`에 `textOffsetX`, `textOffsetY` prop을 추가한다. 기본값 `0`.
`BubbleOverlay` 메인 컴포넌트에서 `item.bubble_layout.text_offset_x/y`를 읽어 전달한다.
`computeSingleBubbleGeo`에도 동일하게 반영한다.

**오프셋이 텍스트를 말풍선 밖으로 밀어낼 수 있다.** 이번 단계에서는 클램프하지 마라. 4단계 UI에서 슬라이더 범위로 제한한다.
