# 지시서 — 관리자 페이지 (운영 콘솔)

> Claude Code에게: EziToon 운영 작업(갤러리 노출, 패킷, 공지, 상품
> 가격)을 도도가 화면에서 직접 처리하는 내부용 관리자 페이지 지시서다.
> **지금은 1단계만 구현한다. 2~5단계는 전체 파악용으로만 읽고, 각
> 단계는 이전 단계 완료 + 도도의 승인 후 시작한다.**

## 공통 규칙
- 각 단계 완료 시 멈추고 보고. 커밋은 도도 확인 후
- 파괴적 git 금지. 마이그레이션은 project_t_test 리허설 → 백업 →
  "실행해" 승인 후 운영 적용
- 기존 사용자 기능 회귀 금지
- **보안이 최우선**: 관리자 API는 전부 백엔드에서 is_admin 검증.
  프론트에서 메뉴를 숨기는 것만으로는 절대 보호로 치지 않는다.
  관리자가 아닌 계정의 /admin 접근·API 호출은 403

## 설계 개요
- 경로: /admin (로그인 + is_admin=true 계정만)
- 권한: users에 is_admin 컬럼(step22), 도도 구글 계정(id=3)만 true로
  초기 지정
- UI는 기능 위주로 간결하게 — 기존 대시보드 스타일 재사용, 화려할
  필요 없음. 왼쪽 메뉴(대시보드/갤러리/패킷/공지/상품) + 콘텐츠 영역
- 랜딩·사용자 화면에는 /admin 진입점을 노출하지 않는다 (주소 직접
  입력으로만 접근)

## 단계 구성
1. 권한 + 뼈대 + 운영 대시보드
2. 갤러리 노출 관리
3. 패킷 운영 (지급 / 주문 정리)
4. 공지 관리
5. 상품·가격 관리 (products DB 이전)
※ 효과 PNG 업로드는 카탈로그 프론트 코드(effectCatalog.js)의 DB
이전이 필요한 별도 공사라 이 지시서 범위 외 (추후 판단)

## 1단계 — 권한 + 뼈대 + 운영 대시보드 (지금 할 작업)

1. step22.sql: users.is_admin BOOLEAN DEFAULT FALSE + id=3 true 지정
   (+ down 스크립트). 리허설·백업 후 보고 → 승인 후 운영 적용
2. 백엔드: require_admin 의존성(미검증 시 403) + GET /admin/stats
   - 통계: 전체 회원 수, 오늘 가입 수, 오늘 이미지 생성 수, 패킷
     판매 누계(원), 오늘 갤러리 조회수 합
3. 프론트: /admin 라우트 + 레이아웃(왼쪽 메뉴 + 콘텐츠) + 대시보드
   화면(위 통계 카드). 비관리자·비로그인 접근 시 404 또는 홈으로
4. 보고 후 대기. 도도가 /admin 접속 테스트 (관리자 계정 + 일반 계정
   양쪽)

## 2단계 — 갤러리 노출 관리 (승인 후)
- 에피소드 목록 테이블: 제목, 프로젝트, 게이트 상태, 현재 showcase
  여부·카테고리, 조회수·좋아요
- 행마다: 노출 ON/OFF 토글 + 카테고리 선택(단편/연작/광고) + 공개
  URL 복사 버튼
- 검색/필터(프로젝트별) 정도면 충분

## 3단계 — 패킷 운영 (승인 후)
- 회원 목록(닉네임, provider, 가입일, 패킷 잔량) + 검색
- 회원 선택 → 패킷 지급/차감 (수량 + 사유 입력, packet_transactions
  reason=admin_grant 기록) — 기존 admin_grant.py 로직 재사용
- 주문 목록(상태 필터) + 오래된 pending 일괄 만료 처리 버튼
  (만료는 상태 변경만, 삭제 금지)

## 4단계 — 공지 관리 (승인 후)
- 공지 목록 + 등록/수정 폼(내용, type, 활성 여부, 기간)
- 활성 공지는 1건 원칙 — 새 공지 활성화 시 기존 활성 공지 자동
  비활성 (또는 명확한 안내)
- 등록 즉시 사용자 공지 바에 반영되는지 확인 포함

## 5단계 — 상품·가격 관리 (승인 후)
- products.py 정의를 packet_products 테이블로 이전 (step23,
  마이그레이션 원칙 준수. 결제 승인 검증이 DB 가격 기준으로
  동작하는지 반드시 확인 — 가격 변경이 진행 중 주문에 영향 없게
  주문 생성 시점 가격 스냅샷 유지)
- 관리자 화면: 상품 목록 + 가격/패킷 수/노출 여부 수정
- 가격 변경 이력이 남으면 좋음 (간단한 로그 수준)
