# 지시서 — 게이트1 개편: 아이디어 → 기획서

> 대상: 단편·광고 타입만 (연작은 2-A 개요 층이 별도라 이번 범위 밖)
> 원칙: 0단계 조사 보고 → 도도 승인 → 1~3단계 순서대로, 단계마다 멈추고
> 보고. 커밋은 도도 실서버 검증 후. 마이그레이션은 가능하면 피하고
> gate_status JSON 활용 — 새 컬럼이 꼭 필요하면 stepNN 원칙(리허설 DB →
> 백업 → "실행해").
> 항목마다 [근거] 표시: 도도 요청 / 도도가 겪은 문제 / Claude 제안

## 배경

도도가 ep31·ep32에서 확인: 아이디어 칸에 "제목 / 한 줄 소개 / 등장
캐릭터 / 이야기(기승전결) / 톤" 형태의 구조화된 텍스트를 넣으니 대본이
의도대로 거의 그대로 나옴. 지금은 사용자가 이 구조를 스스로 만들어야
하므로, AI가 대신 만들어주고 사용자는 고치기만 하게 한다.

핵심 원칙: **빈칸을 채우게 하지 말고, 채워진 걸 고치게 한다.** AI가 미리
채운 값은 전부 사용자가 수정·삭제·추가 가능.

## 목표 흐름 (사용자 눈에 보이는 순서)

1. **새 단편 모달**: 제목(자유 입력) + 이야기(대략적인 내용, 몇 줄)
   → [만들기] → 게이트1로 이동
2. **게이트1 상단 "아이디어 정리" 카드**: 진입 시 자동으로 AI가 이야기를
   펼침 → 한 줄 소개 / 등장 캐릭터(이름·특징) / 이야기(기·승·전·결 4칸)
   / 톤. 각 칸 직접 수정 가능 + "이렇게 바꿔줘" 한 줄로 재정리
3. **게이트1 설정**: 장르·분위기·전개는 AI 추천값이 미리 선택돼 있고
   변경 가능. 등장인물 칸은 기획서의 캐릭터로 미리 채워져 있고 수정·
   삭제·추가 가능. [자동 생성]은 "기획서 기준으로 다시 뽑기"
4. **[기획 생성]** → 제목 / 로그라인 / 시놉시스(기·승·전·결 4단 표시) /
   등장인물 → 기존처럼 수정 → [기획 승인 → 다음 단계]
5. **읽기 전용(게이트2 이후 되돌아왔을 때)**: 입력값 전부(이야기·정리된
   기획서·장르·분위기·전개·등장인물) + 기획 결과가 다 보임

---

## 0단계 — 조사 (코드 수정 금지)

1. 새 에피소드 모달: 파일, 입력 필드, 생성 API, 아이디어 저장 컬럼/키
2. 게이트1 컴포넌트·저장 구조: 아이디어·예시·장르·분위기·전개·등장인물
   각각 어디에 저장되는지(컬럼 vs gate_status JSON), [등장인물 자동 생성]
   API·프롬프트, [기획 생성] API·프롬프트(입력 필드), 결과(제목·로그라인·
   시놉시스·등장인물) 저장 위치
3. 게이트1 등장인물 → 게이트3 캐릭터 시트 연결 방식
4. 읽기 전용 뷰 컴포넌트, 현재 표시 항목, 입력값이 DB에 남아 있는지
5. 대본 생성 프롬프트가 기획 결과 중 어떤 필드를 쓰는지 — 시놉시스를
   기승전결 4단 구조로 바꿀 때 영향 범위
6. 텍스트 LLM 공통 헬퍼("이렇게 바꿔줘" 재작성 경로 포함) — 새 프롬프트를
   같은 방식으로 추가 가능한지
7. 광고 타입(is_ad)일 때 게이트1이 지금 어떻게 다른지 (제품 관련 입력
   유무)

보고: 항목별 파일·줄·현재 동작, 새 컬럼 필요 여부, 예상 수정 파일 수.
**보고 후 승인 받고 1단계 진행.**

## 1단계 — 아이디어 정리 (백엔드 + 게이트1 상단 카드)

[근거: 도도 요청 — ep31·32 검증 결과]

### 1-1. 저장 구조
- gate_status JSON에 `idea_brief` 객체 추가 (새 컬럼 없이):
  ```
  idea_brief: {
    raw: "사용자가 모달에 쓴 원문",
    summary: "한 줄 소개",
    characters: [{name, description}],
    story: {ki, seung, jeon, gyeol},
    tone: "톤 한 줄",
    suggested: {genre, mood, structure},   // 장르·분위기·전개 추천값
    generated_at: ISO
  }
  ```
- 기존 아이디어 텍스트 필드는 `raw`로 흡수. 기존 에피소드(idea_brief
  없음)는 예전 UI 그대로 동작해야 함 — 폴백 필수

### 1-2. API
- `POST /episodes/{id}/idea-brief` : raw(+선택 hint) → LLM → idea_brief
  저장·반환. 텍스트라 패킷 무료. 실패 시 기존 자동 재시도 UX 적용
- hint가 있으면 "이렇게 바꿔줘" 재정리(기존 idea_brief를 기준으로 hint
  반영)
- `PUT /episodes/{id}/idea-brief` : 사용자가 칸을 직접 고친 값 저장

### 1-3. 프롬프트 (한국어 출력, JSON 반환)
- 입력: raw, 에피소드 타입(단편/광고), 광고면 제품명·특징
- 출력: summary(1문장), characters(2~5명, 이름+특징 한 줄, 동물이면
  종·색·특징), story(기승전결 각 1~3문장, 단편 완결 — 예고식 결말 금지),
  tone(1문장), suggested(장르·분위기·전개는 기존 선택지 값 중에서만)
- 광고 타입: story 안에 제품이 자연스럽게 쓰이는 장면을 반드시 포함,
  노골적 광고 문구 금지 (기존 AD_SCRIPT_INSTRUCTION_ADDON 원칙과 동일)
- 사용자가 raw에 이미 구조화해서 썼으면(제목:·기승전결 등 포함) 그 구조를
  존중해서 정리만

### 1-4. UI — 게이트1 상단 "아이디어 정리" 카드
- 카드 위: 원문(raw) 접이식 표시 (수정 가능, 수정 후 [다시 정리])
- idea_brief 없으면 진입 시 자동 호출 → 로딩 표시 "이야기를 정리하고
  있어요" → 결과 표시
- 칸 5개: 한 줄 소개 / 등장 캐릭터(행 추가·삭제) / 이야기 기·승·전·결
  (4개 textarea) / 톤 — 전부 inline 편집, blur 시 PUT 저장
- 하단: "이렇게 바꿔줘" 입력 + [다시 정리] (기존 대본 편집의 재작성 UI
  패턴 그대로)
- 기존 "아이디어 예시" 3개는 모달의 placeholder/힌트로 이동, 게이트1에서
  제거

### 1-5. 새 단편 모달
- 필드: 제목 / 이야기(textarea, placeholder에 예시 3개 중 1개 + "대략
  적어도 돼요. AI가 기획서로 정리해 드려요")
- 저장 시 idea_brief.raw에 기록, 게이트1 진입 시 자동 정리

**완료 후 보고 → 도도 검증(테스트 프로젝트 새 단편 1개, 패킷 0) → 커밋**

## 2단계 — 설정 미리 채움 + 기획 생성 연결

[근거: 도도 요청 — "자동으로 선택돼 있되 사용자가 바꿀 수 있게"]

### 2-1. 장르·분위기·전개
- idea_brief.suggested 값으로 미리 선택. 사용자 변경 가능. 사용자가
  바꾼 값이 우선(재정리해도 사용자 선택은 덮어쓰지 않음 — 사용자가
  직접 바꾼 적 있는지 플래그 `user_touched`로 관리)

### 2-2. 등장인물
- idea_brief.characters로 미리 채움(이름·설명, 성별·나이는 AI가 추정
  가능하면 채우고 아니면 빈칸). 수정·삭제·직접 추가 가능
- [자동 생성] → "기획서 기준으로 다시 뽑기"로 동작(idea_brief 입력)
- 기존 에피소드(idea_brief 없음)는 예전 동작 유지

### 2-3. [기획 생성]
- 입력에 idea_brief 전체 + 사용자가 확정한 장르·분위기·전개·등장인물 포함
- 출력 시놉시스를 `{ki, seung, jeon, gyeol}` 4단 구조로 (조사 5번 결과에
  따라 대본 프롬프트가 문자열을 기대하면, 저장은 4단 + 대본에 넘길 땐
  합친 문자열로 호환 유지)
- 결과 화면: 시놉시스를 기·승·전·결 소제목으로 표시, 각 단 수정 가능
- 제목은 사용자가 모달에 쓴 걸 기본으로, AI 추천 제목은 옆에 작게
  "추천: ○○○ [적용]"

**완료 후 보고 → 도도 검증(같은 테스트 단편으로 기획 생성 → 대본 생성까지,
패킷 0) → 커밋**

[근거: 도도가 겪은 문제 — 게이트2에서 돌아오면 입력값이 안 보임]
