# 지시서 — 모션 웹툰 1단계 (컷 이미지 → 3초 루프 영상)

> 원칙: 단계마다 멈추고 보고. 커밋은 도도 확인 후. 배포 전 생성 작업
> 없는 것 확인. **DB 마이그레이션 없음**(cuts.spec JSON 확장). 서버에
> **ffmpeg 설치 선행**(apt, sudo — 설치 전 도도 "실행해").
> 근거: docs/조사-모션.md, scratch/motion/out/round1~4
> [근거] 도도 — 인스타 모션 웹툰(배경 고정, 인물만 짧게 움직임) 레퍼런스.
> 4차 테스트 "전체적으로 통과", lite로 충분.
> [근거] 도도 결정 — 움직임 1컷 = **4패킷**(후보 2개 포함), [다시 만들기]
> 4패킷 / 1차는 **웹툰 컷만**(실사 캐릭터 컷 제외 — 실제 인물 영상화는
> 동의·정책 별도) / 릴스 MP4 이어붙이기는 2단계.
> [근거] 테스트 — Veo 3.1 lite(`veo-3.1-lite-generate-preview`): 최소
> 4초, 16:9·9:16만, negativePrompt·lastFrame·referenceImages 미지원,
> 무음. 1:1은 16:9 패딩→크롭 OK. 카메라 고정 문구로 배경 줌 해결.
> 손 개수 오류는 사람이 움직이는 컷에서 2개 중 1개꼴 → 대상 지정 +
> 후보 2 + 비전 검사 + 재생성. 정체성 드리프트 → 앞 3초만 사용.
> 가격: lite $0.05/초(공식) → 후보 2개 $0.40 + 검사·재생성 ≈ $0.47.
> [근거] 조사 — jobs.py 폴링·notify() 재사용 OK, BubbleOverlay는
> absolute SVG라 video 위에 그대로, 서버 ffmpeg 없음, Veo RPM 낮음.

## 0단계 — 서버 준비 (도도 "실행해" 후)
- 서버 `sudo apt install ffmpeg` → `ffmpeg -version` 보고. requirements
  에 moviepy(또는 ffmpeg 직접 호출만 쓰면 생략) 추가 → 배포
- config.py: `VIDEO_MODEL = "veo-3.1-lite-generate-preview"`,
  `MOTION_PACKETS = 4`, `MOTION_CANDIDATES = 2`, `MOTION_CLIP_SEC = 3.0`,
  `MOTION_MAX_RETRY = 1`, `MOTION_CONCURRENCY = 1`(서버 전체 동시 1건)
  — **config에 먼저 넣고** .env는 필요 없음(키는 기존 GEMINI 키)

## 1단계 — 백엔드
- 데이터: `cuts.spec.motion` JSON
  ```
  { status: queued|running|done|failed|none,
    subject_ids: [character_id…], intensity: "subtle"|"normal",
    candidates: [{ id, path, checks:{hands_ok, same_char, note}, created_at }],
    selected: candidate_id|null, export_path, packets_charged, job_id,
    error, updated_at }
  ```
- `app/motion/` 신규: service.py(파이프라인), router.py, prompts.py
- **POST /cuts/{id}/motion** body {subject_ids, intensity}
  - 거부: 컷에 is_photo_real 캐릭터 포함(400 "실사 캐릭터 컷은 아직
    지원하지 않아요"), 이미지 없음, 이미 running, 패킷 부족
  - 패킷 **4 차감**(기존 차감 함수, generation_logs type=motion) →
    spec.motion.status=queued → 백그라운드 job 등록(jobs.py) → 202 {job_id}
- 파이프라인(job):
  1. **입력 준비**: 컷 현재 image_path(DB) → 비율별: 16:9 그대로 /
     9:16은 Veo aspectRatio 9:16 / 1:1·4:3은 16:9 캔버스 양옆 패딩 /
     3:4는 9:16 캔버스 상하 패딩(가장자리 색 확장) → 크롭 좌표 기억
  2. **프롬프트**(prompts.py 한 곳): 공통 "absolutely static camera: no
     zoom, no dolly, no pan, frame edges never move. Background pixels
     stay identical. Keep the illustration style exactly. Seamless
     loop." + 대상: "Only {subject names} move(s) subtly in place: blink,
     hair/ear/tail sway, slight breathing{, small gentle hand motion if
     normal}. Everyone and everything else stays completely still like
     a photograph." + "Hands keep exactly the same shape, count and
     position as drawn. AVOID: extra hands, extra fingers, new objects,
     camera movement." intensity subtle=움직임 목록 최소, normal=위 전체
  3. **생성**: Veo lite 4초, 후보 2개(RPM 때문에 **순차**, 서버 전역
     세마포어 1). 각 완료 즉시 다음 단계
  4. **후처리**(ffmpeg): 앞 3.0초 트림 → 크롭(패딩 썼으면) → H.264
     mp4, 무음, faststart → storage/episodes/{ep}/cuts/motion/
     {cut}_c{n}_v{k}.mp4
  5. **검사**(Gemini flash 비전, 프레임 0.3s·1.5s·2.8s 3장 + 원본 이미지):
     JSON {hands_source, hands_frames:[…], same_character:bool, note}.
     hands_frames 중 하나라도 hands_source와 다르거나 same_character
     false → 탈락 → **그 후보만 1회 재생성**(MOTION_MAX_RETRY). 재생성도
     탈락이면 그대로 두되 checks에 기록(사용자가 보고 고름)
  6. 완료: status=done, selected=null(사용자 선택 대기) → **notify()**
     type=motion_done → 푸시·🔔 "N번 컷 영상이 완성됐어요" (link: 게이트5
     해당 컷). 전부 실패(API 오류 등)면 status=failed + **패킷 4 환불** +
     알림 "영상 생성에 실패해 패킷을 돌려드렸어요"
- **POST /cuts/{id}/motion/select** {candidate_id} → selected 저장 +
  **내보내기용 mp4** 생성: 말풍선·내레이션·효과를 투명 PNG로 렌더(기존
  Pillow compose를 투명 바탕에 — 함수 분리) → ffmpeg overlay → export_
  path. (뷰어는 overlay DOM이라 불필요, 다운로드·인스타용)
- **DELETE /cuts/{id}/motion** → 파일 삭제, spec.motion=none(이미지는 그대로)
- **GET /cuts/{id}/motion/export** → export mp4 다운로드. 에피소드 ZIP:
  GET /episodes/{id}/motion-zip(selected 있는 컷만)
- 컷 재생성(이미지 바뀜) 시 motion은 **자동 삭제**(이미지와 불일치) +
  안내. 컷 삭제 시 파일 정리
- 큐 상태: GET /cuts/{id}/motion → position(대기 순번) 포함. jobs 폴링 재사용
- 비용 로그: generation_logs에 model·초·후보 수·재생성 수 기록
