### 스텝바 클릭 시 흐름

## (2) Gate3Assets 데이터 로딩

**파일:** `frontend/src/components/gates/Gate3Assets.jsx`

### useEffect 의존성

```jsx
// 168행 — 유일한 초기 로딩 useEffect
useEffect(() => { loadAssets(); if (isAd) loadProducts(); }, []);
```

- 의존성 `[]` → 마운트 시 1회 실행. **key 변경으로 재마운트되면 정상 재실행됨**

### loadAssets() 내부 (145-166행)

```jsx
const loadAssets = async () => {
  try {
    const [charRes, locRes, styleRes, presetsRes] = await Promise.all([
      api.get(`.../characters`),
      api.get(`.../locations`),
      api.get(`.../style`).catch(() => ({ data: null })),
      api.get('/styles/presets').catch(() => ({ data: { core: [], beta: [] } })),
    ]);
    const charDetails = await Promise.all(
      charRes.data.map(c => api.get(`/characters/${c.id}`).then(r => r.data).catch(() => c))
    );
    const locDetails = await Promise.all(
      locRes.data.map(l => api.get(`/locations/${l.id}`).then(r => r.data).catch(() => l))
    );
    setCharacters(charDetails);
    setLocations(locDetails);
    setStyles(styleRes.data);
    setPresets(presetsRes.data);
  } catch {}   // ← 최상위 catch가 에러를 조용히 삼킴
};
```

### 문제점

1. **로딩 상태 없음:** `loadAssets()` 실행 중 초기 상태 characters=[], styles=null, presets=null → **빈 화면 렌더**. 로딩 스피너/스켈레톤 없음
2. **에러 무시:** 최상위 `catch {}` — 네트워크 실패, 401, 500 모두 조용히 삼김. 빈 배열 상태 유지
3. **Race condition 가능성:** 빠른 전환 시 마운트→loadAssets 시작→언마운트→재마운트→새 loadAssets 시작. 이전 loadAssets의 setState가 **언마운트된 컴포넌트에 호출**되면 React 경고만 나고 무시되지만, 타이밍에 따라 새 인스턴스의 상태가 이전 인스턴스 응답으로 오염될 수 있음 (key 변경으로 인스턴스가 분리되므로 이론상 불가능하지만, 클로저 캡처 문제 가능)

## (3) Gate4Storyboard 데이터 로딩

**파일:** `frontend/src/components/gates/Gate4Storyboard.jsx`

### useEffect 의존성

```jsx
// 80-85행 — 초기 로딩
useEffect(() => {
  loadCuts();
  loadRecommendation();
  loadLocations();
  loadCharacters();
}, []);

// 88-97행 — 장소 자동 제안 (episodeId당 1회)
const suggestTriedRef = useRef(null);
useEffect(() => { suggestTriedRef.current = null; }, [episodeId]);
useEffect(() => {
  if (locations.length === 0 && !locLoading && !readOnly
      && suggestTriedRef.current !== episodeId) {
    suggestTriedRef.current = episodeId;
    autoSuggestLocations();
  }
}, [locations.length, episodeId]);
```

### 개별 로딩 함수 (48-78행)

```jsx
const loadCuts = async () => { try { ... } catch {} };
const loadRecommendation = async () => { try { ... } catch {} };
const loadLocations = async () => { try { ... } catch {} };
const loadCharacters = async () => { try { ... } catch {} };
```

### 문제점

1. **로딩 상태 부분적:** `locLoading` 상태는 자동 제안(autoSuggestLocations)에서만 사용. 초기 `loadLocations()` 호출은 로딩 표시 없음
2. **에러 무시:** 4개 함수 모두 `catch {}` — 실패 시 빈 배열/null 유지, 사용자에게 알림 없음
3. **장소 패널 빈 상태:** `locations.length === 0 && !locLoading` 일 때 장소 카드 0개 렌더 — 로딩 중인지 실패인지 구분 불가

## (6) 해결안 비교

### A. key에 타임스탬프 추가 (강제 재마운트)

```jsx
<GateComponent key={`${displayGate}-${Date.now()}`} ... />
```

- **장점:** 매 전환마다 100% 새 인스턴스 + useEffect 재실행
- **단점:** 불필요한 언마운트/마운트 (같은 게이트 재렌더 시에도). 입력 중 상태 소실. 오버킬
- **추천도:** ★★☆ — 현재 key={displayGate}가 이미 정상 동작하므로 불필요

### B. 각 useEffect에 gate 의존성 추가

```jsx
// Gate3
useEffect(() => { loadAssets(); }, [projectId, episodeId]);
// Gate4
useEffect(() => { loadCuts(); loadLocations(); ... }, [projectId, episodeId]);
```

- **장점:** episodeId 변경 시 자동 재로딩 (현재는 마운트 시에만)
- **단점:** 같은 episode 내 게이트 전환에는 무관 (episodeId 안 바뀜). 근본 원인이 아닐 수 있음
- **추천도:** ★★☆ — 방어적이지만 증상의 직접 원인이 아님

### C. 로딩 상태 + 에러 처리 + 재시도 (추천)

```jsx
// Gate3 예시
const [initialLoading, setInitialLoading] = useState(true);
const [loadError, setLoadError] = useState(null);

useEffect(() => {
  let cancelled = false;
  const load = async () => {
    setInitialLoading(true);
    setLoadError(null);
    try {
      // ... loadAssets 로직
      if (!cancelled) { setCharacters(...); setStyles(...); }
    } catch (err) {
      if (!cancelled) setLoadError(err.message || '데이터를 불러오지 못했습니다');
    } finally {
      if (!cancelled) setInitialLoading(false);
    }
  };
  load();
  return () => { cancelled = true; };
}, []);

// 렌더
if (initialLoading) return <Skeleton />;
if (loadError) return <ErrorWithRetry message={loadError} onRetry={loadAssets} />;
```

- **장점:**
  - 빈 화면 대신 로딩 스피너 표시 → 사용자 혼란 제거
  - 네트워크 실패 시 에러 메시지 + 재시도 버튼
  - `cancelled` 플래그로 언마운트 후 setState 방지 (race condition 차단)
  - `catch {}` 침묵 제거 → 디버깅 가능
- **단점:** Gate3·Gate4·(Gate5도 동일 패턴) 3개 파일 수정 필요
- **추천도:** ★★★ — **근본 원인(에러 무시 + 로딩 표시 없음)을 직접 해결**

### D. 상위(WorkflowPage)에서 데이터 일괄 로드


## 결론

| 항목 | 판정 |
|---|---|
| key 메커니즘 | **정상** — displayGate 변경 시 재마운트+useEffect 재실행 확인 |
| 근본 원인 | **네트워크 실패 시 빈 화면 고착** — `catch {}`가 에러를 삼키고, 로딩 상태가 없어 빈 화면과 로딩 중을 구분 불가 |
| 재현 조건 | 안정 네트워크에서 미재현. 불안정 네트워크/서버 부하 시 간헐 발생 추정 |
| 추천 해결안 | **C안 (로딩 상태 + 에러 처리 + 재시도)** — Gate3·Gate4·Gate5 공통 적용 |
| 우선순위 | 중 — UX 개선이지만 F5로 우회 가능. 다크 테마 마무리 후 진행 적절 |
