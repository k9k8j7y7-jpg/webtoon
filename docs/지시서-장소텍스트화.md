# 지시서 — 장소 텍스트화 + 게이트4 "콘티&장소"

> 원칙: 단계마다 멈추고 보고. 커밋은 도도 검증 후. 마이그레이션 step27은
> 리허설 DB(project_t_test) → 백업 → SQL 텍스트 보고 → "실행해" → 운영.
> [근거] 도도 요청(장소 이미지 강제 생성이 패널 분할·패킷 낭비의 원인) +
> 조사 확인(이미지 없이 텍스트 폴백 정상, 장소 설명이 한글 그대로 주입,
> 사진 비전 텍스트 폐기 중)

## 목표 (도도가 화면에서 보게 되는 것)

- **게이트3** = 스타일 · 비율 · 캐릭터 · (광고면) 제품. 장소 섹션 없음
- **게이트4 "콘티&장소"** = 상단에 장소 카드 목록(대본에서 AI가 자동 추출),
  이름·묘사·분위기 편집, 실사 참고 사진 업로드(→ AI가 공간 묘사 텍스트로
  변환해 묘사 칸에 채움), **[장소 이미지 만들기 (1패킷)]는 옵션 버튼**.
  그 아래 콘티 생성·컷 카드. 콘티 편집 모달에서 컷의 장소 변경 가능
- 컷 생성 시 장소는 **영문 스펙 한 줄(location_spec_en)**로 주입. 장소
  이미지가 있으면 지금 규칙(풀샷 768px 썸네일)대로 추가 첨부
- 기존 에피소드(장소 이미지 있는 30개)는 그대로 동작. 회귀 없음

## 0단계 — 완료 (조사 보고 수신)

## 1단계 — 백엔드: 스펙 컬럼 + 텍스트 파이프라인

### 1-1. step27 마이그레이션
- `locations.location_spec_en VARCHAR(500) NULL` 추가
- 리허설 → 백업(backup_before_step27) → SQL 텍스트 보고 → "실행해" → 운영
- 기존 행은 NULL → 컷 생성 시 폴백(아래 1-3)

### 1-2. 스펙 생성 (텍스트 LLM, 무료)
- `generate_location_spec_en(name, description, mood_notes) -> str`:
  캐릭터 appearance_en 방식 복제. 영문 한 줄 ≤ 80단어: 공간 종류, 핵심
  가구/구조 3~5개, 색·재질, 조명·시간대, 분위기. 사람·캐릭터 언급 금지
- 호출 시점: 장소 생성/수정(name·description·mood_notes 변경) 시 자동
  재생성. 사용자가 텍스트만 고쳐도 스펙이 따라감
- 사진 업로드: 기존 비전 추출 spatial_desc를 **폐기하지 말고** ①
  description이 비어 있으면 한글 묘사로 채움(있으면 유지) ② 그 결과로
  spec_en 재생성. 사진→일러스트 변환(converted_photo_url)은 **자동 실행
  중단** — [장소 이미지 만들기] 옵션으로만

### 1-3. 컷 생성 주입 (images/service.py)
- loc_desc = `location_spec_en` 우선, 없으면 기존 `name. description`
  (한글 폴백 — 기존 에피소드용). 스펙이 있으면 프롬프트 Setting: 에 영문만
- 이미지 첨부 규칙은 현행 유지(바스트/클로즈업 미첨부, 풀샷 768px 썸네일 —
  이미지가 있을 때만)
- 로그 "location_ref: text_only|attached(768px) spec=en|ko"

### 1-4. API 게이트 완화
- locations 라우터의 "gate≠3 거부"를 **gate 3·4·5 허용**으로. 장소 텍스트
  수정은 이후 재생성에만 영향 — 기존 이미지·콘티는 안 건드림
- 장소 삭제는 콘티가 참조 중이면(어느 컷의 location_id) 거부 + 메시지
  "N개 컷이 이 장소를 쓰고 있어요"
- [AI 제안](대본에서 장소 추출)은 게이트4에서도 호출 가능하게. 이미 장소가
  있으면 **없는 ref_key만 추가**(덮어쓰기 금지)

### 1-5. 게이트3 승인 조건
- 백엔드 approve에서 장소 요구 없음(이미 없음 — 확인만). 프론트 canApprove
  에서 hasLocations 제거는 2단계에서
- 콘티 생성(게이트4)에서 대본이 참조하는 ref_key 중 장소 레코드가 없는 게
  있으면 400 "장소를 먼저 정리해 주세요" + 누락 목록

**완료 후: 리허설·SQL 보고 → 승인 → 운영 적용 → 재시작·health → 보고.
도도 검증은 2단계 UI와 함께.**

## 2단계 — 프론트: 게이트3 정리 + 게이트4 장소 패널

### 2-1. 게이트3 (Gate3Assets.jsx)
- **새 에피소드(장소 0개)**: 장소 섹션 렌더 안 함. canApprove에서
  hasLocations 제거. 안내 한 줄 "장소는 다음 단계(콘티&장소)에서 정리해요"
- **기존 에피소드(장소 ≥1)**: 장소 섹션을 읽기 전용 요약 카드(이름·이미지
  썸네일)로만 표시 + "장소 편집은 콘티&장소 단계에서" 링크. 기존 [생성]·
  [재생성] 버튼은 숨김

### 2-2. 게이트4 (Gate4Storyboard.jsx) — 스텝바 라벨 "콘티&장소"
- 컷 추천 패널 위에 **장소 패널** 추가:
  - 진입 시 장소 0개면 자동 [AI 제안] 호출 → 카드 생성 (텍스트, 무료)
  - 카드: 이름 / 묘사(textarea) / 분위기 메모 / 참고 사진 썸네일·[사진
    업로드] / 영문 스펙 미리보기(회색, 읽기 전용, 접이식) / 이미지 썸네일
    (있으면) / **[장소 이미지 만들기 (1패킷)]** 버튼(없을 때) · [다시 만들기
    (1패킷)](있을 때) / [삭제]
  - blur 저장 → 스펙 자동 갱신(저장 후 "스펙 갱신됨" 짧은 표시)
  - [+ 장소 추가] [AI 제안 다시] (없는 것만 추가)
  - 패널 상단 안내: "장소는 글로 설명하면 충분해요. 매장·집처럼 실제 모습을
    꼭 살려야 할 때만 이미지를 만드세요 (1패킷)"
- 콘티 생성 버튼: 장소 누락 시 400 메시지 표시
- 콘티 편집 모달(게이트4·게이트5 둘 다): location_id를 **드롭다운**으로
  변경 가능(현재 에피소드 장소 목록). 저장은 기존 PUT /cuts/{cut_id}에
  location_id 추가(백엔드 허용 필드에 포함 — 1단계에서)
- 컷 카드의 장소 표시(MapPin)는 유지
- 읽기 전용(게이트5 이후 되돌아옴): 장소 패널은 **편집 가능 유지**(텍스트
  수정은 안전) — 단 [삭제]는 숨김. 콘티 부분만 읽기 전용

### 2-3. 게이트5 콘티 수정 모달
- 장소 드롭다운 추가(2-2와 동일 컴포넌트). [저장 후 재생성]이면 새 장소
  스펙으로 재생성

**완료 후 프론트 빌드·배포 → 보고 → 도도 검증 → 커밋**
