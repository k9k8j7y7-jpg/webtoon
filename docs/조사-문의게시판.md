### step29.sql 초안

```sql
-- step29: 1:1 문의 게시판
CREATE TABLE inquiries (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  category ENUM('bug','howto','payment','feature','other') NOT NULL,
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,
  episode_id BIGINT NULL,
  status ENUM('received','checking','answered','closed') NOT NULL DEFAULT 'received',
  satisfaction ENUM('good','bad') NULL,
  attachments JSON NULL,
  device_info JSON NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user (user_id),
  INDEX idx_status_created (status, created_at),
  INDEX idx_category (category)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE inquiry_messages (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  inquiry_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  is_admin TINYINT(1) NOT NULL DEFAULT 0,
  content TEXT NOT NULL,
  attachments JSON NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_inquiry (inquiry_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 2. 기존 알림 시스템

**알림 시스템 없음.** 현재 헤더의 🔔 아이콘은 비활성 플레이스홀더 (`Layout.jsx:59-62`, `cursor-default`, title="알림 (준비 중)"). 백엔드에 notifications 테이블·모델·라우터 모두 없음.

**알림 구현 방안 (문의 답변 알림용):**
- `notifications` 테이블 신설: `id, user_id, type('inquiry_reply' 등), title, body, link, is_read, created_at`
- 관리자 답변 시 `inquiry_messages` INSERT와 동시에 notification INSERT
- 프론트: 🔔 아이콘에 읽지 않은 개수 뱃지 + 클릭 시 드롭다운 목록
- 폴링(`GET /notifications/unread-count` 60초 간격) 또는 후속 SSE
- **문의 게시판과 알림을 같은 단계에 넣으면 범위가 커짐 → 1단계는 알림 없이, 관리자 답변 시 status 변경만으로 사용자가 목록에서 확인. 2단계에서 notifications 테이블 + 🔔 활성화**

## 5. 리포트용 집계 쿼리 가능성

이 설계로 모두 가능:

| 집계 | 쿼리 방법 |
|---|---|
| 카테고리×주 | `GROUP BY category, YEARWEEK(created_at)` on inquiries |
| 미답변 건수 | `WHERE status IN ('received','checking')` |
| 평균 답변 시간 | `inquiries.created_at` ↔ 첫 `inquiry_messages WHERE is_admin=1`의 `created_at` 차이 |
| 👍 비율 | `COUNT(satisfaction='good') / COUNT(satisfaction IS NOT NULL)` |
| 사용자별 문의 수 | `GROUP BY user_id` |
| 디바이스 분포 | `JSON_EXTRACT(device_info, '$.device_type')` GROUP BY |

인덱스 `idx_status_created`와 `idx_category`로 필터 성능 충분.
